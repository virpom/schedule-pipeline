# Расписание ПТК — Telegram-бот

Бот с расписанием **Политехнического колледжа ЗГУ** (Норильск). Сам забирает
файлы из ЭИОС колледжа, раскладывает их по слоям «базовое расписание + замены»
и отдаёт студентам и преподавателям по кнопкам и рассылкой.

```
ЭИОС → xlsx + docx замен + docx звонков → SQLite → Telegram
```

## Бот

Публичный адрес бота в репозитории не хранится — он зависит от стенда и задаётся
в BotFather. Для своего развёртывания подставьте свой:

```
https://t.me/<bot_username>
```

Кнопка «📨 Поддержка» в меню появляется только после того, как админ задал ссылку:
`/admin` → «⚙️ Настройки» → «Ссылка поддержки» (ключ `support_link` в таблице `setting`).

## Что это

- **Источник данных** — [страница «Расписание занятий» в ЭИОС](https://eios.norvuz.ru/mod/page/view.php?id=49960),
  блок «Политехнический колледж». Оттуда берутся три файла: очное расписание
  (`.xlsx`), листок замен (`.docx`) и расписание звонков (два `.docx`).
- **Хранилище** — один файл SQLite. Внешних сервисов нет: ни Redis, ни Postgres,
  ни воркеров.
- **Обновление** — фоновый цикл раз в `poll_interval` секунд (по умолчанию 300),
  ночью пауза. Рассылка уходит только если файл на сайте реально изменился.
- **Правки старост** — староста может править расписание своей группы из бота,
  и эти правки не затираются следующей синхронизацией с сайтом.

## Быстрый старт

```bash
git clone <repo> schedule-pipeline && cd schedule-pipeline
cp .env.example .env
$EDITOR .env          # BOT_TOKEN и ADMINS обязательны
docker build -t schedule-bot:latest .
docker run -d --name schedule-bot --restart unless-stopped \
  --env-file .env -v "$PWD/data:/data" schedule-bot:latest
docker logs -f --tail=100 schedule-bot
```

В логах должны появиться `poller started` и `bell loop started` — значит
фоновые задачи поднялись. Бот отвечает на `/start`.

База и фото лежат в `./data` на хосте (в контейнере — `/data`):

```
data/
├── database.db          # SQLite, создаётся при первом старте
└── photos/
    ├── monday/          # картинки для понедельника
    ├── tuesday/
    └── ... sunday/
```

## Переменные окружения

Все переменные читаются в `config.py`. Файл `.env` подхватывается вручную,
и **уже заданные переменные окружения не перетираются** — в докере значения
приходят через `env_file`.

| Переменная | Обязательна | По умолчанию | Что это |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен от BotFather |
| `ADMINS` | нет | пусто | Telegram ID админов через запятую или пробел |
| `SQLITE_PATH` | нет | `database.db` | путь к файлу базы |
| `SCHEDULE_URL` | нет | `https://eios.norvuz.ru/mod/page/view.php?id=49960` | страница-каталог ЭИОС |
| `PHOTOS_PATH` | нет | `/data/photos` | папка с подпапками `monday`…`sunday` |
| `TZ` | нет | — | часовой пояс контейнера (`Asia/Krasnoyarsk`) |

Интервал опроса, скорость рассылки, ночная пауза, дедлайн «занятий нет» и ссылка
поддержки **живут в БД**, а не в `.env`: их меняет админ из бота, и они переживают
рестарт. Значения по умолчанию — в `infrastructure/database/repo/setting.py`.

`TZ` важна: от локального времени зависят ночная пауза, дедлайн и время звонков.

## Команды

### Студент и преподаватель

| Команда | Что делает |
|---|---|
| `/start` | меню; при первом входе — выбор роли |
| `/group ДП-26` | быстро задать группу |

### Админ (только для ID из `ADMINS`)

| Команда | Что делает |
|---|---|
| `/admin` | админ-меню кнопками |
| `/stats` | пользователи, подписки, объём расписания, разбивка по группам |
| `/teachers` | зарегистрированные преподаватели |
| `/chats` | групповые чаты и их привязка к группам |
| `/bell` | текущее расписание звонков |
| `/settings` | текущие настройки |
| `/setpoll 300` | интервал опроса, сек (мин. 10) |
| `/setrate 20` | скорость рассылки, сообщ/сек (0–30) |
| `/setnight 23:00 07:00` | ночная пауза; `/setnight off` — выключить |
| `/setbell MONDAY I_IV 1 09:25-10:10` | поправить один звонок |
| `/setgroup ДП-26` | в групповом чате: привязать чат к группе |
| `/broadcast текст` | рассылка всем (с подтверждением) |
| `/broadcast_teachers текст` | рассылка преподавателям |
| `/broadcast_group ДП-26 текст` | рассылка группе |
| `/notify` | тест уведомления: всем / себе / конкретной группе |
| `/notify me`, `/notify ДП-26` | превью расписания |

Все массовые рассылки идут через подтверждение «✅ Отправить / ❌ Отмена»
и дросселируются по `notify_rate`.

## Как это работает

Три слоя данных:

```
base_lesson     «нечётная неделя, понедельник, 1 пара, ДП-26 = Математика»
substitution    «26.10.2026, 1 пара, ДП-26: вместо Математики — Физика»
     ↓
get_day_slots()  база по чётности + замены на дату
     ↓
college_lesson   материализованный результат на 14 дней вперёд
```

Читают `college_lesson` почти все хендлеры, рассылка и звонки. Староста правит
слои (`base_lesson` / `substitution`) с `source='manual'`, и синхронизация
с сайтом их не трогает.

Подробно — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Особенности, о которых стоит знать

- **В очном файле нет кабинетов.** Аудитория приходит только в листке замен —
  у пар из базы поле `room` пустое.
- **Чётность недели у колледжа сдвинута на 1 относительно ISO.** Учтено
  константой `PARITY_OFFSET = 1` в `tgbot/services/schedule_layer.py`.
- **Сайт может лежать неделями.** Бот продолжает отдавать последнее известное
  расписание и честно предупреждает, что замены не проверены.
- **Замены на сайте не архивируются** — файл перезаписывается. Историю хранит
  бот: `day_snapshot` (снимки прошедших дней) и `college_lesson`.
