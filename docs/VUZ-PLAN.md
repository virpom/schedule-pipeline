| Вопрос | Ответ |

## A. Модель данных — суффикс `@vuz`

Группы вуза хранятся как `ЭК-23@vuz`. В таблицах расписания **ни одной
миграции**: `base_lesson`, `substitution`, `college_lesson`, `chats`,
`day_snapshot` остаются как есть.

В `users` добавляется `unit String(16) default 'college'` — чтобы помнить
«выбрал ВУЗ, но группу ещё не выбрал».

**Почему так.** 87 обращений к `.group` не трогаются вообще — разделение
получается бесплатно. Отдельная колонка `unit` во всех шести таблицах
потребовала бы batch-alter и правки каждого запроса; отдельная таблица
`vuz_lesson` продублировала бы весь слой материализации, звонков, рассылки
и уведомлений.

Коллизия реальна и ровно три группы: `ЭК-23`, `ЭК-24`, `ЭК-25`.

При показе суффикс срезается: студент видит `ЭК-23`, а не `ЭК-23@vuz`.

## B. Выбор учебного заведения

В `start()` без identity вместо `ROLE_KB` — `UNIT_KB`:
«🎓 Колледж» / «🏛 Университет» (`unit:college` / `unit:vuz`).

Выбор пишется в `users.unit`, дальше существующий поток: студент →
группа/курс, преподаватель → фамилия. В настройках — «🏛 Сменить учебное
заведение».

**При смене сбрасываются** `group`, `course`, `teacher_name`. Иначе студент
вуза с группой `ЭК-23@vuz` переключится на колледж и увидит пустой день.
Права редактора не трогаются — они привязаны к группе отдельно.

## C. Выбор группы — факультет → курс и форма → группа

109 групп в один экран не лезут. Три уровня:

```
vu:fac:FEU          → факультет
vu:cr:FEU:2:full    → курс и форма
vu:g:ЭК-26-1        → группа
```

Факультет и курс берутся **из листа файла**, не из имени группы: по
`ЭК-26-1` факультет не определить. Синхронизация заполняет таблицу
`vuz_group(name PK, faculty, course, form)` — около 92 строк.

Пересечений групп между файлами нет (проверено: 0 из 92).

## D. Парсер `.xls`

Новый `parsers/vuz.py`, читает BIFF через `xlrd` с `formatting_info=True` —
без этого не видно объединённых ячеек, а на них держится половина структуры.

Что проверено на реальных файлах:

| Что | Факт |
|---|---|
| Шапка | строка 8, `A=День недели`, `B=Время`, дальше пары «группа / ауд» |
| Колонка времени | **не всегда B**: в листе `ФЭЭиУ 1 курс` в B реальные звонки, а сетка в C |
| Сетка | 8 меток → пара 1..8. Бывают опечатки: `18.50 - 22.00`, en-dash |
| Мержи времени | в заочке метка растянута на 4 строки → разворачивать вниз |
| День | в колонке A, но в листе `ЭК,ЭЭ,ТМ,ИП,СА-26-2` — inline слева от групп |
| Чётность | `н.`/`ч.`; две строки = обе недели; вертикальный мерж = `ANY` |
| Списки недель | `№н. 5-13` — здесь **`№н` = номер недели**, не «нечётная» |
| Общая лекция | горизонтальный мерж = одна пара для всех накрытых групп |
| Длина предмета | 168 ячеек длиннее 128 символов, максимум 462 |
| Суффикс `(6,9,12,15)` | недели, когда группы нет в сетке. Отбрасывается |

**Разбор датированных ячеек** (111 штук):

| Формат | Действие |
|---|---|
| `DD.MM.YYYY - перенос на DD.MM` | `cancel` на исходную + `add` на целевую |
| `DD.MM - Предмет` | `add` |
| `пары нет` | `cancel` |
| `07.11; 21.11 - …` | попарно; при несовпадении — в лог и тревогу |
| `перенос на 13.50` (9 штук) | неоднозначно: `cancel` + комментарий + тревога |

Перед вставкой проверять занятость слота: есть базовая пара → `replace`,
нет → `add`. Иначе `UNIQUE(date, group, para)` даст конфликт.

## E. Звонки — 8 пар, `course_group='VUZ'`

Миграция вставляет 16 строк: `MONDAY` и `OTHER` × пары 1–8, `course_group='VUZ'`,
без обедов. `course_group_from_group()` возвращает `VUZ` для `…@vuz`.

**Почему 16, а не 8:** `format_day` ищет по `(day_type, cg, para)`, а для
понедельника `day_type` = `MONDAY`. Дешевле продублировать строки.

### 🔴 Мина: `replace_bells` снесёт звонки вуза

```python
delete(BellSchedule).where(BellSchedule.course_group != "ALL")
```

Первый же проход колледжа удалит `VUZ`-строки. Правка:
`not in ("ALL", "VUZ")`. **Это надо сделать до того, как появятся звонки вуза.**

## F. Якорь недели — без вопросов владельцу

`week_no = ISO_week - 35`, то есть **31.08.2026 = неделя 1**.

Проверено на 38 датированных ячейках: 35 попаданий. Три промаха — ошибки
в самом файле (опечатка года `2022`, чужие номера в одном листе).

Чётность при этом совпадает с колледжем: неделя 1 нечётная, ISO 36 чётный →
`PARITY_OFFSET = 1` уже правильный, **новый офсет не нужен**.

Якорь кладётся в `setting` как `vuz_week_anchor`. Каждая синхронизация
пересчитывает его голосованием по датированным ячейкам; меньше 70 %
совпадений — тревога админу, но расписание работает на сохранённом.
Команда `/setvuzanchor` — ручной override на случай смены семестра.

## G. Синхронизация

`tgbot/services/sync_vuz.py::sync_once()` качает `1-ochnoe.xls` и
`2-ochno-zaochnoe.xls`, кладёт в `base_lesson` / `substitution` через
существующие `replace_base_lessons` / `replace_substitutions`, заполняет
`vuz_group`.

В `poll_once` — второй независимый блок в `try/except`: падение вуза не
мешает колледжу и наоборот.

`source_state` получает второй ключ: `last_sync_vuz_ok`, параметр `source`.
Тревоги — `kind="structure_vuz"`.

Материализация, звонки, рассылка, снимки — **без изменений**.

### Три места, где вуз протекает в колледж

1. `format_day` рисует «Разговоры о важном» по `(MONDAY,'ALL',0)` — у вуза
   их нет, для студента вуза `show_rov=False`.
2. `_day_text` при пустом дне уходит в «Ещё не выложено» по
   `schedule_files.get_hash()` — у вуза этого хеша не будет никогда.
3. `format_stale_warning` пишет «Сайт колледжа не отвечает» — параметризовать.

## Порядок этапов

1. ✅ **Фундамент — сделано** (коммит `059632f`). `xlrd`, миграция `0004_vuz`,
   звонки `VUZ` (16 строк), `course_group_from_group`, `is_vuz()`/`strip_unit()`,
   правка `replace_bells`. Проверено на копии прод-базы и на проде.
2. **Парсер + sync.** `parsers/vuz.py`, `sync_vuz.py`, запись в БД, тесты на
   трёх файлах. Проверка: `base_lesson` с `@vuz` ≈ 1500, ручной diff по 3–5 группам.
3. **UI.** `unit`, навигация, сброс, `show_rov`, пустой день. Проверка:
   студент вуза видит сегодня, студент колледжа ничего не потерял.
4. **Замены из дат.** Переносы, «пары нет», датированные добавления.
   Можно отложить: без них расписание верное, только без значков 🔄.
5. **Очно-заочное.** `2-ochno-zaochnoe.xls` теми же правилами.

**Вне объёма:** магистратура, сессии, преподаватели вуза.

## Риски

| Риск | Проверка |
|---|---|
| Вуз сменит структуру `.xls` | `VuzParseError` → тревога `structure_vuz`; тест на фикстурах падает первым |
| `replace_bells` снесёт звонки вуза | тест: после `sync_once` колледжа `VUZ`-строки на месте |
| `№н` понят неверно | 35/38 на датированных; тест на этих же ячейках |
| Перенос на время без даты | `cancel` + тревога, не молчим |
| `subject` обрезается | расширение до 256 + тест на самой длинной (462) |
| Три группы с одинаковыми именами | суффикс + тест `get_groups()` не смешивает |
| Ошибка вуза роняет поллер | тест: колледж синхронизируется при падении вуза |
| Прод-БД 219 пользователей | миграция с `server_default`, проверка на копии прод-БД |

## Не проработано

- **Преподаватели вуза** — расписания по факультетам в файлах нет, только по
  группам. Поиск по фамилии для них останется колледжевым.
- **Заочное отделение** (`3-zaochnoe.xls`) — семантика пар «установочная
  сессия» не разобрана.
- **Точные тексты экранов** — не написаны, только структура клавиатур.
- **Подписи факультетов** — в файлах два варианта («ГОРНО-ТЕХНОЛОГИЧЕСКИЯ»
  и «…ОГО»), сокращения `GTF`/`FEU` не утверждены.
