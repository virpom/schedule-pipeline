# Редакторы расписания (старосты) — проектная проработка

> Статус: **спроектировано, не реализовано.** Документ описывает целевую модель,
> формат ввода и порядок работ. См. также `docs/ROADMAP.md` (что доделать).

## Зачем

Сайт `polaruniversity.ru` / `norvuz.ru` с октября 2026 лежит (авария в Yandex Cloud).
Расписание не обновляется, бот живёт на данных от 2–8 октября. Пока сайт недоступен,
единственный способ держать расписание актуальным — **ручной ввод старостами**.

Плюс колледж живёт по схеме **чётная / нечётная неделя** и ежедневно выдаёт **замены
на следующий день**. Ни то, ни другое нынешняя модель (пары, привязанные к дате) не
поддерживает.

## Модель данных: три слоя

Сейчас в БД `CollegeLesson` — пары, жёстко привязанные к конкретной дате. Это
подходит только для «временного» режима. Нужна схема из трёх слоёв:

```
Слой 1  БАЗОВОЕ расписание   «нечётная неделя, среда, 2 пара, ДП-26 = Математика»
                             не привязано к дате; живёт, пока сайт не обновит
Слой 2  ЗАМЕНЫ               «16.10.2026, 2 пара, ДП-26: вместо Математики — Физика»
                             привязано к конкретной дате; живёт один день
Слой 3  ИТОГ                 база (по чётности) + замены = то, что видит студент
```

Студент всегда видит **Слой 3**. Замена перекрывает базу. Нет замены — показывается база.

## Чётность недели

**Решено: по ISO-номеру недели.**

```python
def week_parity(date: datetime.date) -> str:
    return "EVEN" if date.isocalendar().week % 2 == 0 else "ODD"
```

Сверка на реальном календаре (на 16.10.2026):

| Дата | ISO-неделя | Чётность |
|---|---|---|
| 2026-10-02 (пт) | 40 | ЧЁТНАЯ |
| 2026-10-05 (пн) | 41 | нечётная |
| 2026-10-12 (пн) | 42 | ЧЁТНАЯ |
| 2026-10-19 (пн) | 43 | нечётная |

> ⚠️ Нужно подтверждение от старост: совпадает ли это с тем, как считает колледж.
> Если нет — вводим настройку `parity_offset` в `Setting` (сдвиг на 1 неделю).

## Права и ограничения

| Правило | Значение |
|---|---|
| Чьи группы | только своя (одна) |
| Базовое расписание | править можно без ограничений по дате |
| Замены | на **вчера, сегодня и вперёд**; раньше вчера — запрещено |
| Один слот | одна пара (и в базе, и в заменах) |
| Конфликт сайт/староста | **побеждает староста**, но `source=manual` фиксируется |
| Срок жизни замены | один день; после учебного дня — в историю |
| «Занятий нет» | отдельно не нужно; покрывается заменой `cancel` |

## Формат ввода: почему кнопки, а не текст

Ключевой принцип: **не давать вводить свободный текст там, где можно дать кнопку.**
Свободный ввод порождает опечатки, разные написания одного преподавателя и
неразбираемый формат.

### Что вводится как (гарантия корректности)

| Данные | Способ | Почему безопасно |
|---|---|---|
| Дата | кнопки «Сегодня/Завтра/Выбрать» | нельзя ошибиться |
| Пара (номер) | кнопки 1–5 | вне диапазона невозможно |
| Чётность недели | кнопки ODD/EVEN/ANY | — |
| **Время пары** | **не вводится вообще** | берётся из `BellSchedule` по курсу группы |
| Преподаватель | инлайн-список из БД (57 имён) + «свой» | нет опечаток, автодополнение |
| Предмет | автодополнение из предметов группы | единообразие названий |
| Аудитория | текст с валидацией | формат «317», «ауд. 215» |

### Экран редактора

```
✏️ Редактирование — ДП-26

[📚 Базовое расписание]   ← чётная/нечётная неделя
[🔁 Замены]               ← на конкретный день
[📜 История правок]
```

### Замены (самый частый сценарий — «на завтра»)

```
🔁 Замены — ДП-26
Дата: [Сегодня] [Завтра] [Выбрать]

Базовое на 17.10 (чётная неделя, суббота):
1) 09:00–10:35  Организация документооборота   Харькова Д.А. · 317
2) 10:45–12:40  БЖД                           Ляшко Д.В. · 215

Тык по паре → [❌ Отменить] [🔄 Заменить] [➕ Добавить]
```

После выбора действия — пошаговое заполнение с **предпросмотром**:

```
Проверь, так увидят студенты:

📅 Суббота, 17 октября
2) 10:45–12:40  Физика
Петров П.П. · 305

[✅ Сохранить] [✏️ Изменить] [❌ Отмена]
```

### Базовое расписание

```
📚 Базовое — ДП-26
Неделя: [Нечётная] [Чётная] [Каждую]

Среда
1) 09:00–10:35  Математика  Иванов И.И. · 201
2) 10:45–12:40  Физика      Петров П.П. · 305
   [➕ Добавить пару]  [✏️ Изменить]  [🗑 Удалить]
```

### Быстрый массовый ввод (для целого дня)

```
Отправь пары на 17.10, одна на строку:
1. Организация документооборота — Харькова Д.А. — 317
2. БЖД — Ляшко — 215
```

Бот разбирает и **сопоставляет с базой**:

```
Разобрал 2 пары. Проверь:
1) 09:00–10:35  Организация документооборота · Харькова Д.А. · 317   ✅
2) 10:45–12:40  БЖД · Ляшко → распознан как «Ляшко Д.В.» · 215       ✅

[✅ Подтвердить] [✏️ Переписать]
```

Нераспознанные строки **подсвечиваются и не сохраняются**, пока их не исправят.

## Валидация

| Проверка | Поведение |
|---|---|
| Предмет пустой / < 3 символов | не пропускает |
| Преподаватель не из БД | предлагает похожих, просит подтвердить |
| Пара вне 1–5 | невозможно (кнопки) |
| Замена на дату без базовой пары | «в этот день пары нет — добавить как новую?» |
| Замена раньше «вчера» | блокирует |
| Конфликт: замена на занятый слот | предлагает заменить существующую |
| Время вручную | недоступно by design |

## Исправление ошибок

1. **Предпросмотр** до сохранения — ровно как увидит студент.
2. **История правок** — `/editlog ДП-26` (кто, что, когда).
3. **↩️ Отменить последнюю правку** — из `ScheduleEdit.old_value`.
4. **`source=manual`** — когда сайт оживёт, парсер не затрёт правки молча,
   а покажет «расхождение, что оставить?».
5. **Уведомление админу** о каждой правке старосты (можно отключить).

## Уведомления

Только подписчикам **этой группы** + её чатам (не всем 215):

```
🔄 Замена на завтра (ДП-26)

📅 Суббота, 17 октября
2) 10:45–12:40  Физика
Петров П.П. · 305
```

## История (архив)

Требование: **сохранять всё, что было показано студентам.**

- Каждый прошедший учебный день **фиксируется** в архиве (`DaySnapshot`):
  фактический итог (база + замены) на конец дня.
- Архив доступен старосте/админу и в «📜 История» у студента.
- Старые данные (2–8 октября, «временный» режим) **сохраняются** отдельно как
  архив — не конвертируются в базовое, чтобы не искажать историю.

Задача-планировщик: после 23:59 (или по окончании последней пары) — снять снапшот дня.

### Как пользоваться

**Админ** выдаёт права: `/admin` → «✏️ Редакторы» → «➕ Добавить редактора»
→ присылает **@никнейм**, например `@virp0m` → выбирает человека из
найденных → выбирает группу кнопкой.

Поиск понимает: `@ник`, `ник` без собачки, любой регистр, часть имени
и — на всякий случай — числовой id. Если не нашлось, значит человек
ещё не запускал бота.

**Староста** видит в меню кнопку «✏️ Редактор расписания»:

```
✏️ Редактор расписания
├── 📅 Правки на дату (замены)   → вчера..+6 дней → пара → заменить/отменить/добавить
├── 🗓 Базовое расписание        → Пн..Сб → чётная/нечётная/любая → 1..5 пара
├── 📜 Журнал правок             → последние 10 + откат
└── 👁 Как видят студенты        → предпросмотр ровно как в рассылке
```

Ввод предмета: подставляется из предметов группы одним нажатием либо
пишется текстом. Преподаватель и кабинет вводятся текстом, но их можно
пропустить. **Время пары не вводится никогда** — берётся из звонков.
