# Разбор источников

Практическая сторона: что лежит на сайте, как это устроено и на чём легко
ошибиться. Подробный разбор с доказательствами, объёмами и образцами
ячеек — в [`SOURCE-EIOS.md`](SOURCE-EIOS.md); здесь то, что нужно знать,
когда парсер сломался или расписание «съехало».

## Откуда берутся файлы

Страница-каталог в Moodle:

```
https://eios.norvuz.ru/mod/page/view.php?id=49960
```

Внутри — несколько блоков. Нам нужен **«Политехнический колледж»**. Ссылки
ищутся по маркеру `/upload/timetable.ptk/`, а не по позиции в разметке:
порядок блоков может меняться.

| Файл | Что внутри |
|---|---|
| `СПО/Очная форма.xlsx` | базовое расписание по чётности |
| `СПО/Листок замен.docx` | замены на конкретные даты |
| `Расписание звонков/понедельник.docx` | звонки для понедельника |
| `Расписание звонков/стандартное.docx` | звонки для остальных дней |

Если ссылка на `Очная форма.xlsx` не нашлась — `extract_links` бросает
`EiosParseError` с текстом «структура источника изменилась». Это значит,
что поменялась разметка страницы, а не что сайт лежит.

## Очное расписание (xlsx)

Сетка: строка — группа и день недели, столбец — пара.

### Две строки в ячейке = две недели

Верхняя строка — нечётная неделя, нижняя — чётная. Ячейка может быть
объединена по вертикали (тогда это одна и та же пара обе недели) или нет.

### Чётность считается со сдвигом

**Самое частое место ошибок.** Чётность колледжа — это ISO-неделя,
сдвинутая на 1:

```python
PARITY_OFFSET = 1   # tgbot/services/schedule_layer.py
```

ISO-неделя 43 → чётная неделя колледжа. Если бот показывает расписание
не той недели, проверяйте это первым.

### Кабинетов в файле нет

В `Очная форма.xlsx` **нет ни одного кабинета**. Кабинеты есть только
в листке замен (и то не у всех записей).

Поэтому у пар из базового расписания кабинет пустой — это норма, а не
баг парсера. Если староста хочет видеть кабинет, он ставит его правкой.

### Вечерние пары

Иногда в ячейке вместо обычной пары стоит время — это вечерние занятия
для заочников или платников. Показываются со своим временем (`time_note`),
а не по сетке звонков.

## Листок замен (docx)

Таблица с заголовком дня. Заголовок даёт дату, дальше строки по группам.

### Три действия

| Что в файле | Что значит |
|---|---|
| вместо X → Y | **replace**: пара заменена |
| «—» или пусто | **cancel**: пары не будет |
| добавлена строка | **add**: пара появилась |

### Названия групп пишут с ошибками

В листке встречаются `ЭОК-26` (регистр), `ДОУ - 25` (пробелы),
`ЭОф-26` (опечатка вместо `ЭО-26ФП`).

`_resolve_groups()` приводит их к именам из очного расписания через
`eios.match_group()`. Если группа не сопоставилась — в лог уходит
`группа из листка замен не найдена: '...'`, а запись **отбрасывается**.

Если в логах такое есть, значит замены для группы молча теряются.
Это повод добавить соответствие в `match_group`.

### Замены на будущие даты

Листок выдаётся сразу на несколько дней (например, СБ + ПН). Поэтому
рассылка собирает даты из самого листка, а не из фиксированного окна
«сегодня + 2».

## Звонки (docx)

Два файла — два `day_type`:

| Файл | `day_type` | Особенность |
|---|---|---|
| `понедельник.docx` | `MONDAY` | **только 5 пар** |
| `стандартное.docx` | `OTHER` | 6 пар |

Это не баг. В понедельник шестой пары действительно нет.

Внутри — деление на потоки (`course_group`): `I_IV` и `II_III`.
Ключ звонка — `(day_type, course_group, para)`.

## Дедупликация

ETag и Last-Modified у этих файлов ненадёжны, поэтому сравнение идёт по
`sha256` содержимого. Хеш хранится в `setting` под ключом
`eios_hash_ochoe` / `eios_hash_zameny` / `eios_hash_bells`.

Если хеш совпал — файл не разбирается и слои не перезаписываются.
Именно поэтому рассылка не уходит каждый день: она срабатывает только
при реальном изменении.

## Как проверить парсер руками

Скачать и разобрать без бота:

```bash
cd schedule-pipeline
.venv/bin/python -c "
import asyncio, sys
sys.path.insert(0, '.')
from aiohttp import ClientSession
from parsers import eios
from config import load_config

async def main():
    cfg = load_config('.env')
    async with ClientSession() as s:
        async with s.get(cfg.schedule_url) as r:
            links = eios.extract_links(await r.text())
    print('очное :', links.ochoe)
    print('замены:', links.zameny)
    print('звонки:', links.bells_monday, links.bells_standard)

asyncio.run(main())
"
```

Дальше можно разобрать конкретный файл:

```bash
.venv/bin/python -c "
import sys; sys.path.insert(0, '.')
from parsers import eios
data = open('/tmp/ptk/ochnoe.xlsx', 'rb').read()
lessons = eios.parse_ochoe(data)
print('пар:', len(lessons))
print('групп:', len({l.group for l in lessons}))
print(lessons[0])
"
```

## Что делать, если расписание неверное

1. **Съехала неделя** → `PARITY_OFFSET`, см. выше.
2. **Пропали замены** → ищите в логах `не найдена`, сверьте `match_group`.
3. **Пустые кабинеты** → норма для базового расписания.
4. **Расписание не обновилось** → проверьте `/stats`: если `⚠️ ЭИОС не
   отвечает`, проблема в сайте, а не в парсере.
5. **Пары не той группы** → сравните имена групп в БД и в файле:
   ```bash
   docker compose exec bot python -c "
   import sqlite3
   c = sqlite3.connect('/data/database.db')
   print([r[0] for r in c.execute('select distinct "group" from base_lesson')])
   "
   ```
