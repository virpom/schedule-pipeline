# План 157: новый факультет вуза становится недоступен — пустое имя кнопки

**Приоритет:** низкий. Сегодня не срабатывает: оба факультета в файле
распознаются. Но включится в тот день, когда вуз откроет третий, и
выглядеть будет как «группы пропали».

**Трудоёмкость:** S (~6 строк).

## Что происходит

`parsers/vuz.py:393-406`:

```python
def _faculty(sheet: Sheet) -> tuple[str, str]:
    for r in range(min(8, sheet.nrows)):
        for c in range(min(3, sheet.ncols)):
            v = sheet.text(r, c).upper()
            if "ГОРНО" in v:
                return "GTF", "Горно-технологический"
            if "ЭЛЕКТРОЭНЕРГЕТИК" in v:
                return "FEU", "Электроэнергетики, экономики и управления"
    return "", ""          # <- :406
```

Распознаются **ровно два** факультета по корню названия. Любой другой
лист получает пустой код.

Проверил на проде: факультетов два, оба покрыты.

```
vuz_group: 92 группы
  'GTF': 48
  'FEU': 44
```

## Что будет с третьим

`parse_sheet:625` пишет пустой код в справочник:

```python
VuzGroup(name=g + VUZ_SUFFIX, faculty=faculty, course=course, form="full")
```

Дальше `_vuz_faculty_kb` (`user.py:238-243`):

```python
groups = await repo.vuz_groups.all()
facs = sorted({g.faculty for g in groups})     # {"", "FEU", "GTF"}
rows = [[InlineKeyboardButton(text=FACULTY_NAMES.get(f, f),
                              callback_data=f"vu:fac:{f}")] for f in facs]
```

`FACULTY_NAMES` (`user.py`) знает только два кода:

```python
FACULTY_NAMES = {
    "FEU": "⚡ ФЭЭиУ",
    "GTF": "⛏ ГТФ",
}
```

Значит `FACULTY_NAMES.get("", "")` возвращает **пустую строку**.

## Почему пустая строка хуже ошибки

Telegram не отклоняет кнопку с пустым `text` — он **удаляет весь ряд**.
Проверено замерами от 22.08.2026: «An empty label deletes its row…
the message arrives with no keyboard at all — still `200 OK`».

То есть:

- ошибки нет ни в логах, ни в ответе API;
- студент видит клавиатуру без третьего факультета;
- **группы этого факультета недостижимы через выбор** — до них можно
  добраться только поиском по номеру, если он вообще работает.

Данные при этом целы: пары в `college_lesson` есть, `vuz_group`
заполнен. Сломана только навигация.

## Почему это не то же самое, что `_course`

Рядом живёт `_course:422-428` с тем же приёмом «не нашли — вернём
дефолт»:

```python
    return 1
```

Разница принципиальная: `1` — **осмысленное значение**, оно не ломает
ни один экран. Проверил: расхождений курса с номером группы на проде
**0** (все 92 группы совпадают).

`_faculty` возвращает `""` — значение, которое ломает клавиатуру
молча. Один и тот же приём, разные последствия.

## Что сделать

**1. Не писать пустой код в справочник** — отбросить такой лист с
предупреждением:

```python
faculty, faculty_name = _faculty(sheet)
if not faculty:
    raise VuzParseError(
        f"Лист «{sheet_name}»: не распознан факультет — "
        f"добавь корень названия в _faculty()")
```

Это громко: `sync_once:348` залогирует ошибку, `result["failed"]`
пополнится, админ увидит. См. план 156 — там же про то, что этот
`raise` рвёт цикл по формам; правки надо делать вместе.

**2. Не строить пустую кнопку** — подстраховать UI независимо от
парсера:

```python
rows = [[InlineKeyboardButton(
    text=FACULTY_NAMES.get(f) or f or "❓ Другой факультет",
    callback_data=f"vu:fac:{f}")] for f in facs]
```

Тогда даже старые записи с `faculty=""` дадут нажимаемую кнопку.

**Оба пункта нужны.** Первый не даёт новым данным испортиться, второй
спасает уже записанные.

## Проверено и признал корректным

**`_course` работает.** 92 группы, распределение 1 курс — 24, 2 — 21,
3 — 20, 4 — 17, 5 — 8, 6 — 2. Расхождений с номером группы **0**.

**`_year` работает.** Дефолт — текущий год; используется только для
разбора дат без года в `_cell_changes`, и `_year:414-418` сначала
ищет «20XX-20XX» в шапке.

**`_header_row` бросает исключение**, а не возвращает дефолт
(`:438`) — правильный образец, в отличие от `_faculty`.

**`faculty_name` не используется.** `parse_sheet:611` присваивает его,
но в `VuzGroup` идёт только код. Мёртвая переменная, безвредная.

**Данные не теряются.** Даже при пустом `faculty` пары пишутся в
`base_lesson` и материализуются в `college_lesson` — недоступна только
навигация.

## Риски

- **`raise` на неизвестном факультете** остановит разбор всего файла,
  если вуз переименует существующий факультет. Это лучше, чем тихая
  потеря, но требует, чтобы `_faculty` знал все актуальные корни.
  Проверил: сейчас их два, и оба в коде.
- **Правка UI (`or "❓ Другой факультет"`)** не решает причину —
  студент попадёт в список форм факультета с пустым кодом, и там
  `FORM_NAMES.get(f, f)` уже вернёт нормальный текст, потому что `f`
  это `"full"`/`"part"`. Цепочка сработает.
