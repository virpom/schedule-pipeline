# План 020: обновить `aiohttp` — 8 CVE, заблокировано версией aiogram

**Приоритет:** выше, чем кажется. Единственная находка про безопасность,
и обновление заблокировано зависимостью.

**Трудоёмкость:** M (обновление aiogram + прогон 183 тестов).

## Проблема

`requirements.txt:3`:

```
aiohttp~=3.10.10
```

Установлено `aiohttp 3.10.11`. `pip-audit` находит **8 уникальных
уязвимостей** (74 записи с дублями по базам):

| CVE / GHSA | Исправлено в |
|---|---|
| PYSEC-2026-2094…2107 (11 шт.) | 3.13.4 / 3.14.0 / 3.14.1 |
| PYSEC-2026-3545, 3546, 3547 | 3.14.2 / 3.14.3 |
| CVE-2026-111063…111066, 111064, 111748, 111749, 111750 | 3.14.4 |
| GHSA-2g87-pp6c-29x5 | 3.14.4 |

Все исправления — в **3.13.4+**, то есть за пределами всей ветки 3.10.

## Почему нельзя просто поднять aiohttp

`aiogram 3.13.1` жёстко ограничивает:

```
Requires-Dist: aiohttp<3.11,>=3.9.0
```

То есть `pip install aiohttp==3.14.4` сломает зависимости. Проверено
через `importlib.metadata.requires('aiogram')`.

## Проверенные варианты

| aiogram | ограничение aiohttp | Максимум |
|---|---|---|
| 3.13.1 (сейчас) | `<3.11` | 3.10.11 ← уязвим |
| 3.20.0 | `<3.12` | 3.11.18 — всё ещё уязвим |
| 3.25.0 | `<3.14` | 3.13.5 — почти |
| **3.31.0** | **`<3.15`** | **3.14.5 ← все CVE закрыты** |

Нужен **aiogram 3.31.0** (текущая стабильная).

## Насколько это опасно на практике

Бот — **клиент**, не сервер:

- Серверные векторы (HTTP request smuggling, DoS на парсинге запросов)
  **неприменимы** — бот не принимает входящие HTTP.
- Клиентские векторы применимы: контент приходит с `eios.norvuz.ru`
  и `norvuz.ru`, которыми бот не управляет. Если сайт скомпрометирован
  или отвечает враждебно, уязвимость может сработать.
- aiogram использует aiohttp для Telegram API — доверенный сервер.

**Вывод:** риск средний, не критический. Но 8 CVE в единственной
сетевой библиотеке — это то, что не хочется оставлять навсегда.

## Что сделать

### 1. Обновить aiogram

```
aiogram~=3.31.0
aiohttp~=3.14.5
```

Проверить остальные ограничения aiogram 3.31 на другие пакеты —
`pydantic`, `magic-filter`, `certifi`. Скорее всего они не конфликтуют
с текущими, но проверить.

### 2. Прогнать тесты

```bash
.venv/bin/python -m pytest -q     # ожидаем 183 passed
```

Тесты почти не касаются aiogram (только `CallbackQuery`/`Message`
в 4 файлах). Основной риск — **изменения API** между 3.13 и 3.31.

Что проверить вручную после обновления:

- `/start` и любая кнопка (middleware, FSM),
- админка: `/stats`, рассылка (меню),
- редактор: правка базы, замена, откат,
- вузовская навигация: факультет → форма → курс → группа.

### 3. Проверить `DefaultBotProperties`

`main.py:56`:

```python
bot = Bot(token=..., default=DefaultBotProperties(parse_mode="HTML"))
```

Это API aiogram 3.x, стабилен с 3.7. Скорее всего не сломается, но
это единственное место, где aiogram используется не через декораторы.

### 4. Проверить `MemoryStorage`

`main.py:57` — `Dispatcher(storage=MemoryStorage())`. Не менялся.

### 5. Зафиксировать результат

После обновления:

```bash
.venv/bin/python -m pip_audit -r requirements.txt
```

Ожидаемо: `No known vulnerabilities found`.

## Как проверить

```bash
# локально
.venv/bin/python -m pip install -U "aiogram~=3.31.0" "aiohttp~=3.14.5"
.venv/bin/python -m pytest -q
.venv/bin/python -m pip_audit -r requirements.txt

# на проде после деплоя
docker exec <bot> python -c "import aiogram, aiohttp; print(aiogram.__version__, aiohttp.__version__)"
docker logs --tail 20 <bot>     # после плана 015
```

## Риски

- **Ломающие изменения aiogram.** Между 3.13 и 3.31 — 18 минорных
  версий. Прочитать `CHANGES.rst` aiogram перед обновлением,
  обратить внимание на `CallbackQuery.answer`, `FSMContext`,
  `InlineKeyboardMarkup`.
- **Не обновлять «на всякий случай» вместе с другими пакетами.**
  Отдельный коммит: только aiogram + aiohttp, чтобы легче откатить.
- **Если что-то сломалось** — откатиться на `aiogram~=3.13.1` и
  принять риск CVE (бот за NAT, векторы клиентские, сайт доверенный).
  Это осознанный компромисс, а не забывчивость.
