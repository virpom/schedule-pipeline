# План 148: преподаватель вуза видит звонки колледжа

**Приоритет:** средний. Сейчас не видно никому (все 167 преподавателей
вуза ботом не пользуются), но при подключении человек получит чужую
сетку — ту же проблему, которую уже чинили для студентов вуза.

**Трудоёмкость:** S (~3 строки).

## Проблема

`cb_bell` (`user.py:751`) выбирает сетку так:

```python
is_vuz_user = (is_vuz(user.group) if user.group
               else user.unit == "vuz")
```

Логика: «если группа известна — смотри её суффикс, иначе спроси
`unit`». Для студента верно. **Для преподавателя — нет:** у него
`group = None` всегда, он ведёт пары, а не учится в группе.

А `unit` у преподавателя остаётся дефолтным:

```
users с group = NULL:
  6602662332  role=teacher  unit=college  teacher=None
  1039429314  role=teacher  unit=college  teacher='Молчанова Н.А.'
  1037099659  role=teacher  unit=college  teacher='Боровик И.А.'
```

Дефолт в схеме: `unit VARCHAR(16) NOT NULL DEFAULT 'college'`. Значит
**любой преподаватель вуза получит `unit='college'`**, пока его не
переключат вручную — а переключать некому, `/setunit` не существует.

## Что видит преподаватель вуза

Проверил `format_bell(bell, lunches, vuz=False)`:

```
⏰ Расписание звонков

Понедельник
🇷🇺 Разговоры о важном · 09:00–09:20
1 и 4 курс
1 пара  09:25–10:10 / 10:15–11:00
2 пара  11:10–11:55 / 🍽 11:55–12:20 / 12:20–13:05
3 пара  13:15–14:00 / 14:05–14:50
...
```

А должен видеть (`vuz=True`):

```
⏰ Расписание звонков вуза

1 пара  08:40–09:25 / 09:35–10:10
2 пара  10:20–11:05 / 11:15–11:50
3 пара  12:10–12:55 / 13:05–13:40
...
8 пара  20:30–21:15 / 21:25–22:00
```

**Пять пар вместо восьми, обед колледжа, «Разговоры о важном»** — всё
чужое. Вуз учится до 22:00, а человеку показывают до 15:20.

## Почему `unit` не помогает

Проверил все места, где он читается или пишется:

```
user.py:533   user.unit = "vuz"        <- при выборе группы вуза
user.py:590   user.unit = "college"    <- при выборе группы колледжа
user.py:754   user.unit == "vuz"       <- единственное чтение
```

**`unit` полностью дублирует суффикс `@vuz` в поле `group`** и
заполняется только вместе с ним. Для преподавателя ни одна из веток
не срабатывает — он группу не выбирает.

Проверил согласованность на живой базе:

```
users с группой: 243
  расхождений unit vs @vuz: 1
    id=6629888790  group='АП-25оз@vuz'  unit='college'
```

Одно расхождение — и оно безвредно, потому что при известной группе
`unit` не читается.

## Что сделать

Спросить принадлежность по преподавателю тоже. Проще всего — по его
парам, но это лишний запрос на каждый клик по «Звонкам».

Надёжнее: при выборе роли преподавателя и вводе фамилии определять
подразделение один раз и писать в `unit`. Тогда проверка уже
существующая сработает.

Либо, если не хочется трогать ввод, — читать `unit` **раньше** группы
и синхронизировать его при любом изменении группы:

```python
is_vuz_user = user.unit == "vuz" or is_vuz(user.group)
```

Но тогда расхождение `6629888790` начнёт вредить: у него
`unit='college'`, а группа вуза — покажет колледж. Значит порядок
надо сохранить (`group` первым), а `unit` заполнять правильно.

**Минимальное корректное решение:** при вводе фамилии преподавателя
спросить подразделение и записать `unit`, как это делается для
студентов (`:533` / `:590`).

## Что проверил и признал корректным

**Для студента вуза сетка верная.** `is_vuz('ИС-25@vuz')` → `True`,
`unit` не читается. Проверил обоих студентов вуза (2119263223,
1286816332) — у них группа с суффиксом, всё правильно.

**Для студента колледжа верно.** Группа без суффикса → `False`,
`unit='college'` совпадает.

**`set_unit` пишет корректно.** Проверил `user.py:79` — простой
`update`, вызывается только из двух мест, оба с правильным значением.

**`unit` не влияет ни на что другое.** Проверил grep по `tgbot/`:
единственное чтение — `:754`. Расписание, замены, звонки-напоминания
его не смотрят.

## Риски

- **Спрашивать подразделение при вводе фамилии** — лишний шаг для
  преподавателя. Но без него `unit` не заполнить, а угадать по
  фамилии нельзя: «Молчанова Н.А.» есть и в колледже, и в вузе.
- **`bell.py` тоже выбирает сетку по группе** (`course_group_from_group`),
  но у преподавателя группа приходит из `college_lesson`, а не из
  `users` — там всё правильно.
