## Разметка: почему это дешевле, чем казалось

Проверил по документации MAX, не по памяти:
[форматирование текста](https://dev.max.ru/docs-api/use-cases/sending-messages/text-formatting/).

MAX принимает `format: "html"` с тегами `<b>`, `<i>`, `<s>`, `<u>`,
`<code>`, `<pre>`, `<a href>`, `<blockquote>`.

Наш код использует ровно: `<b>` (123), `<i>` (13), `<s>` (1), `<code>` (6).
**Все поддерживаются.** Значит тексты переиспользуются как есть, без
второго рендерера. Это снимает половину работы.

## Как проверяем, что ничего не сломалось

Главный риск: рефакторинг меняет текст на экране незаметно. Поэтому
**сравнение побайтово на живой базе**, а не «на глаз looks fine».

### Проверка A — золотые строки (главная)

Скрипт снимает **текущий** вывод `_day_text` для всех пользователей
и всех дат окна, пишет в JSON:

```python
# до рефакторинга
for user in users:            # 324 человека
    for date in window:       # 14 дат
        gold[f"{user.id}:{date}"] = await _day_text(repo, user, date)
```

Это **4536 случаев**. После рефакторинга тот же скрипт зовёт новый путь
и сравнивает. Требование: **0 расхождений**.

Файл `tests/fixtures/golden_day_text.json` кладём в репозиторий, чтобы
проверка работала и без прод-базы.

### Проверка B — все пять состояний дня

Явно, отдельными тестами, потому что именно в ветках живут баги:

| Состояние | Как воспроизвести |
|---|---|
| нет группы | пользователь без `group` |
| есть пары | обычный день |
| всё отменено | все `action == SUB_CANCEL` |
| не опубликовано | `schedule_file` без записи |
| сайт лежит | `is_stale` = True, `last_ok` есть и нет |

Плюс преподаватель без группы, преподаватель только вуза, студент вуза.

### Проверка C — клавиатуры

Для каждой клавиатуры: число кнопок, `callback_data` ≤ 64 байт,
не больше 12 в ряду, суммарно ≤ 100. Это ограничения Telegram — если
адаптер их нарушит, кнопка отвалится молча.

### Проверка D — полный прогон

`pytest -q` — 1013 тестов должны остаться зелёными. Ни один не удаляем
и не «подгоняем» под новый код, кроме случаев, где тест проверял
внутренности, которых больше нет (тогда переписываем на проверку
поведения, как делали с `_retry`).

### Проверка E — живой прогон на копии базы

Скопировать прод-базу, поднять бота с ней локально, потыкать все экраны.
Только после этого — решение о деплое (отдельно, не в этом плане).

- **Не трогает прод.** Деплой — отдельное решение после проверок D и E.
