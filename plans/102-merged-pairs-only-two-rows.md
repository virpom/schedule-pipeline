# План 102: `merged_pairs` ловит только 2-строчные объединения

**Приоритет:** низкий. Сегодня потерь нет — проверил все 937 объединений
в колонках групп. Но парсер молча теряет данные, если источник
отформатируют иначе.

**Трудоёмкость:** S (одна строка).

## Проблема

`parsers/eios.py:266` строит множество объединённых ячеек так:

```python
merged_pairs = {
    (rng.min_row, rng.min_col)
    for rng in sheet.merged_cells.ranges
    if rng.min_col == rng.max_col and rng.max_row == rng.min_row + 1
}
```

Условие `rng.max_row == rng.min_row + 1` — **ровно две строки**. Всё,
что выше, в множество не попадает.

Дальше парсер использует его так:

```python
# Объединённая ячейка — одна пара на обе недели.
if (row, col) in merged_pairs:
    if top_subject:
        lessons.append(BaseLesson(..., para=para, subject=top_subject, ...))
    continue

# Разъединённая: верх = чётная, низ = нечётная.
if top_subject:
    lessons.append(BaseLesson(..., parity=PARITY_EVEN, ...))
```

То есть непойманное объединение разбирается как **две пары по
чётности** вместо одной общей. Если ячейка была объединена на три
строки, верх попадёт в чётную неделю, а низ — в нечётную, хотя это
была одна пара на все недели.

## Воспроизвёл на синтетическом файле

Собрал xlsx с трёхстрочным объединением и прогнал через `parse_ochoe`:

```
2-строчное объединение:  para=1  parity=BOTH   <- правильно, одна пара на обе недели
3-строчное объединение:  para=1  parity=EVEN   <- пара только в ЧЁТНУЮ неделю
```

**Пара молча пропадает в нечётной неделе.** Ни ошибки, ни предупреждения
в логе — просто в нечётную неделю студент видит пустой день.

## Что в реальном файле

Скачал текущий `Очная форма.xlsx` с прода (52550 байт, 4 листа) и
посчитал все объединения:

```
в колонках групп (col >= 3):
  высота 2: 930
  высота 3:   7
```

Семь трёхстрочных. Все — **пустые**:

```
3 курс  I23:I25   -> None
```

Проверил содержимое вокруг: в строке 23 стоит `5 пара`, в 24–25 пусто,
данные группы `ЮР-24Б` начинаются только в строке 26. То есть
объединение сделано для оформления, данных в нём нет.

**Потерь нет.** Парсер читает строку 23 один раз, строки 24–25
пропускает по `if not (para_cell and "пара" in str(para_cell))`.

## Почему это всё-таки стоит починить

Условие `max_row == min_row + 1` — это допущение о разметке, а не о
данных. Оно перестанет выполняться, как только методист объединит
ячейку на три строки и что-то в неё впишет — например, пару, которая
идёт два академических часа с перерывом. Тогда:

- верхняя строка уйдёт в чётную неделю,
- нижняя — в нечётную,
- и расписание разъедется по неделям без единой ошибки в логах.

## Что сделать

Считать объединением любое, что занимает больше одной строки:

```python
merged_pairs = {
    (rng.min_row, rng.min_col)
    for rng in sheet.merged_cells.ranges
    if rng.min_col == rng.max_col and rng.max_row > rng.min_row
}
```

`> min_row` вместо `== min_row + 1`. Одна строка.

**Проверил правку на живом коде** (временно применил, прогнал, откатил):

```
высота 2: 1 пара, parity=BOTH    <- как было, не сломалось
высота 3: 1 пара, parity=BOTH    <- починилось
все тесты: 184 passed
```

Исходники не менял — правка была временная, для проверки.

**Проверить, что не сломает текущий файл.** Все 930 двухстрочных
попадают в множество и раньше, и сейчас — поведение для них не
меняется. Семь трёхстрочных теперь тоже попадут; поскольку они пустые,
`if top_subject` не сработает и ничего не добавится. Вывод парсера
останется прежним.

## Проверено и признано корректным

**`para_end` в новом парсере нет — и это правильно.** В старом
`parsers/polar.py` (удалён в `8f00303`) было:

```python
def _parse_para(raw: str) -> tuple[int, int] | None:
    nums = [int(x) for x in re.findall(r"\d+", raw)]
    return nums[0], nums[-1]
```

То есть из ячейки «3-4 пара» получалось `para=3, para_end=4`. Новый
`parsers/eios.py` берёт только первое число:

```python
_PARA_RE = re.compile(r"\d+")
para = int(_PARA_RE.search(str(para_cell)).group())
```

Проверил, теряется ли что-то: **в текущем xlsx нет ни одной ячейки с
двумя номерами**. Все варианты в файле — `'1 пара'`, `'2 пара'`,
`'3 пара'`, `'4 пара'`, `'5 пара'`. Так что `para_end` всегда равен
`para`, и потери нет.

**27 строк с `para_end = para + 1` в `college_lesson` — исторический
осадок.** Все они на датах 02.10–08.10, то есть **вне окна
материализации** (14 дней от 26.10), и потому не перезаписаны. В окне
(26.10 и позже) таких строк **0**. Это данные от старого парсера
`polar.py`, который работал до перехода на ЭИОС (коммит `8f00303`,
23.10).

**`format_day` и `bell._tick` умеют `para_end`** — `common/schedule.py:234`
и `tgbot/services/bell.py:51` обходят `range(para, para_end + 1)`. То
есть если источник когда-нибудь начнёт отдавать сдвоенные пары, код
отрисует их правильно. Сейчас просто нечего отрисовывать.

## Риски

- **Расширение условия может поймать объединение по вертикали, которое
  не про пары.** Например, если методист объединит ячейку группы на
  весь день. Тогда `top_subject` возьмётся один раз и размножится не
  туда. Но такое объединение и сейчас ломает разбор — просто иначе.
- **Тест придётся дописать.** Проверил `tests/test_eios_parser.py`:
  хелпер `_make_xlsx` (строка 41) жёстко делает двухстрочные:

  ```python
  for row, col in merged:
      ws.merge_cells(start_row=row, start_column=col,
                     end_row=row + 1, end_column=col)
  ```

  `end_row=row + 1` — всегда две строки. Трёхстрочное объединение
  фикстурой не выразить, поэтому дефект тестами и не покрыт.

  Правка хелпера — три строки:

  ```python
  for item in merged:
      row, col, height = item if len(item) == 3 else (*item, 2)
      ws.merge_cells(start_row=row, start_column=col,
                     end_row=row + height - 1, end_column=col)
  ```

  Тогда тест на дефект пишется так:

  ```python
  def test_three_row_merge_is_both_weeks():
      data = _make_xlsx(
          rows=[(5, "ПОНЕДЕЛЬНИК", 1, {3: "Физика\nИвасишина Е.Е."})],
          groups={3: "ДП-26"},
          merged=[(5, 3, 3)],      # три строки
      )
      lessons = parse_ochoe(data)
      assert len(lessons) == 1
      assert lessons[0].parity == PARITY_BOTH
  ```

  **Сейчас этот тест падает** — возвращается `parity=EVEN`.
