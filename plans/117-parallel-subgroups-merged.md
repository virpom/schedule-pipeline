# План 117: параллельные подгруппы выглядят как одна пара с двумя предметами

**Приоритет:** средний. Задевает 3 группы вуза (≈60 студентов) на
конкретных днях. Данные верны, но подача сбивает с толку.

**Трудоёмкость:** S (~10 строк).

## Что происходит

В вузе часть занятий идёт **параллельно по подгруппам**: половина
группы на физкультуре, половина — на иностранном, в одно и то же
время. В файле `.xls` это две отдельные пары на одном слоте.

`_merge_para_clash` (`sync_eios.py:315`) склеивает их в одну строку
через `" / "`. Студент видит:

```
7) 18:50–20:20  Физическая культура и спорт (лек.,прак. ) / Иностранный язык (прак. )
   Кабышева М.И., Кострицына Н.А.
```

**Три вещи непонятны:**
1. Какой предмет **его** — оба в одной строке
2. Кто из двух преподавателей чей
3. Что это **одновременно**, а не две пары подряд

## Масштаб — проверил на проде

Слотов с несколькими парами на номер после фильтра по неделе: **5**,
в **3 группах**:

```
ИП-26-2@vuz   28.10  п7, п8
СА - 26-2@vuz 28.10  п7, п8
АП-24@vuz     02.11  п5
```

В `college_lesson` ровно 5 строк со склейкой — все корректны:

```
ИП-26-2@vuz    28.10 п7  Физическая культура и спорт / Иностранный язык
ИП-26-2@vuz    28.10 п8  Иностранный язык / Прикладная физическая культура
СА - 26-2@vuz  28.10 п7  Физическая культура и спорт / Иностранный язык
СА - 26-2@vuz  28.10 п8  Иностранный язык / Прикладная физическая культура
АП-24@vuz      02.11 п5  Электрические машины / Теория автоматического управления
```

**Дублей номера пары: 0.** UNIQUE `(date, group, para)` держит,
склейка работает.

## Почему это нельзя показать точнее

**В файле нет признака подгруппы.** Проверил все 11 листов обоих
файлов на `подгрупп|пгр|1 п/гр|2 п/гр` — **0 совпадений**.

Значит бот не может знать, кто в какой подгруппе. Склейка через `/` —
честный максимум: «в это время идут два занятия, уточни у куратора».

## Что сделать

Сделать склейку **читаемой**. Сейчас два предмета слиты в одну строку
без пояснения. Вариант — разнести по строкам с пометкой:

```python
def _merge_para_clash(slots: list) -> list:
    ...
    seen[slot.para] = Slot(
        para=slot.para,
        subject=f"{prev.subject}  <i>или</i>  {slot.subject}"[:256],
        ...
    )
```

Слово «или» вместо «/» сразу говорит, что занятия параллельные, а не
последовательные.

Второй шаг — развести преподавателей по предметам:

```python
teacher=f"{prev.teacher} / {slot.teacher}"[:128]
```

Уже так и есть. Но в выводе `format_day` (`common/schedule.py:264`)
они соединяются через `" · "`, и получается
`Кабышева М.И., Кострицына Н.А.` — запятая сливает их в одно.

Правка в `_merge_para_clash` — соединять через `" / "` вместо `", "`,
чтобы разделитель совпадал с разделителем предметов.

## Проверено и признано корректным

**Склейка не теряет предмет.** Проверил на проде: искал слоты, где
один предмет — подстрока другого (условие
`if lesson.subject not in found.subject` в `_merge_slot_clash`
теоретически теряет такой предмет). **0 случаев** среди 92 вузовских
групп за 14 дней.

**`_merge_para_clash` склеивает верно.** 5 пар → 3 строки, оба предмета
сохранены, преподаватели сохранены.

**Обрезки по 256 символов нет.** Проверил самую длинную склейку:
73 символа при лимите 256.

**`get_day` возвращает несколько строк на `para`, только если у них
разные `weeks`.** Это by design: у вуза в одном слоте живут пары на
разных неделях. Ключ `(para, weeks)` в `merged` это учитывает, а
`_fits_week` отсекает лишние.

## Риски

- **Слово «или» может быть неверно** в случае `АП-24@vuz`: там
  «Электрические машины» и «Теория автоматического управления» — это,
  возможно, не подгруппы, а ошибка в файле. Но раз файл так говорит,
  показать «или» честнее, чем склеить в один предмет.
- **`subgroup` в схеме нет.** `_merge_para_clash` уже помечает это
  `ponytail`-комментарием. Если вуз начнёт всерьёз делить группы,
  нужна колонка и выбор подгруппы в настройках пользователя — это
  отдельная задача, не правка.
