# План 025: `materialize_day` не отмечает день как опубликованный

> **СДЕЛАНО 27.10.2026** (коммит `38e94f9`).
>
> Общая функция `_publish_day` в `sync_eios.py`, вызванная из
> `materialize` и `materialize_day`. Существующий признак не
> перетирается — проверка `get_hash(date) is None` осталась.
>
> Дедупликация 45 строк, о которой говорит план, **не делалась**:
> `materialize` и `materialize_day` расходятся в том, откуда берут
> `manual`-строки, и сводить их — отдельная правка на риск сломать
> материализацию. Здесь только недостающий вызов.

**Приоритет:** низкий. Латентный — проявится, когда староста поставит
замену на день за пределами 14-дневного окна.

**Трудоёмкость:** S (~4 строки).

## Проблема

`sync_eios.materialize` (строка 460) после записи дня делает:

```python
if await repo.schedule_files.get_hash(date) is None:
    await repo.schedule_files.set_hash(date, f"eios-{date.isoformat()}")
```

`materialize_day` (строка 350) — **не делает**. Он заканчивается на
`replace_date` и возвращает `len(rows)`.

Две функции собирают одни и те же строки (~45 строк дублированного
кода), но одна пишет признак публикации, а другая нет.

## Почему это важно

`user.py:674` решает, что показать на пустой день:

```python
published = await repo.schedule_files.get_hash(date) is not None
if note:          text = format_no_lessons(date, note)
elif published:   text = format_no_lessons(date)          # «занятий нет»
elif stale:       text = format_unverified(date, last_ok)  # «данные не проверены»
else:
    ...           text = format_not_published(date)        # «не выложено»
```

Три разных сообщения, и выбор зависит от `schedule_file`.

## Когда ломается

Сейчас на проде расхождений нет — поллер каждые 5 минут делает полный
`materialize` на 14 дней, и все даты покрыты:

```
даты в college_lesson без schedule_file: 0
```

Но есть обратный перекос — 2 даты есть в `schedule_file` и отсутствуют
в `college_lesson` (`2026-10-25`, `2026-11-01` — воскресенья).

**Сценарий поломки:**

1. Староста ставит замену на день `D+15` (за пределами окна).
2. `cb_sub_edit` → `_rebuild(repo, date=D+15)` → `materialize_day`.
3. Строки записаны, `schedule_file(D+15)` **не создан**.
4. Пар на этот день нет (или все отменены).
5. Студент открывает `D+15`:
   - `published = False`
   - `stale = False` (сайт жив)
   - `now.hour < deadline_hour`
   - → **«Расписание ещё не выложено»**

Хотя день уже обработан и замены учтены. Сообщение вводит в заблуждение:
студент ждёт публикации, которой не будет.

## Что сделать

Вынести общую часть в одну функцию и вызвать из обеих:

```python
async def _publish_day(repo, date) -> None:
    """Отметить день как опубликованный.

    Нужно и полному materialize, и материализации одного дня после
    правки старосты: иначе день, пересобранный только правкой, для
    студента выглядит «ещё не выложенным».
    """
    if await repo.schedule_files.get_hash(date) is None:
        await repo.schedule_files.set_hash(date, f"eios-{date.isoformat()}")


async def materialize_day(repo, date) -> int:
    ...
    await repo.college_lessons.replace_date(date, rows)
    await _publish_day(repo, date)
    return len(rows)
```

И в `materialize` заменить блок на `await _publish_day(repo, date)`.

**Заодно** убрать дублирование. Сверил два блока построчно — они
совпадают **побайтно**, кроме двух вещей:

| | `materialize_day` | `materialize` |
|---|---|---|
| отступ | 4 пробела | 8 пробелов (внутри цикла по дням) |
| источник групп | `await repo.base_lessons.get_groups()` прямо в цикле | `groups`, полученный один раз до цикла |

Второе — важное: `materialize` уже вынес `get_groups()` из цикла
(правильно), а `materialize_day` вызывает его при каждом вызове
(не страшно, он для одного дня).

Вынести общее в `_day_rows(repo, date, groups)` и вызвать из обеих
функций. Это же нужно плану 008. Сделать обе правки одним коммитом.

## Как проверить

```python
def test_materialize_day_marks_published():
    """День, пересобранный правкой, считается опубликованным.

    materialize писал schedule_file, а materialize_day — нет, поэтому
    пустой день после правки выглядел «ещё не выложенным».
    """
```

Вживую: староста ставит замену на `+16` дней → студент открывает этот
день → должно быть «Занятий нет», а не «не выложено».

## Риски

- **Семантика «опубликовано».** Сейчас `schedule_file` означает «сайт
  выложил файл на этот день». `materialize_day` пишет туда же — но по
  смыслу это «день обработан», а не «сайт опубликовал». Разница
  проявится, если когда-нибудь понадобится отличать. Пока оба
  означают одно и то же для пользователя, так что правка безопасна.
  Если хочется строгости — завести отдельный ключ, но это лишняя
  работа.
- **Воскресенья.** 2 даты есть в `schedule_file`, но не в
  `college_lesson` — это дни без пар. `get_groups()` вернёт группы, но
  `get_day_slots` даст пусто, и `replace_date(date, [])` запишет ноль
  строк. `schedule_file` при этом останется. Так и задумано.
