# План 024: однофамильцы неразличимы в поиске преподавателя

> **СДЕЛАНО 27.10.2026** (коммит `9df8ea4`, тот же, что закрыл 107).
>
> `teacher_matches` сверяет инициалы, а не только фамилию. Проверено
> прогоном: `Силин Д.Ю.` не совпадает с `Силин Д.С.`, `Кабышева М.И.`
> не совпадает с `Кабышева Н.А.`, а варианты записи (`Силин Д. С.` /
> `Силин Д.С.`) и поиск по одной фамилии работают как раньше.
>
> Этот план и 107 описывают один дефект; 107 — основная запись, здесь
> остался замер охвата (7 пар, а не 3) и разбор по `college_lesson`.

**Приоритет:** средний. Найдено **3 пары настоящих однофамильцев**,
у одной из пар общая группа — расписания смешаются.

**Трудоёмкость:** S (~10 строк).

## Проблема

`common/schedule.py:86`:

```python
def teacher_matches(lesson_teacher: str, selected_name: str) -> bool:
    lb = teacher_base(lesson_teacher)
    if lb == selected_name:
        return True
    ls = lb.split()
    ss = selected_name.split()
    if not ls or not ss:
        return False
    return ls[0].casefold() == ss[0].casefold()   # ← только фамилия
```

Если выбрано «Силин Д.С.», сравнение идёт по `ls[0]` — только фамилия.
Значит **«Силин Д.Ю.» тоже совпадёт**.

фамилии — иначе «Горпинченко В.А.» увидит пары по архивному делу.

### Самый неприятный случай

```
Кабышева М.И. -> ГП-25@vuz, ТМ-25@vuz, ИП-25@vuz
Кабышева Н.А. -> ГП-25@vuz          ← та же группа!
```

Обе преподают в `ГП-25@vuz`. Студент этой группы ищет «Кабышева» —
получает расписание **обеих** вперемешку, и не может понять, какая
пара его.

```
Силин Д.Ю. -> ПС-22оз@vuz           ← отдельная группа
Силин Д.С. -> СА-24@vuz, ГИ-24@vuz, МД-24@vuz, ГД-24оз@vuz, СА-24оз@vuz
```

## Что сделать

Сравнивать фамилию **и инициалы, если они есть в запросе**:

```python
def teacher_matches(lesson_teacher: str, selected_name: str) -> bool:
    """Совпадает ли преподаватель пары с выбранным.

    Сравниваем фамилию и, если в запросе есть инициалы, их тоже:
    иначе «Силин Д.С.» находил ещё и «Силин Д.Ю.».
    """
    lb = teacher_base(lesson_teacher)
    sel = teacher_base(selected_name)
    if lb == sel:
        return True
    ls, ss = lb.split(), sel.split()
    if not ls or not ss:
        return False
    if ls[0].casefold() != ss[0].casefold():
        return False
    # Запрос без инициалов («Коленова») — оставляем поиск по фамилии.
    if len(ss) == 1:
        return True
    # Запрос с инициалами — сверяем их.
    return len(ls) > 1 and ls[1].casefold() == ss[1].casefold()
```

Заметить: `teacher_base` уже убирает пробелы внутри инициалов, поэтому
`Силин Д. С.` и `Силин Д.С.` дадут одинаковый `ls[1] == "д.с."`.

## Что это не ломает

- **Поиск по одной фамилии** («Коленова») — работает как раньше
  (`len(ss) == 1`).
- **Варианты записи** одного человека (`Елесин М. А.` / `Елесин М.А.`)
  — `teacher_base` нормализует, сравнение пройдёт.
- **Колледж** — те же правила, у него тоже есть варианты записи.

## Воспроизведено на текущем коде

```
teacher_matches('Силин Д.Ю.',    'Силин Д.С.')   -> True   ← должно False
teacher_matches('Кабышева Н.А.','Кабышева М.И.') -> True   ← должно False
teacher_matches('Иванова Н.А.', 'Иванова З.Н')   -> True   ← должно False
```

Фикс прогнан на 7 случаях — все верны:

```
Силин Д.Ю.  vs Силин Д.С.  -> False  ✓
Силин Д.С.  vs Силин Д.С.  -> True   ✓
Силин Д. С. vs Силин Д.С.  -> True   ✓ (пробел в инициалах)
Силин Д.С.  vs Силин       -> True   ✓ (поиск по фамилии)
Кабышева Н.А. vs М.И.      -> False  ✓
Иванова Н.А.  vs З.Н       -> False  ✓
Елесин М. А.  vs М.А.      -> True   ✓ (вариант записи)
```

## Как проверить

```python
def test_homonyms_not_mixed():
    """Однофамильцы с разными инициалами — разные люди.

    В данных есть Иванова З.Н./Н.А., Кабышева М.И./Н.А.,
    Силин Д.С./Д.Ю. Сравнение только по фамилии их смешивало.
    """
    assert teacher_matches("Силин Д.Ю.", "Силин Д.С.") is False
    assert teacher_matches("Силин Д.С.", "Силин Д.С.") is True
    assert teacher_matches("Силин Д. С.", "Силин Д.С.") is True   # пробел
    assert teacher_matches("Силин Д.С.", "Силин") is True          # по фамилии
```

Вживую: «🔍 Найти преподавателя» → «Силин» → выбрать «Силин Д.Ю.» →
в неделе не должно быть пар `СА-24@vuz`, `ГИ-24@vuz`, `МД-24@vuz`.

## Риски

- **Запрос с инициалами в другом формате.** Если пользователь введёт
  «Силин Дмитрий» (имя полностью), `ss[1]` будет «дмитрий», а `ls[1]`
  — «д.с.». Тогда совпадения не будет, хотя человек тот. Сейчас такого
  ввода нет: список преподавателей приходит из базы, где только
  «Фамилия И.О.». Но если добавят ручной ввод — учесть.
- **`teacher_base` на запросе.** Сейчас она применяется только к
  `lesson_teacher`. Применить и к `selected_name` — обязательно,
  иначе «Силин Д. С.» из списка не совпадёт сам с собой.
