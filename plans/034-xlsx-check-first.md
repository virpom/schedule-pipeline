# План 034: `.xlsx`-проверка перехватывает чужие файлы

> **СДЕЛАНО 27.10.2026** (коммит `d1edbf8`).
>
> Порядок обратный: замены, заочка, звонки, и только потом «очная» +
> `.xlsx`. Одного расширения больше не достаточно — `.xlsx` без слова
> «очная» очной формой не считается и даёт `EiosParseError`, то есть
> тревогу, а не тихое стирание 704 строк.
>
> Проверено на живой странице (200, 88313 байт): все пять ссылок
> разбираются как раньше.

**Приоритет:** высокий. Тот же исход, что в плане 001 (стирание
расписания колледжа), но **другой триггер** — и план 001 его не
закрывает.

**Трудоёмкость:** S (~6 строк).

## Проблема

`parsers/eios.py:147`:

```python
if name.endswith(".xlsx"):
    result.ochoe = url
elif "замен" in name:
    result.zameny = url
elif "заоч" in name:
    result.zaochnoe = url
elif "звон" in url.lower() or "понед" in name or "стандарт" in name:
    ...
```

Проверка **расширения** стоит первой, а смысловые признаки — после,
в `elif`. Значит любой файл с именем на `.xlsx` назначается «очной
формой», чем бы он ни был.

Сейчас работает только потому, что заочка и листок замен лежат в
`.docx`. Проверил на живом HTML — все 5 ссылок разбираются верно:

```
очная форма.xlsx    -> ochoe
листок замен.docx   -> zameny
заочная форма.docx  -> zaochnoe
понедельник.docx    -> bells_monday
стандартное.docx    -> bells_standard
```

## Что сломается

Достаточно, чтобы колледж сменил формат **листка замен** на `.xlsx` —
это более вероятно, чем кажется: у вуза уже есть `.xls` и `.xlsx` в
одном каталоге (`3-zaochnoe.xls`, `5-sessiy-mag-ochno-zaoch.xlsx`).

```
1. «Листок замен.xlsx» появляется на странице
2. extract_links: endswith(".xlsx") -> ochoe = листок замен
   ветка "замен" не выполняется (elif)
3. _sync_ochoe -> parse_ochoe(листок замен) -> 0 пар
4. replace_base_lessons([]) ->
      DELETE FROM base_lesson WHERE source='site'   <- 704 строки
      commit()
5. _sync_zameny: zameny is None -> замены не обновляются вовсе
6. materialize: get_groups() вернёт только @vuz
   college_lesson перезаписан без колледжа
7. 220 студентов видят «Занятий нет»
```

Проверил шаг 3 — собрал `.xlsx` с шапкой листка замен и прогнал
`parse_ochoe`:

```
parse_ochoe на листке замен -> 0 пар
```

Шаг 4 подтверждён чтением кода: `delete()` выполняется **до** вставки,
безусловно, без проверки на пустоту.

## Почему план 001 не спасает

План 001 ставит guard на `if not lessons: raise` в `_sync_ochoe`.
Это закрывает случай «правильный файл, но разбор дал пусто». Здесь
guard **тоже сработает** — но только как вторая линия: он превратит
тихое стирание в исключение и тревогу админу.

Однако останется вторая половина проблемы: `zameny` не разберётся
(ссылка ушла в `ochoe`), и замены не обновятся. Плюс если листок замен
случайно окажется **непустым** при разборе как «очная форма» — guard
не сработает, а в базу уедет мусор. Поэтому чинить надо здесь.

## Что сделать

Проверять смысл раньше расширения:

```python
if "замен" in name:
    result.zameny = url
elif "заоч" in name:
    result.zaochnoe = url
elif "звон" in url.lower() or "понед" in name or "стандарт" in name:
    if "понед" in name:
        result.bells_monday = url
    elif "стандарт" in name:
        result.bells_standard = url
elif name.endswith(".xlsx"):
    result.ochoe = url
```

Заметить: «очная форма» — единственное имя, у которого нет
смыслового маркера, кроме слова «очная». Надёжнее опираться на него:

```python
elif "очная" in name and name.endswith(".xlsx"):
    result.ochoe = url
```

Тогда `.xlsx` сам по себе перестаёт быть признаком.

## Как проверить

```python
def test_links_semantic_before_extension():
    """Листок замен в .xlsx не должен становиться «очной формой»."""
    html = '<a href=".../СПО/Листок замен.xlsx">…</a>'
    links = eios.extract_links(html)
    assert links.zameny is not None
    assert links.ochoe is None        # или упадёт EiosParseError
```

Плюс тест на реальном HTML страницы (он у меня скачан) — чтобы
проверить, что все 5 ссылок по-прежнему на местах.

## Риски

- **`EiosParseError` при отсутствии `ochoe`** — это хорошо: бот
  скажет «структура изменилась» вместо тихого стирания. Но если
  колледж переименует «Очная форма.xlsx» во что-то без слова «очная»,
  бот встанет. Сейчас имя стабильно годами, так что риск приемлемый —
  и он лучше, чем молчаливое стирание.
- **Порядок `elif` для звонков** уже корректен: `понед` проверяется
  раньше `стандарт`, и оба не пересекаются.
- **`LINK_MARKER`** отсекает ссылки вуза (`timetable.ptk/СПО` против
  `timetable/`) — проверил, в `all_links` попали только 5 файлов СПО,
  файлы вуза не просочились.
