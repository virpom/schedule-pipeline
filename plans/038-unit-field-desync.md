**Приоритет:** низкий. Сейчас рассинхрон безвреден, но поле не несёт

**Трудоёмкость:** S (~4 строки, либо M на удаление поля).

## Проблема

В `users` есть колонка `unit` («college» / «vuz»), добавленная
миграцией `0004_vuz`. Задумывалась как признак подразделения. На деле
подразделение **уже закодировано в имени группы** суффиксом `@vuz`.

Провёл полный аудит — поле почти не используется.

**Запись — 2 места, оба сразу после `set_group`:**

```python
user.py:533  cb_vuz_group -> set_group(name); set_unit(user.id, "vuz")
user.py:590  cb_group     -> set_group(group); set_unit(user.id, "college")
```

**Чтение — 1 место:**

```python
user.py:754  is_vuz_user = (is_vuz(user.group) if user.group
                            else user.unit == "vuz")
```

**Не используется вовсе:**

```
poller.py:172   bells_group(user.group, user.course)
bell.py:39      bells_group(user.group, user.course)
admin.py:188    is_vuz(u.group) == is_v      <- по суффиксу, не по unit
admin.py:446    bells_group(user.group, user.course)
```

## Ветка `else` в `user.py:754` недостижима

`unit == "vuz"` пишется **только** вместе с `group`. Значит если
`group` пуст, `unit` там `"college"` по умолчанию, и выражение всегда
даёт `False`. Проверено на проде:

```
group IS NULL: 7 пользователей
   unit=college role=student x4
   unit=college role=teacher x3
```

Ни одного `unit="vuz"` с пустой группой. То есть fallback никогда не
срабатывает — он мёртв.

## Найденный рассинхрон

На проде ровно один пользователь, у которого `unit` не совпадает
с суффиксом:

```
id=6629888790  'гелька_67👼'  group='АП-25оз@vuz'  unit='college'
```

Причина: `/group` (`user.py:413`) меняет `group`, но **не трогает
`unit`**:

```python
await repo.users.set_role(user.id, "student")
await repo.users.set_group(user.id, group)
# set_unit не вызывается
```

Человек был «колледжем», ввёл `/group` с вузовской группой — группа
стала вузовской, `unit` остался колледжем.

**Сейчас это безвредно:** `user.py:754` проверяет `is_vuz(group)`
первым, и при заданной группе `unit` не читается. Звонки вуза
показываются верно.

**Станет багом, если** кто-то добавит проверку `unit` в новом месте
(например, в рассылке «только студентам вуза») — тогда один человек
попадёт не в ту выборку.

## Что сделать

**Минимально** — `/group` ставит `unit` по суффиксу, чтобы рассинхрона
не было:

```python
group = parts[1].strip().upper()
await repo.users.set_role(user.id, "student")
await repo.users.set_group(user.id, group)
await repo.users.set_unit(user.id, "vuz" if is_vuz(group) else "college")
```

**Правильно** — убрать `unit` совсем и везде использовать
`is_vuz(user.group)`. Поле дублирует то, что уже есть в имени группы,
и единственное его чтение можно свести к одной строке:

```python
is_vuz_user = is_vuz(user.group)
```

Это требует миграции `0007_drop_unit` (batch `drop_column`) и правки
трёх мест. Для одного рассинхрона на 227 человек — избыточно, но
убирает целый класс будущих ошибок.

## Проверено и признано корректным

**`admin.py:188` уже считает по суффиксу:**

```python
mine = [u for u in students if is_vuz(u.group) == is_v]
```

То есть админская статистика не зависит от `unit` — она была написана
правильно с самого начала. Это ещё один довод, что поле лишнее.

**Побочно замечено (не баг, но неточность):** та же строка считает
7 пользователей **без группы** студентами колледжа (`is_vuz(None)`
= `False`). В «Колледж — подробно» они попадают в «Студентов: N»,
хотя группы у них нет. На проде это 4 человека — на цифру не влияет,
но при росте «мёртвых» аккаунтов статистика начнёт врать. Правильнее
`if u.group and is_vuz(u.group) == is_v`.

## Риски

- **Удаление `unit` требует миграции с `batch_alter_table`** — SQLite
  не умеет `DROP COLUMN` до 3.35, alembic делает это пересозданием
  таблицы. Для 227 строк безопасно, но таблица `users` — самая
  нагруженная, и миграция пойдёт при старте.
- **`unit` может понадобиться для будущего.** Если появится третье
  подразделение (например, «магистратура» отдельно от вуза), суффикса
  `@vuz` не хватит. Но тогда и `@vuz` придётся менять — то есть это
  не аргумент за сохранение поля в текущем виде.
- **`/group` без валидации** — это план 037. Здесь речь только о
  `unit`; правки пересекаются, делать их вместе.
