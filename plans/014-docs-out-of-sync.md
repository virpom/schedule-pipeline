
Правильно: `docker exec bot-wi188f7kradbxpz2efrl7vms ...`.

## Что сделать

Порядок по убыванию вреда:

1. **`TROUBLESHOOTING.md` + `PARSING.md`** — это документы, которые
   читают **во время аварии**. Неработающие команды здесь дороже всего.
   Заменить все 15 вхождений `docker compose exec bot` →
   `docker exec bot-wi188f7kradbxpz2efrl7vms`. Либо (лучше) добавить
   в начало каждого документа:
   ```bash
   BOT=bot-wi188f7kradbxpz2efrl7vms
   docker exec $BOT python -c "..."
   ```
2. **`EDITORS.md`** — сменить статус на «реализовано», обновить схему
   (`weeks`, `para` до 8).
3. **`ROADMAP.md`** — либо переписать под текущий HEAD, либо явно
   пометить шапкой «устарел, актуален на 5f0d2ef, см. plans/».
   Второе дешевле и честнее.
4. **`README.md`** — числа тестов, статус вуза.
5. **`ARCHITECTURE.md`** — список миграций.
6. **`DEPLOYMENT.md`** — согласовать «Быстрый старт» с разделом «Прод»
   (или явно сказать, что compose — для локальной разработки).
7. **`VUZ.md`** — статус.

## Как проверить

После правок — сверка команд вживую:

```bash
# каждая команда из TROUBLESHOOTING.md должна отрабатывать
docker exec bot-wi188f7kradbxpz2efrl7vms python -c "print('ok')"
```

И проверить, что числа совпадают:

```bash
.venv/bin/python -m pytest -q | tail -1     # 183 passed
ls migrations/versions/*.py | wc -l          # 6
```

## Риски

- **Не переписать историю.** `ROADMAP.md` содержит ценные рассуждения
  о том, почему решения приняты именно так. При обновлении сохранять
  «почему», убирать только «что уже сделано».
- **`EDITORS.md` описывает проектную модель** — она может отличаться от
  реализации намеренно. Перед переписыванием схемы свериться, нет ли
  в модели того, что ещё не сделано (например, `action='add'` для замен).
