# План 042: редактор вуза не видит слоты 6–8

> **СДЕЛАНО 27.10.2026** (коммит `fc56593`).
>
> `max_para(group)` в `common/schedule.py`: 8 для `@vuz`, 6 иначе.
> `paras_kb` и `sub_slots_kb` получили параметр `last`, все шесть
> вызовов передают `last=max_para(group)`.
>
> Правка `format_bell` для колледжа (третье место из плана) не нужна:
> там ограничение намеренное — план сам это отмечает в разделе
> «Проверено и признано корректным».

**Приоритет:** средний. Сейчас оба редактора сидят на `ДП-26`
(колледж), так что дефект потенциальный — но включится в ту же минуту,
как админ выдаст права на вузовскую группу.

**Трудоёмкость:** S (~6 строк, после плана 041).

## Проблема

`paras_kb` и `sub_slots_kb` (`editor.py:110` и `:154`) перебирают
жёсткий диапазон:

```python
for p in range(1, 6):        # 1..5
```

Сетка колледжа — 6 пар, вуза — **8**. Значит для вуза редактор
показывает 5 слотов из 8.

**На проде это уже 572 пары.** Распределение `college_lesson` для
`@vuz`:

```
para=1: 343    para=5:  93
para=2: 339    para=6:  70   <- недоступно
para=3: 292    para=7: 268   <- недоступно
para=4: 216    para=8: 234   <- недоступно
```

В `base_lesson` для `@vuz` то же: `para=7` — 396 строк, `para=8` — 312.

## Как это включится

`admin.py:1204` — `_ask_group` предлагает **все** группы:

```python
base_groups = await repo.base_lessons.get_groups()
site_groups = await repo.college_lessons.get_groups()
groups = sorted(set(base_groups) | set(site_groups))
```

`base_groups` включает все 92 группы `@vuz`. То есть админ может
выдать права на `ЭК-24@vuz`, и староста увидит:

```
1) ...
2) ...
3) ...
4) ...
5) ...
[⬅️ Назад]
```

Пар 6, 7, 8 для него не существует.

## Последствия

1. **Не может отменить пару на 7-м слоте.** В вузе это самый частый
   слот (268 пар) — больше, чем на 4-м.
2. **Не может исправить пару на 8-м** (234 пары).
3. **Может создать лишнюю.** Увидев «5) — пусто» на дне, где реально
   стоит пара на 6-м, староста поставит новую на 5-й — и студент
   увидит две пары вместо одной.

## Что сделать

Верхнюю границу брать из данных, а не из константы. Минимум — 6
(колледж), максимум — из самих слотов и сетки звонков:

```python
def _last_para(slots, bell, cg) -> int:
    known = [p for (_, g, p) in bell if g == cg]
    return max([6] + [s.para for s in slots] + known)
```

Проще — передать число явно из того места, где известна группа:

```python
def paras_kb(weekday, parity, slots, prefix="ed:bs", last: int = 6):
    ...
    for p in range(1, last + 1):
```

И в вызывающем коде:

```python
last = 8 if is_vuz(group) else 6
kb = paras_kb(weekday, parity, slots, last=last)
```

Восьмёрка — не магия: `_format_bell_vuz` (`common/schedule.py:376`)
уже использует `range(1, 9)`, то есть восемь пар зашиты в сетку вуза.

**Та же правка нужна в трёх местах:**
- `editor.py:110` — `paras_kb` (список пар дня)
- `editor.py:154` — `sub_slots_kb` (список пар для замены)
- `common/schedule.py:358` — `format_bell` для колледжа

## Проверено и признано корректным

**`format_bell` для колледжа намеренно ограничен пятью парами.**
`common/schedule.py:358`:

```python
paras = [bell[(day_type, cg, p)] for p in range(1, 6) if (day_type, cg, p) in bell]
```

Хотя в сетке колледжа есть 6-я пара (`18:05–19:40`), экран «Звонки»
показывает пять. Это осознанное решение — шестая пара в колледже
редкость (на проде **ноль** групп имеют пары на 6-м слоте в
`base_lesson`). Но тогда `paras_kb` тем более не должен обещать
шестую — либо обещать, либо не обещать в обоих местах.

**У колледжа на 6-м слоте сейчас пусто.** Проверил:

```
para=5: 21 группа из 37 (пары есть)
para=6: 0 групп
```

Три строки `para=6` в `college_lesson` — осадок с 02.10 и 07.10, вне
окна материализации. То есть план 041 про шестую пару колледжа —
про потенциальную возможность, а не про текущие потери.

**Оба существующих редактора — на `ДП-26`** (`schedule_editor`: два
человека, группа колледжа). Вузовский дефект пока не сработал.

## Риски

- **Шесть строк вместо пяти в `paras_kb`** удлинит клавиатуру
  колледжа на одну кнопку. Мелочь, но надо проверить, что она не
  упирается в лимит сообщения (сейчас 6 кнопок + «Назад» = 7 строк,
  лимит Telegram — 100 кнопок).
- **`last=8` для вуза может показать пустые слоты**, если у группы
  пары только до 6-го. Косметика: «7) — пусто». Лучше считать
  `max(6, max(s.para for s in slots))` и добавлять 1–2 запаса, а не
  жёсткие 8.
- **`sub_slots_kb` с `last=8`** увеличит клавиатуру замены до 9 строк.
  Приемлемо.
