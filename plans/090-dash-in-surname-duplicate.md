# План 090: дефис и тире в фамилии — один человек в списке дважды

**Приоритет:** низкий. Не теряет данные, но список преподавателей
содержит дубль, и это единственная пара, где `teacher_base` не
справляется.

**Трудоёмкость:** S (~3 строки).

## Проблема

В `college_lesson` **три** варианта записи одного преподавателя:

```
'Мурашова-Росс А.В.'       без пробелов    26 пар
'Мурашова - Росс А.В.'     дефис U+002D     8 пар
'Мурашова – Росс А.В.'     тире U+2013      4 пар
                        -----------
                        38 пар, один человек
```

Все три — `Мурашова-Росс`.

`teacher_base` (`common/schedule.py:69`) их **не схлопывает**:

```python
head = (name or "").split(",")[0].strip()
head = re.sub(r"\s+", " ", head)
return re.sub(r"(?<=\b[А-ЯЁA-Z]\.)\s+(?=[А-ЯЁA-Z]\.)", "", head)
```

Проверил на живом коде:

```
teacher_base('Мурашова-Росс А.В.')   -> 'Мурашова-Росс А.В.'
teacher_base('Мурашова - Росс А.В.') -> 'Мурашова - Росс А.В.'
teacher_base('Мурашова – Росс А.В.') -> 'Мурашова – Росс А.В.'
все три различны
```

Значит `_clean_teacher_names` считает их **двумя разными людьми** и
выдаёт оба в списке (`get_teachers` / `get_teachers_vuz`).

## Что видит студент

В экране «Найти преподавателя» — **три** записи:

```
Мурашова-Росс А.В.
Мурашова - Росс А.В.
Мурашова – Росс А.В.
```

Выбирает любую — `teacher_matches` сравнивает только фамилию
(`ls[0].casefold() == ss[0].casefold()`), поэтому находит пары
**обоих вариантов**. То есть результат правильный, но список выглядит
как ошибка данных.

Проверил: `teacher_matches` для обеих записей возвращает `True` при
выборе любой из них — дубль безвреден, но заметен.

## Насколько это редко

Единственный такой человек во всей базе. Проверил все 3927 строк
`college_lesson` — фамилий с дефисом или тире ровно три записи, и все
три оказались им же:

```
Мурашова-Росс А.В.      (без пробелов)
Мурашова - Росс А.В.    (дефис с пробелами)
Мурашова – Росс А.В.    (тире)
```

Больше двойных фамилий нет. Это не система, а одна ячейка в файле
вуза, набранная тремя способами за разные недели.

В `base_lesson` вариантов два: `Мурашова-Росс А.В.` и
`Мурашова - Росс А.В.` — тире там не встречается.

## Что сделать

Нормализовать разделитель в `teacher_base`:

```python
head = re.sub(r"\s*[–—]\s*|\s+-\s*|\s*-\s+", "-", head)
```

Тогда все три записи дадут `Мурашова-Росс А.В.`,
`_clean_teacher_names` оставит одну.

**Побочный эффект проверен:** склейки вида `Кабышева М.И. /
Кострицына Н.А.` идут через слэш — регулярка их не заденет.
Единственные записи с дефисом, кроме Мурашовой, — `Кузьмина С.М.,
1-ая подгруппа` и `2-ая подгруппа`. Но `teacher_base` сначала режет по
запятой, поэтому до дефиса там дело не доходит: остаётся
`Кузьмина С.М.` — проверено.

## Проверено и признано корректным

**`_clean_teacher_names` работает правильно.** Проверил на реальных
данных:

```
вход:  Горпинченко В.А., Горпинченко Е.В., Ляшко, Ляшко Д.В.,
       Иванова З.Н., Иванова Н.А.
выход: Горпинченко В.А., Горпинченко Е.В., Иванова З.Н.,
       Иванова Н.А., Ляшко Д.В.
```

Настоящие однофамильцы сохранены (это верно — они разные люди),
`Ляшко` без инициалов убран в пользу `Ляшко Д.В.` (тоже верно).

**Склейки через слэш остаются отдельными записями.** `Кабышева М.И. /
Кострицына Н.А.` — это две пары в одной ячейке, и `teacher_base`
режет по запятой, а не по слэшу, так что в списке она висит как
«третий человек». Проверил, кого она находит:

```
teacher_matches('Кабышева М.И. / Кострицына Н.А.', 'Кострицына Н.А.')  -> False
teacher_matches('Кабышева М.И. / Кострицына Н.А.', 'Кабышева М.И.')     -> True
```

То есть **Кострицына не находит свою половину склейки**, а Кабышева
находит. Это асимметрично и неправильно — но это
[план 078](078-merge-loses-second-teacher.md) (склейка теряет второго
преподавателя), не дублирую.

**Однофамильцы — отдельный дефект.** Их семь пар, и они не
схлопываются намеренно (разные люди). Разбор — в
[плане 024](024-homonyms-mixed.md), там же я уточнил замер по
`college_lesson`.

## Риски

- **Правка `teacher_base` влияет на всё.** Она используется в
  `teacher_matches`, `_clean_teacher_names` и в поиске. Но замена
  `« - »` на `«-»` не может сделать две разные фамилии одинаковыми —
  только схлопнуть два написания одной.
- **Исторические данные.** `base_lesson` и `college_lesson` хранят
  оба варианта; правка не переписывает БД, только нормализует при
  чтении. Список станет короче на одну запись, пары останутся.
