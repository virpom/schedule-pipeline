> **СДЕЛАНО 27.10.2026** (коммит `9bbec0b`, миграция `0008_room_len`).
>

> а не `c+1`: «ГП-26» занимает две колонки, и после мержа «ауд»
> оказывается не соседней). `_cell_room` читает её и отбрасывает мусор.
>
> Две ловушки, найденные на настоящем файле:

>    («Геология (прак.) Иванов И.И.»), плюс стоят пометки «н.»/«ч.» и
>    «Айка»/«ЭИОС». Всё это попадало в `room`.

**Приоритет:** высокий для 3 студентов вуза — это потеря **полезных
данных**, а не косметика. В источнике 717 кабинетов и 43 ссылки на

## Что теряется

Структура листа: после каждой группы идёт колонка «ауд».

```
col0: 'День недели'
col1: 'Время'
col2: 'Время'
col3: 'ЭК-26-1'   col4: 'ауд'
col5: 'МН-26'     col6: 'ауд'
col7: 'ЭЭ-26-1'   col8: 'ауд'
...
```

Подсчёт по всем 11 листам файла:

| Содержимое колонки «ауд» | Ячеек |
|---|---|
| обычный кабинет (`М-406`, `М-411`, …) | **717** |
| ссылка на онлайн-пару (`https://teams.microsoft.com/meet/…`) | **43** |
| пусто | 2318 |

**43 ссылки на Teams** — это дистанционные пары. Студент не знает, куда
подключаться. Это самая дорогая потеря: без ссылки пару невозможно
посетить вообще.

## Почему у колледжа нет — и это нормально

У `BaseLesson` в `eios.py` поля `room` **нет вовсе**, и в файле
`Очная форма.xlsx` кабинетов тоже нет (проверено: 0 совпадений на
первых 60 строках). Колледж кабинеты не публикует — тут нечего чинить.

Поле `room` в `base_lesson` нужно вузу, и оно уже есть в схеме.

## Что сделать

**Хорошая новость:** весь путь уже готов, кроме парсера.
`sync_vuz.py:148` уже пишет `room=(lesson.room or "")[:64]`, колонка
`base_lesson.room` есть (`String(64)`), `college_lesson.room` тоже,
и `common/schedule.py:265` её выводит. Не хватает **одного места** —
`parsers/vuz.py`.

### 1. Читать колонку кабинета

`_groups` уже отбрасывает «ауд»-колонки (`if low in SERVICE or "ауд"
in low: continue`). Нужно вернуть связь «группа → колонка кабинета».

```python
def _groups(sheet: Sheet, header: int, time_col: int) -> list[tuple[int, str, int | None]]:
    """Колонки групп: (индекс колонки, имя, индекс колонки кабинета)."""
    result = []
    seen: set[str] = set()
    pending: int | None = None      # колонка группы, ждущая свой «ауд»
    for c in range(time_col + 1, sheet.ncols):
        name = sheet.text(header, c).strip()
        if "ауд" in name.lower():
            if pending is not None:
                result[-1] = (result[-1][0], result[-1][1], c)
                pending = None
            continue
        if not name or name in seen:
            continue
        seen.add(name)
        low = name.lower()
        if low in SERVICE:
            continue
        clean = re.sub(r"\s*\([\d,\s]+\)\s*$", "", name).strip()
        if clean:
            result.append((c, clean, None))
            pending = c
    return result
```

Заметить: `pending` нужен, потому что «ГП-26» занимает две колонки
(шапка `col15` и `col17`, между ними `col16` без подписи). После
мержа кабинет может оказаться не в `c+1`.

### 3. Отличить ссылку от кабинета

Ссылка на Teams не должна попадать в поле «кабинет» как есть — в
сообщении Telegram она займёт полстроки. Варианты:

**А. Минимальный:** писать `"онлайн"` вместо URL, URL отбрасывать.
Дёшево, но студент теряет ссылку.

**Б. Правильный:** добавить в `VuzLesson`/`base_lesson` поле `url`
(миграция) и выводить ссылку в конце сообщения строкой
`🔗 <a href="...">подключиться</a>`.

**В. Компромисс:** `room = "онлайн"`, а ссылку сохранять в
существующее поле `subject` нельзя — испортит расписание.

Рекомендация: **Б**, но это миграция `0007` и правка `common/schedule.py`.
Если хочется быстрее — **А** с явной записью в ROADMAP.

### 4. Осторожно с мержем и дедупликацией

`_dedupe` (строка 731) строит ключ **без `room`**:

```python
key = (lesson.group, lesson.weekday, lesson.para, lesson.parity,
       lesson.subject, lesson.teacher, lesson.weeks)
```

Пока `room` всегда пуст — это неважно. После правки две пары одного
предмета с одним преподавателем, но **в разных кабинетах**, схлопнутся
в одну. Добавить `lesson.room` в ключ.

`_merge_slot_clash` и `_merge_same_subject` склеивают пары. При склейке
кабинеты надо объединять, а не терять:

```python
if lesson.room and lesson.room not in found.room:
    found.room = f"{found.room}, {lesson.room}" if found.room else lesson.room
```

**Ещё одно место** — `sync_eios._merge_para_clash` (строка 336):

```python
room=prev.room or slot.room,
```

`teacher` и `subject` склеиваются через `" / "`, а `room` берёт только
первый. Сейчас незаметно (кабинетов нет), но после правки парсера
второй кабинет будет теряться молча. Заменить на тот же приём склейки.

## Риски

- **Мерж колонок.** «ГП-26» занимает две колонки — наивное `c + 1`
  возьмёт пустую. Нужен поиск «ближайшая колонка с подписью ауд»,
  а не арифметика.
- **Ссылки в тексте сообщения.** Telegram режет сообщения >4096
  символов; 8 пар × длинный URL — риск. Обрезать или делать
  гиперссылкой.
- **Колледж не трогать.** У него кабинетов в источнике нет; поле
  останется пустым, и это правильно.
- **Миграция при варианте Б.** `0007_room_url` + `bulk_insert` +
  `materialize`. Проверить, что старые строки не сломаются (дефолт `""`).
- **`String(64)` не хватает.** Замерено на реальных данных: длина
  ссылок Teams — от 43 до **70** символов, в среднем 61. **20 из 43**
  не влезают в `String(64)` и обрежутся до нерабочего URL. Поэтому
  вариант Б требует расширения колонки (или отдельного поля), а не
  просто проброса. Это меняет оценку трудоёмкости: не M, а M+.
