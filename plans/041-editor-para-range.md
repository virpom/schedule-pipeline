# План 041: редактор не видит 6-ю пару и не понимает спаренные пары

> **СДЕЛАНО 27.10.2026.**
>
> Проблема 1 (шестая пара) закрыта в плане 023 (`0ed4e13`) — `MAX_PARA`.
> Проблема 2 (спаренные пары) закрыта коммитом `692aa75`, см.
> [план 056](056-para-end-dead-mechanism.md).

**Приоритет:** средний. Староста может испортить расписание, не заметив
этого.

**Трудоёмкость:** M (~30 строк — `Slot`, `get_day_slots`, `materialize_day`,
`paras_kb`, `sub_slots_kb`, `preview_text`).

## Проблема 1: `paras_kb` показывает только 5 пар

`tgbot/handlers/editor.py:108`:

```python
def paras_kb(weekday: int, parity: str, slots: list[Slot], prefix: str = "ed:bs") -> InlineKeyboardMarkup:
    by_para = {s.para: s for s in slots}
    rows = []
    for p in range(1, 6):        # <- 1..5, шестая не попадает
        slot = by_para.get(p)
        ...
```

А сетка колледжа имеет **шесть** пар:

```
п6: 18:05–19:40 (в остальные дни)
п6: нет         (в понедельник)
```

Проверил прод: `bell_schedule` для колледжа — `max(para)=6`, для вуза
— `max(para)=8`. То есть шестая пара реальна, но недоступна для
правки.

**Сейчас это уже видно.** В `college_lesson` три строки на 6-м слоте:

```
2026-10-02  ЭОф-24  Общая энергетика
2026-10-02  ДОУ-24  Иностранный язык
2026-10-07  ПРф-24  Горные машины
```

Их нельзя ни отредактировать, ни отменить через редактор — в списке
пар их просто нет.

## Проблема 2: спаренные пары показываются по-разному

`college_lesson` умеет хранить пару, занимающую два слота:
`para=5, para_end=6`. Таких строк на проде **27**:

```
2026-10-02  ТЭф-25  5..6  Техническая механика
2026-10-02  СМф-24  3..4  Строительство дорог
2026-10-03  ДП-26   1..2  Организация документооборота
2026-10-06  ТЭф-24  5..6  Тех. обслуживание
...
```

`format_day` рисует **обе** пары:

```python
para_end = getattr(lesson, "para_end", None) or lesson.para
for p in range(lesson.para, para_end + 1):
    ...
```

Студент видит:

```
5) 16:20–17:55  Техническая механика
6) 18:05–19:40  Техническая механика
```

А `paras_kb` строит словарь по `slot.para` — то есть пару видит только
на 5-м слоте, а 6-й показывает пустым:

```
5) Техническая механика
6) — пусто              <- хотя это та же пара
```

**Последствие.** Староста жмёт «6) — пусто» и ставит туда новую пару.
`upsert` пишет второй слот на `para=6`, и получается наложение:
спаренная пара 5–6 плюс отдельная пара на 6. Студент увидит три строки
вместо двух.

## Что сделать

**Часть 1 — показать все пары.** Верхнюю границу брать из данных, а не
из константы:

```python
def paras_kb(weekday: int, parity: str, slots: list[Slot], prefix: str = "ed:bs") -> InlineKeyboardMarkup:
    by_para = {s.para: s for s in slots}
    last = max([6] + [s.para for s in slots])   # минимум 6, больше если есть
    rows = []
    for p in range(1, last + 1):
        ...
```

Шесть — потому что это максимум колледжа; если в данных окажется
седьмая (например, вузовская), она тоже попадёт.

**Часть 2 — показать занятость спаренной пары.** Заполнить `by_para`
по всему диапазону:

```python
by_para = {}
for s in slots:
    end = getattr(s, "para_end", None) or s.para
    for p in range(s.para, end + 1):
        by_para[p] = s
```

**Но есть тонкость: `Slot` не имеет `para_end`.** Его `__slots__`:

```python
__slots__ = ("para", "subject", "teacher", "room", "changed", "action",
             "comment", "group")
```

А `paras_kb` получает слоты из `get_day_slots`, который возвращает
`Slot`. То есть `getattr(s, "para_end", None)` всегда даст `None`, и
правка части 2 **ничего не изменит** для текущего потока.

Проблема глубже: `format_day` читает `para_end` через `getattr`, и
ведёт себя по-разному в зависимости от того, что ему передали:

```
CollegeLesson (студент, college_lesson)  -> para_end=6 -> ДВЕ строки
Slot          (редактор, get_day_slots)  -> нет поля  -> ОДНА строка
```

**Превью редактора расходится со студентом по этой же причине.**
`preview_text` (`editor.py:240`) собирает `Slot` без `para_end` и
обещает показать «ровно так, как увидят студенты» — но для спаренной
пары покажет одну строку вместо двух.

Правильное исправление — **добавить `para_end` в `Slot`** и заполнять
его в `get_day_slots` из `base_lesson`/`substitution`. Тогда:
- `paras_kb` увидит диапазон;
- `preview_text` совпадёт со студентом;
- `materialize_day` перестанет обнулять `para_end`
  (`"para_end": slot.para` → `slot.para_end`).

Это уже M, а не S: правка `Slot`, `get_day_slots`, `materialize_day`,
`paras_kb`, `sub_slots_kb`, `preview_text`.

**Часть 3 — та же правка в `sub_slots_kb`.** `editor.py:151` строит
клавиатуру замен и использует `by_para = {s.para: s for s in slots}`.
Там нужен тот же обход по диапазону, иначе для замены спаренной пары
6-й слот тоже будет выглядеть пустым.

**Часть 4 — превью совпадёт со студентом.** После появления
`para_end` в `Slot` в `preview_text` нужно передавать его явно:

```python
lessons = [Slot(s.para, s.subject, s.teacher, s.room,
                changed=s.changed, action=s.action, comment=s.comment,
                group=group, para_end=getattr(s, "para_end", None))
           for s in slots]
```

## Проверено и признано корректным

**`format_day` показывает спаренную пару правильно.** Две строки с
одинаковым предметом и разным временем — это честное отражение того,
что пара занимает два академических часа с перерывом. Так и должно
быть.

**`materialize_day` переносит `para_end` корректно:**

```python
rows.append({
    "para": slot.para,
    "para_end": slot.para,       # <- но здесь ставится slot.para!
    ...
})
```

Хотя это выглядит как потеря `para_end`, `get_day_slots` возвращает
`Slot` без `para_end` — то есть после материализации пара всегда
становится однослотовой. Строки с `para_end>para` в `college_lesson`
остались **с прошлой версии** и пересоберутся при следующем попадании
даты в окно `materialize`. Это не баг текущего кода, а осадок.

**Три строки `para=6` в `college_lesson` — тоже осадок.** Они с дат
02.10 и 07.10, которые сейчас вне окна `today..today+14`. В
`base_lesson` сейчас `max(para)=5`, в `substitution` тоже `max=5` —
то есть при пересборке этих дат шестая пара исчезла бы.

## Риски

- **`last = max([6] + ...)` покажет лишний слот**, если у группы вообще
  нет пар на 6-й. Косметика: «6) — пусто» вместо пяти строк. Не вредит,
  но можно ограничить шестёркой только для колледжа
  (`VUZ_GROUP` → 8).
- **Заполнение `by_para` по диапазону может удивить** того, кто ждёт
  ровно `len(slots)` кнопок. На практике кнопок станет меньше (две
  пары склеятся в одну) — это и есть цель.
- **Правка `paras_kb` затронет и вузовские группы**: у вуза 8 пар, а
  `range(1,6)` показывает 5. Сейчас редактор вуза тоже неполный.
