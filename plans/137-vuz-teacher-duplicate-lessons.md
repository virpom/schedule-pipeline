# План 137: преподаватель вуза видит каждую пару дважды

> **СДЕЛАНО 27.10.2026** (коммит `02bedd3`). Проверено на проде:
> Кабышева М.И., 28.10 — 7 строк из `college_lesson`, из них 4
> дублируют вузовский слой; теперь остаются 4 + колледжевые.

**Приоритет:** средний. Сейчас не видно никому (ни один преподаватель
вуза ботом не пользуется), но при первом подключении человек увидит
дубли в каждом дне.

**Трудоёмкость:** S (~6 строк).

## Проблема

`_user_lessons` (`user.py:357`) складывает **два источника**:

```python
async def _user_lessons(repo, user, date):
    if _is_teacher(user):
        college = await repo.college_lessons.get_for_teacher_date(user.teacher_name, date)
        vuz = await _vuz_teacher_day(repo, user, date)
        return sorted([*college, *vuz], key=lambda l: l.para)
```

Замысел верный: преподаватель может вести и колледж, и вуз, а данные
лежат в разных местах. Но **`college_lesson` уже содержит строки вуза** —
материализация (`sync_eios.materialize_day`) перебирает
`base_lessons.get_groups()`, а тот возвращает **все** группы, включая
`@vuz`. Проверил:

```
college_lesson: 3927 строк
  из них @vuz:  1855 (47%)
```

Значит `get_for_teacher_date` уже отдаёт пары вуза, а
`_vuz_teacher_day` добавляет их **второй раз** из `base_lesson`.

## Почему сейчас не видно

**Ни один преподаватель вуза ботом не пользуется.** Проверил:

```
users с role='teacher':  3
  6602662332  teacher_name=None          <- не настроен
  1039429314  'Молчанова Н.А.'  вузовский=False
  1037099659  'Боровик И.А.'    вузовский=False
```

Оба настроенных — преподаватели **колледжа**. У них `college_lesson`
содержит только колледжные строки, `_vuz_teacher_day` вернёт пусто,
дублей нет.

## Что сделать

Не добавлять `_vuz_teacher_day`, если `college_lesson` уже покрывает
вуз. Проверка простая:

```python
async def _user_lessons(repo, user, date):
    if _is_teacher(user):
        college = await repo.college_lessons.get_for_teacher_date(user.teacher_name, date)
        # college_lesson уже материализует группы @vuz, поэтому второй
        # источник нужен только если материализация ещё не дошла до даты.
        if not any(is_vuz(l.group) for l in college):
            vuz = await _vuz_teacher_day(repo, user, date)
            college = [*college, *vuz]
        return sorted(college, key=lambda l: l.para)
```

Либо проще: **убрать `_vuz_teacher_day` совсем**, раз материализация
покрывает вуз. Но она идёт на 14 дней вперёд — для дат за окном
`college_lesson` пуст, и `_vuz_teacher_day` остаётся единственным
источником. Значит первая проверка правильнее.

**Отдельно:** `_user_lessons_range` (`:365`) для преподавателя вообще
не зовёт `_vuz_teacher_day`:

```python
if _is_teacher(user):
    return await repo.college_lessons.get_for_teacher_range(user.teacher_name, start, end)
```

То есть неделя и день показывают **разное**: день — с дублями, неделя —
без вуза вовсе. Это надо привести к одному поведению.

## Риски

- **Дедупликация по `(para, group, subject)` может склеить разные
  группы** с одинаковым предметом. Проверять надо по группе тоже.
- **Если материализация отстала** (сайт лежал), `college_lesson` пуст
  на дальние даты, и `_vuz_teacher_day` нужен. Проверка
  `not any(is_vuz(...))` это покрывает.

> **Добивка 27.10.2026** (коммит `b9d3bb7`): ключ склейки без кабинета —
> источники расходятся именно на нём. На проде у Кабышевой 5 → 4
> пары, дублей 0; у Андреевой 3 пары, дублей 0.
