# План 058: «Неделя» — не неделя, и нет навигации по дням

**Приоритет:** низкий. Работает, но семантика вводит в заблуждение.

**Трудоёмкость:** S (~10 строк).

## Проблема 1: «🗓 Неделя» показывает скользящие 7 дней

`user.py:722`:

```python
async def _week_text(repo, user) -> str:
    start = datetime.date.today()
    end = start + datetime.timedelta(days=6)
```

Не «текущая учебная неделя» (понедельник–воскресенье), а **сегодня
плюс шесть дней**. Кнопка называется «Неделя», и студент ждёт неделю
целиком.

Проверил сегодняшний день: 26 октября 2026 — понедельник. Совпадает,
разницы не видно. Но в среду:

```
среда 28 окт -> покажет 28 окт .. 3 ноя
```

То есть вторая половина недели (пн, вт) не видна. Студент, который в
среду хочет узнать, что в понедельник, должен догадаться, что
«Неделя» — не неделя.

Два варианта:

**А. Сделать настоящую неделю** — от понедельника:

```python
start = datetime.date.today() - datetime.timedelta(days=today.weekday())
end = start + datetime.timedelta(days=6)
```

Тогда в среду видно всю неделю с понедельника, включая прошедшие дни.
Но расписание на прошедшие дни уже неактуально и займёт половину
экрана.

**Б. Переименовать кнопку** в «🗓 7 дней» — честно и бесплатно.
Студент понимает, что это скользящее окно.

Рекомендую **Б**: переименование не ломает привычку и не добавляет
мусора из прошедших дней.

## Проблема 2: с экрана недели некуда идти, кроме меню

`user.py:741`:

```python
await cb.message.edit_text(await _week_text(repo, user), reply_markup=BACK_KB)
```

`BACK_KB` — одна кнопка «⬅️ В меню».

Сначала я написал, что на экране дня навигация есть, а на неделе нет.
Проверил `_show_day` (`user.py:699`):

```python
async def _show_day(cb, repo, user, date):
    await cb.message.edit_text(await _day_text(repo, user, date), reply_markup=BACK_KB)
```

**Тоже `BACK_KB`.** То есть навигации по дням нет нигде: чтобы
переключиться с сегодня на завтра, надо выйти в меню и нажать другую
кнопку. Это два лишних нажатия на самое частое действие в боте —
студент смотрит «сегодня», потом сразу «завтра».

Сценарий: студент открыл «Неделю», увидел, что завтра контрольная,
хочет посмотреть завтра подробно — надо вернуться в меню, потом
нажать «Завтра».

Предложение — заменить `BACK_KB` на общий набор в обоих местах:

```python
NAV_KB = InlineKeyboardMarkup(inline_keyboard=[
    [InlineKeyboardButton(text="📅 Сегодня", callback_data="day:today"),
     InlineKeyboardButton(text="📅 Завтра", callback_data="day:tomorrow")],
    [InlineKeyboardButton(text="🗓 Неделя", callback_data="week")],
    [InlineKeyboardButton(text="⬅️ В меню", callback_data="menu")],
])
```

Три действия в один тап вместо двух через меню. Заменяет `BACK_KB` в
`_show_day` и `cb_week`.

Цена — один лишний ряд под текстом. При экране дня, где текста на
пол-экрана, это приемлемо.

## Проверено и снято: переполнение 4096 символов

Заподозрил, что неделя может не влезть в лимит Telegram. Замерил на
живых данных — взял три самые плотные группы:

```
СМк-25: 19 пар за неделю -> 1831 символов
ЭОф-24: 19 пар -> 1927 символов
ПСО-23: 18 пар -> 1937 символов
```

Это ~102 символа на пару. Реальный максимум на проде — `ГИ-24@vuz` с
23 парами за неделю (26.10–01.11), то есть **около 2350 символов**.

До лимита 4096 остаётся запас ~1746 символов, это ещё 17 пар.

Сломается, если у группы окажется 40+ пар за неделю — то есть 6 пар
каждый день без выходных. Сейчас максимум 5 пар в день (проверил:
`ПРк-25` и `СМк-25` по 5 на 26 октября).

Риск далёкий, но реальный: если при этом случится, Telegram вернёт
`BadRequest: message is too long`, а глобального обработчика ошибок нет
(находка 25) — студент увидит зависший экран. Стоит либо добавить
разбиение по 4000 символов, либо обрезать с пометкой. Но не срочно.

## Проверено и признано корректным

**Меню помещается на экран.** Посчитал ряды для обычного студента:

```
1. Сегодня | Завтра
2. Неделя  | История
3. Предмет | Преподаватель
4. Звонки  | Подписка
5. Настройки
6. Поддержка
```

Шесть рядов, десять кнопок. Telegram показывает примерно восемь рядов
до скролла — помещается. У редактора добавляется седьмой ряд, у
студента без группы — восьмой сверху. Тоже помещается.

Комментарий в коде это учитывает:

> Тонкие настройки (детализация звонков, режим уведомлений) убраны в
> «Настройки» — иначе меню разрастается до 8 рядов и в нём теряется
> главное действие.

Решение вынести настройки в отдельный экран — правильное.

**Кнопка «Преподаватель» скрыта у преподавателей** — проверено:
`if not _is_teacher(user)`. Комментарий объясняет: «у него нет своей
группы, и кнопка показывала пары чужой группы, которую он никогда не
выбирал». Верно.

**Студенту без группы кнопка выбора ставится первой** —
`rows.insert(0, ...)`. Комментарий: «Без идентичности остальные кнопки
только ругаются "Сначала выбери группу"». Разумно.

**`strip_unit` в меню** — суффикс `@vuz` не показывается человеку.
Проверено: `ident = strip_unit(user.group)`. Верно.

**Курс для вуза берётся из группы, а не из поля** — комментарий
объясняет: «У вуза курс зашит в номер группы (ГИ-23 → 3 курс), и
отдельное поле course остаётся от прежней группы. Без этого ГИ-23
подписывалась "1 курс"». Проверено в коде `menu_text`.

## Риски

- **Переименование кнопки** сломает привычку у тех, кто уже пользуется.
  Но «7 дней» точнее, и никто не жаловался на название.
- **Настоящая неделя (вариант А)** покажет прошедшие дни — они
  бесполезны и займут место. Если делать, то с фильтром «не раньше
  сегодня».
- **Разбиение длинного текста** потребует отправки нескольких
  сообщений вместо `edit_text` — меняет поведение экрана.
