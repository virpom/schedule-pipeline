# План 146: редактор замен показывает отменённую пару как обычную

> **СДЕЛАНО 27.10.2026** (раунд 224, коммит `59ead0a`).
> `sub_day_text` проверяет `action` раньше `changed`:
> отменённая пара рисуется «❌ отменено».

**Приоритет:** средний. Староста ставит отмену, экран её не отражает —
и он не понимает, сработало ли.

**Трудоёмкость:** S (~4 строки).

## Проблема: текст и кнопки говорят разное

Экран дня замен рисуется двумя функциями сразу. **Кнопки** различают
отмену (`editor.py:157`):

```python
if sub and sub.action == SUB_CANCEL:
    label = f"{p}) ❌ отменена"
elif sub:
    label = f"{p}) 🔄 {sub.subject[:20]}"
```

А **текст над ними** — нет (`:232`):

```python
for s in slots:
    meta = " · ".join(x for x in (s.teacher, s.room) if x)
    flag = " 🔄" if s.changed else ""
    lines.append(f"<b>{s.para})</b> {s.subject}{flag}")
```

`Slot.changed` — просто флаг «есть замена». Про `action` он не знает.

## Проверил на живой группе

`СМк-25`, 26.10. Замены в базе:

```
п1  action=add      «Тракторы и автомобили»
п2  action=replace  «Тракторы и автомобили»
п3  action=replace  «Иностранный язык»
п5  action=cancel   subject=''          <- ОТМЕНА
```

Что покажет `sub_day_text`:

```
1) Тракторы и автомобили 🔄
2) Тракторы и автомобили 🔄
3) Иностранный язык 🔄
4) История России
5) История России 🔄        <- отмена не видна
```

**Пара 5 отменена, а выглядит как обычная пара с заменой.** Кнопка
под ней при этом честно пишет «5) ❌ отменена».

То есть на одном экране два разных ответа на вопрос «что с этой парой».

## Почему это важно

Староста ставит отмену через `cb_sub_cancel`, экран перерисовывается
(`_render_sub_day`), и в тексте — по-прежнему «История России 🔄».
Человек нажимает ещё раз, чтобы убедиться. Получает то же самое.

Он не видит подтверждения, что отмена применилась.

## Сравнение с тем, как это сделано для студентов

`common/schedule.py:248` — правильная отрисовка:

```python
if getattr(lesson, "action", None) == SUB_CANCEL:
    lines.append(f"{p}) <s><b>{time_str}</b>  {lesson.subject}</s>"
                 f"  ❌ <i>отменено</i>")
    continue
```

Студент видит зачёркнутый предмет и «отменено». Староста — нет.

## Что сделать

Повторить логику `format_day` в `sub_day_text`:

```python
for s in slots:
    if getattr(s, "action", None) == SUB_CANCEL:
        lines.append(f"<b>{s.para})</b> <s>{s.subject}</s>  ❌ отменено")
        continue
    meta = " · ".join(x for x in (s.teacher, s.room) if x)
    flag = " 🔄" if s.changed else ""
    lines.append(f"<b>{s.para})</b> {s.subject}{flag}")
    if meta:
        lines.append(f"      {meta}")
```

## Что проверил и признал корректным

**`sub_slots_kb` различает отмену.** Проверил `:157-162`: три ветки —
`❌ отменена`, `🔄 предмет`, обычная. Кнопки верные, править не нужно.

**`get_day_slots` проставляет `action` правильно.** Проверил
`schedule_layer.py`: при отмене создаётся `Slot(..., changed=True,
action=SUB_CANCEL)`. Поле есть, рендер его просто не читает.

**`sub_actions_kb` показывает верные действия.** При `has_sub=True`
есть и «❌ Отменить пару», и «↩️ Снять замену» — обе ветки доступны.

**Окно дат `вчера..+6` достаточно.** Проверил: замены есть только на
24.10 (44 шт., вне окна — прошлое) и 26.10 (52 шт., в окне). Для
работы вперёд шести дней хватает: замены дают на день.

**`range(1, 6)` в `sub_slots_kb` для колледжа верен.** Проверил: во
всех будущих днях колледжа только **3 строки** с `para > 5`, и все на
прошлых датах (02.10, 07.10 — п6). Колледж учится в 5 пар.

**`group` — неиспользуемый параметр.** У `sub_dates_kb` (`:132`) и
`sub_day_text` (`:220`) он объявлен, но внутри не читается. Не дефект,
просто мусор в подписи.

## Риски

- **`Slot.action` есть не всегда.** У `Slot`, собранного вручную
  (`Slot(l.para, l.subject, ...)` в `_save_base:477`), `action=""`. Но
  `sub_day_text` получает слоты из `get_day_slots`, где поле
  заполняется — проверка `getattr(s, "action", None)` это покрывает.
- **Зачёркивание в Telegram** работает только для `<s>`, и в
  `sub_day_text` уже используется `<b>` — вложенность допустима.
