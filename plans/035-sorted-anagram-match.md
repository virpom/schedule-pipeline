# План 035: `match_group` угадывает по одной цифре

**Приоритет:** низкий. В текущих данных коллизий нет (проверил все 37
групп), но механизм ошибается на правдоподобных именах.

**Трудоёмкость:** S (~15 строк + 2 теста).

## Проблема

`parsers/eios.py:594` в `match_group`:

```python
candidates: list[tuple[float, str]] = []
for other_key, original in by_key.items():
    if sorted(key) == sorted(other_key):
        score = 1.0
    elif key in other_key or other_key in key:
        score = 0.9
    else:
        score = _similarity(key, other_key)
        if score < 0.75:
            continue
    candidates.append((score, original))
```

Две проблемы.

**1. `sorted()` сравнивает анаграмму.** Для `ЭК25` и `ЭК52` набор
символов одинаковый — обе дают `['2','5','К','Э']`. Перестановка цифр
внутри номера получает максимальную оценку `1.0`:

```
ЭК-52   -> 'ЭК-25'
ЮР-42А  -> 'ЮР-24А'
```

**2. Порог `0.75` слишком низкий для коротких имён.** Имя группы —
это 4–5 символов, из которых 2 — общий префикс факультета. Любой
`ЭК-2X` даёт с любым `ЭК-5X` ровно `0.75` (совпадают `Э`, `К` и одна
цифра из двух):

```
ЭК52 vs ЭК24 = 0.750
ЭК52 vs ЭК25 = 0.750
ЭК52 vs ЭК26 = 0.750
```

То есть **одна цифра из двух решает исход**.

## Почему это не видно сейчас

Прогнал все 37 групп колледжа попарно на анаграммы — **0 пар**.
Номера групп `22`–`26` двузначные, и перестановка даёт несуществующий
номер (`52`, `62`). В листке замен такого имени не будет.

## Что проверено и работает

`match_group` на реальных данных хорош — переписывать не надо:

- **25 из 25** групп листка замен сопоставлены, ни одной потери.
- Опечатки: `ДОУ - 25` → `ДОУ-25`, `ЭОК-26` → `ЭОк-26`,
  `ЭОф-26` → `ЭО-26ФП` (через `KNOWN_TYPOS`).
- Похожие группы не путаются: `ЮР-24А`/`ЮР-24Б`, `ЮР-25А`/`ЮР-25Б`,
  `ДОУ-24`/`ДОУ-25`, `ЭК-23`/`ЭК-24`/`ЭК-25`.
- Мусор → `None`: `ХХХ-99`, `АААА`, `ЮР`, `ЭК`.
- `ЮР-24` без суффикса при наличии `А` и `Б` → `None` (не угадывает).

## Что попробовал и отбросил

**Поднять порог до `0.80`.** Не работает: `ЭКО26`/`ЭОК26` (реальная
перестановка букв) тоже даёт `0.80`, и отсекается вместе с мусором.
Проверил:

```
порог 0.75: ЭКО26/ЭОК26 проходит=True,  ЭК52/ЭК24 проходит=True
порог 0.80: ЭКО26/ЭОК26 проходит=True,  ЭК52/ЭК24 проходит=False
порог 0.85: ЭКО26/ЭОК26 проходит=False, ЭК52/ЭК24 проходит=False
```

**Отсечь только анаграммы.** Тоже недостаточно: `ЮР42А` не анаграмма
`ЮР25А` (наборы разные), но `_similarity` даёт `0.80` — и после
отсева анаграммы-`ЮР24А` остаётся единственным кандидатом, поэтому
`ЮР-42А` → `ЮР-25А`.

## Что сделать

Сравнивать **структуру**, а не символы: буквенный префикс, номер и
суффикс по отдельности. Для имени группы это надёжнее любой
строковой метрики.

```python
_GROUP_RE = re.compile(r"^([А-ЯЁ]+)(\d+)(.*)$")


def _group_parts(name: str) -> tuple[str, str, str] | None:
    """Разложить имя группы на факультет, номер и суффикс."""
    m = _GROUP_RE.match(normalize_group(name))
    return (m.group(1), m.group(2), m.group(3)) if m else None


def match_group(name: str, known: list[str]) -> str | None:
    key = normalize_group(name)
    by_key = {normalize_group(g): g for g in known}
    if key in by_key:
        return by_key[key]

    fixed = KNOWN_TYPOS.get(key)
    if fixed and normalize_group(fixed) in by_key:
        return by_key[normalize_group(fixed)]

    want = _group_parts(key)
    if want is None:
        return None
    dept, num, suffix = want

    # Номер и суффикс должны совпасть целиком: иначе «ЭК-52» прилипнет
    # к «ЭК-25» по одной общей цифре.
    hits = [
        original
        for other, original in by_key.items()
        if (parts := _group_parts(other))
        and parts[0] == dept and parts[1] == num and parts[2] == suffix
    ]
    if len(hits) == 1:
        return hits[0]

    # Осталась только опечатка в буквах факультета («ЭОК» / «ЭКО»).
    # Номер и суффикс при этом обязаны совпадать. Для букв анаграмма —
    # как раз то, что нужно: цифр здесь уже нет, путаницы не будет.
    loose = [
        original
        for other, original in by_key.items()
        if (parts := _group_parts(other))
        and parts[1] == num and parts[2] == suffix
        and (sorted(dept) == sorted(parts[0]) or dept in parts[0] or parts[0] in dept)
    ]
    if len(loose) == 1:
        return loose[0]
    return None
```

Ключевое: **номер группы сравнивается как строка целиком**, а не
по вхождению. `ЭК52` никогда не совпадёт с `ЭК25`, потому что
`"52" != "25"`.

Заметить: в блоке `loose` `sorted()` уместен, а в исходном коде — нет.
Разница в том, **что** сравнивается: там анаграмма считалась по всему
имени (буквы **и цифры**), здесь — только по буквам факультета.

Проверил: `_similarity` на коротких префиксах ненадёжна
(`ЭКО`/`ЭОК` = `0.67` — ниже любого разумного порога), а `sorted()`
даёт верное `True`. Поэтому в `loose` — именно `sorted()`.

## Как проверить

```python
def test_transposed_digits_not_matched():
    """«ЭК-52» не должно прилипать к «ЭК-25»."""
    assert eios.match_group("ЭК-52", ["ЭК-24", "ЭК-25", "ЭК-26"]) is None

def test_letter_typo_still_matched():
    """Опечатка в буквах факультета при верном номере — находится."""
    assert eios.match_group("ЭКО-26", ["ЭОк-26"]) == "ЭОк-26"

def test_real_zameny_still_all_matched():
    """Все 25 групп реального листка замен по-прежнему находятся."""
```

Прогнать `pytest tests/test_eios_parser.py` — там есть проверки

## Риски

- **Структурный разбор не покроет экзотику.** Если появится группа без
  цифр (`ЮР-А`) или с буквой внутри номера, `_group_parts` вернёт
  `None` и группа потеряется. Тогда замена не применится и уйдёт
  `log.warning("группа из листка замен не найдена")` — это видно в
  логе, не молчание.
- **Строже = меньше угадывания.** Сейчас `match_group` иногда
  «угадывает» и попадает; после правки будет честно возвращать `None`.
  Для замены это правильнее: неверная замена хуже отсутствующей
  (студент увидит «замены нет» и спросит, а не пойдёт не туда).
- **`KNOWN_TYPOS` остаётся.** Она срабатывает **до** структурного
  разбора, так что подтверждённые опечатки (`ЭОф-26` → `ЭО-26ФП`)
  работают как раньше.
