# План 097: «вакансия» — не преподаватель, но выбирается как преподаватель

**Приоритет:** средний. Метка пустой ставки попадает в список людей, и
студент, нажавший её, **становится преподавателем** с расписанием
пустой ставки.

**Трудоёмкость:** S (~4 строки).

## Проблема

В расписании колледжа пустая ставка записана словом `вакансия` прямо в
поле преподавателя:

```
ПРф-23  27.10  пара 2  Монтаж и эксплуатация горного оборудования  вакансия
ПРк-25  28.10  пара 2  Геология                                    вакансия
ПРк-25  29.10  пара 4  Геология                                    вакансия
ПРк-25  31.10  пара 1  Геология                                    вакансия
```

Всего 8 строк в `college_lesson` и 4 в `base_lesson`.

`_clean_teacher_names` (`college_lesson.py:11`) фильтрует пустые имена
и схлопывает дубли, но **не отбрасывает не-имена**:

```python
names = {teacher_base(t) for t in raw if t and teacher_base(t)}
```

`teacher_base('вакансия')` возвращает `'вакансия'` — слово непустое,
поэтому проходит. Дальше `get_teachers` отдаёт его как преподавателя, и
`_teacher_search_kb` рисует под буквой **«В»** кнопку «вакансия».

## Что происходит при нажатии

`cb_teacher` (`user.py:629`) не проверяет, человек ли это:

```python
name = cb.data.split(":", 1)[1]
await repo.users.set_role(user.id, "teacher")       # <- без проверки
await repo.users.set_teacher_name(user.id, name)
```

`set_role` просто пишет `role='teacher'` в БД. Значит студент, нажавший
«вакансия»:

1. перестаёт быть студентом (`_is_teacher` → `True`);
2. теряет доступ к расписанию своей группы;
3. видит расписание пустой ставки — несколько пар на разных неделях.

Проверил сопоставление: `teacher_matches('вакансия', 'вакансия')` →
`True`, так что пары действительно найдутся.

**Вернуть себя обратно** можно только через «🎯 Выбрать группу» — если
студент помнит, что она была. Экран выбора роли не спрашивает
подтверждения.

## Почему это не «просто мусор в списке»

Список преподавателей — это **выбор личности**, а не просмотр. Нажатие
меняет состояние пользователя в базе. Ошибиться легко: буква «В» —
третья в алфавите, рядом с реальными фамилиями на «В».

## Что сделать

Отбросить не-имена в `_clean_teacher_names`:

```python
PLACEHOLDERS = {"вакансия", "вакант", "нет", "-", "—"}

def _clean_teacher_names(raw) -> list[str]:
    names = {teacher_base(t) for t in raw
             if t and teacher_base(t) and teacher_base(t).casefold() not in PLACEHOLDERS}
    ...
```

**Проверить регистр — оба варианта уже есть.** В базе лежат и
`'вакансия'`, и `'Вакансия'`:

```
college_lesson: 'вакансия'
base_lesson:    'Вакансия'
```

Сравнение по `casefold()` ловит оба, сравнение по `==` — только один.

**Прогнал фильтр на всех 199 именах.** Отфильтровывается ровно два
значения — `'Вакансия'` и `'вакансия'`. Ни одна настоящая фамилия не
задевается: проверил, есть ли имена, начинающиеся с этих слов — только
они сами.

## Что это чинит и чего не чинит

**Чинит:** «вакансия» исчезает из списка, нажать нельзя.

**Не чинит:** пары с пустой ставкой **остаются в расписании группы** —
студент видит «Геология, преподаватель: вакансия». И это, пожалуй,
правильно: скрывать саму пару нельзя, иначе студент не узнает, что она
есть. Метка честно говорит, что преподаватель не назначен.

**Не чинит:** `teacher_answer` (свободный поиск по фамилии) — но там
нажатие не меняет роль, только показывает пары. Если ввести
«вакансия» руками, увидишь её расписание. Это чтение, не выбор
личности, так что терпимо.

## Проверено и признано корректным

**Списки преподавателей сейчас не пусты.** `get_teachers` (колледж) —
67 имён, 21 буква; `get_teachers_vuz` — 126 имён, 24 буквы. Пустой
клавиатуры (только «Назад») на проде не бывает, хотя код это
допускает: `letters = sorted({...})` на пустом списке даст `[]`.

**Буквы у подразделений разные.** Колледж: `АБВГДЕЗИКЛМНОПРСТУФХЧ`,
вуз: `АБВГДЕЖИКЛМНОПРСТУФЦЧЭЮЯ`. Пересечение большое, но не полное —
это нормально, у вуза и колледжа разные преподаватели.

**`callback_data` влезает.** `tlet:col:В` и `teacher:вакансия` — далеко
до 64 байт.

## Риски

- **Скрыть «вакансию» — не удалить данные.** Пары останутся, поле
  `teacher` не изменится. Правка только в списке для выбора.
- **Другие метки.** Если в файле встретится `'нет'` или `'-'` в поле
  преподавателя, они попадут в список так же. Список `PLACEHOLDERS`
  стоит держать коротким и явным, а не пытаться угадать по шаблону —
  иначе можно случайно отфильтровать настоящую фамилию.
- **Уже выбравшие — проверил, таких нет.** В `users` ровно одно
  непустое `teacher_name`:

  ```
  Молчанова Н.А.
  ```

  Строк с `teacher_name LIKE '%вакан%'` — **0**. То есть дефект пока
  латентный: метка в списке висит, но никто не нажимал. Правка ничего
  не сломает задним числом.
