# План 151: `get_for_teacher` не фильтрует чётность — преподаватель видит пары чужой недели

**Приоритет:** высокий. Преподаватель вуза видит пары, которых в этот
день нет. Студенты этих групп их не видят — у них правильный фильтр.

**Трудоёмкость:** S (~2 строки).

## Проблема

`base_lesson` хранит чётность в `week_parity` (`ODD` / `EVEN` / `ANY`).
Проверил три пути чтения:

**`get_day` (`base_lesson.py:34`)** — фильтрует:

```python
.where(
    BaseLesson.group == group,
    BaseLesson.weekday == weekday,
    BaseLesson.week_parity.in_([parity, PARITY_ANY]),   # <- вот
)
```

**`get_week` (`:63`)** — фильтрует так же.

**`get_for_teacher` (`:123`)** — **не фильтрует**:

```python
query = (select(BaseLesson)
         .where(BaseLesson.group.like("%@vuz"),
                BaseLesson.teacher.like(f"%{surname}%"))
         .order_by(BaseLesson.weekday, BaseLesson.para))
if weekday is not None:
    query = query.where(BaseLesson.weekday == weekday)
# week_parity не упоминается вовсе
```

Параметр `week` есть, но применяется только к `weeks` через `_fits_week`
— это **другое поле**: список номеров недель для пар с плавающим
расписанием. До `week_parity` дело не доходит.

## Доказал на живой базе

`Плотников С.С.`, 27.10.2026 — девятая неделя вуза, **нечётная**:

```
get_for_teacher(weekday=2, week=9):
  п2 Неорганическая химия (лаб.)   parity=EVEN  ТМ-26-1@vuz   <- ЧУЖАЯ
  п4 Неорганическая химия (прак)   parity=EVEN  ТМ-26-1@vuz   <- ЧУЖАЯ
  п4 Металлургия редких металлов   parity=ANY   ТМ-23@vuz
  п5 Производство меди             parity=ANY   ТМ-23@vuz
  п7 Химия (лаб.)                  parity=ANY   ММ - 25оз@vuz
  п8 Химия                         parity=ANY   ММ - 25оз@vuz
```

А `get_day` — как материализация — для той же группы и дня:

```
  п2 Основы российской государственности  parity=ODD
  п3 Основы российской государственности  parity=ODD
```

**Две пары на п2 и п4 — из чётной недели, которой сейчас нет.**

## Как это видит человек

`_vuz_teacher_day` (`user.py:331`) зовёт `get_for_teacher` и
превращает результат в `Slot`. Дальше `format_day` печатает всё
подряд. Значит преподаватель вуза на нечётной неделе видит:

```
2) Неорганическая химия (лаб.)   ТМ-26-1
4) Неорганическая химия (прак.)  ТМ-26-1
4) Металлургия редких металлов   ТМ-23
```

Пара 4 дважды — причём первая из них идёт только на чётной неделе.

Студент `ТМ-26-1@vuz` в тот же день видит `Основы российской
государственности` на п2 и п3. У них с преподавателем **разные
расписания одного дня**.

## Масштаб

Проверил: в `base_lesson` **1340 строк с `weeks != ""`**, все `@vuz`,
и **0 строк колледжа**. То есть проблема только у вуза — и именно у
него расписание собирается из `base_lesson` напрямую.

## Почему не всплыло

Ни один из 167 преподавателей вуза ботом не пользуется. Проверил
`users`: `role='teacher'` — три человека, все колледжные
(«Молчанова Н.А.», «Боровик И.А.» и один без фамилии).

## Что сделать

Добавить фильтр по чётности. Но `get_for_teacher` не знает, какая
чётность нужна — он получает `week` (номер), а не `parity`. Два
варианта:

**Вариант A** — вычислить чётность из `week` внутри метода. У вуза
`vuz_week` возвращает номер, а `EVEN` = чётный. Тогда:

```python
if week is not None:
    parity = PARITY_EVEN if week % 2 == 0 else PARITY_ODD
    query = query.where(BaseLesson.week_parity.in_([parity, PARITY_ANY]))
```

**Вариант B** — передавать `parity` явно из `_vuz_teacher_day`, где
чётность уже известна из `vuz_week`.

Вариант A короче, но дублирует правило чётности в репозитории.
Вариант B честнее, но меняет подпись метода — проверил вызывающих:
только `_vuz_teacher_day:337`.

## Что проверил и признал корректным

**`get_day` и `get_week` фильтруют верно.** Проверил `:38` и `:67` —
обе используют `week_parity.in_([parity, PARITY_ANY])`.

**Материализация даёт правильные данные.** `college_lesson` для
`ТМ-26-1@vuz` 27.10 содержит ровно `Основы российской
государственности` п2 и п3 — без чётных пар. Значит студенты видят
верно, и `notify_new_schedule` тоже (он читает `college_lesson`).

**`_fits_week` работает.** Проверил `:11`: пустой `weeks` → `True`,
иначе проверка по списку номеров. Пары с `weeks=''` проходят всегда —
и правильно, их чётность уже отфильтрована бы в `get_day`.

**Нет слотов с ODD и EVEN одновременно.** Проверил группировкой по
`(teacher, weekday, para)`: **0 слотов**, где есть и `ODD`, и `EVEN`.
Значит фильтр не отбросит нужное.

## Риски

- **Вариант A** кладёт правило «чётный номер = чётная неделя» в
  репозиторий, хотя оно уже есть в `sync_vuz`. При смене якоря
  разъедется.
- **Фильтр уменьшит число строк** — если где-то `week_parity`
  заполнен неверно, пары пропадут. Проверил: у вуза `ODD`/`EVEN`/`ANY`
  только три значения, мусора нет.
