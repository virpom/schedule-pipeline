# План 139: преподаватель вуза получает предупреждение о сайте колледжа

> **СДЕЛАНО 27.10.2026** (коммит `4a49dbe`). Источник предупреждения
> для преподавателя выбирается по группам его пар: все `@vuz` —
> вузовский. На проде преподавателей вуза в боте пока нет, так
> что проверено тестами.

**Приоритет:** низкий-средний. Не видно никому сейчас (все 167
преподавателей вуза ботом не пользуются), но при подключении человек
получит чужую проблему.

**Трудоёмкость:** S (~4 строки).

## Проблема

`_day_text` (`user.py:657`) выбирает источник предупреждения по группе:

```python
if is_vuz(user.group):
    stale = await source_state.is_stale_vuz(repo)
    last_ok = await source_state.last_ok_vuz(repo) if stale else None
else:
    stale = await source_state.is_stale(repo)
    last_ok = await source_state.last_ok(repo) if stale else None
```

А `is_vuz` (`common/schedule.py:47`) требует строку:

```python
def is_vuz(group: str | None) -> bool:
    return bool(group) and group.endswith(VUZ_SUFFIX)
```

**У преподавателя `group = None`** — он ведёт пары, а не учится в
группе. Значит `is_vuz(None)` → `False` → ветка колледжа.

## Что видит преподаватель вуза

Отрисовал `_day_text` для `Плотников С.С.` на 27.10:

```
📅 Вторник, 27 октября

2) 10:20–11:05 / 🍽 11:30–11:55 / 11:15–11:50  Неорганическая химия (лаб.)
ТМ-26-1
4) 13:50–14:35 / 14:45–15:20  Металлургия редких металлов (лек.)
ТМ-23
...
```

Плюс в конце:

```
⚠️ Сайт колледжа не отвечает с 26.10 15:48. Замены с тех пор не
проверены — они могли появиться.
```

Проверил программно: `"не отвечает" in txt` → `True`,
`"колледж" in txt.lower()` → `True`.

**Преподаватель вуза получает предупреждение про сайт колледжа**,
хотя его расписание приходит из другого источника (`norvuz.ru`), и
последняя успешная синхронизация вуза — 26.10 21:57, то есть свежая.

## Почему так вышло

Замысел верный: у вуза свой источник, и общий флаг показывал студенту
вуза чужую проблему. Комментарий прямо это объясняет:

```python
# У вуза свой источник: сайт колледжа может лежать, а расписание вуза
# при этом свежее. Общий флаг показывал студенту вуза чужую проблему.
```

Но проверка идёт по `user.group`, а у преподавателя его нет. Ветка
выбирается **не по тому признаку**.

## Как правильно определить «это вуз»

Преподаватель вуза — тот, чьи пары лежат в группах `@vuz`. Это уже
известно после `_user_lessons`:

```python
lessons = await _user_lessons(repo, user, date)
is_vuz_user = is_vuz(user.group) or any(is_vuz(l.group) for l in lessons)
```

Порядок важен: `_user_lessons` надо вызвать **до** выбора источника,
а сейчас он вызывается на строке выше — то есть данные уже есть.

## Масштаб

```
преподавателей вуза в base_lesson: 167
преподавателей вуза в боте:        0
```

Дефект латентный. Оба настроенных преподавателя (`Молчанова`,
`Боровик`) — из колледжа, у них `is_vuz(None)` даёт `False`, что
**случайно верно**.

## Что сделать

```python
lessons = await _user_lessons(repo, user, date)
vuz_user = is_vuz(user.group) or any(is_vuz(getattr(l, "group", "")) for l in lessons)
if vuz_user:
    stale = await source_state.is_stale_vuz(repo)
    ...
```

**Осторожно:** `Slot` из `_vuz_teacher_day` содержит `group`, а
`CollegeLesson` тоже. У обоих поле есть, `getattr` можно опустить.

## Что проверил и признал корректным

**`meta` в `notify_new_schedule` не перевёрнут.** Заподозрил
`meta="group" if is_teacher else "teacher"` (`poller.py:208`) —
выглядит как инверсия. Проверил `format_day:257`:

```python
if meta == "group":
    names = ", ".join(strip_unit(g) for g in raw_group.split(", "))
    m = " · ".join(x for x in (names, lesson.room) if x)
else:
    m = " · ".join(x for x in (lesson.teacher, lesson.room) if x)
```

`meta="group"` показывает **группу**, иначе — преподавателя. Для
преподавателя нужна группа (он знает, кого ведёт), для студента —
преподаватель. Логика верная, инверсии нет.

**`_send_preview` не теряет звонки вуза.** Заподозрил, что
`admin.py:416` вызывает `format_day` без `group_course_group`, и для
группы вуза подставятся звонки колледжа. Проверил на `АП-26@vuz`:
результат **идентичен** вызову с явным `gcg`. `format_day` сам зовёт
`course_group_from_group`, а тот для `@vuz` возвращает `VUZ`. Дефекта
нет.

## Риски

- **`_user_lessons` может вернуть пусто** (нет пар вообще). Тогда
  `any(...)` по пустому списку даст `False`, и преподаватель вуза без
  пар в этот день получит предупреждение колледжа. Это лучше, чем
  сейчас, но не идеально — надёжнее проверять принадлежность по
  `base_lesson`, а не по дню.
