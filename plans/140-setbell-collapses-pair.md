# План 140: `/setbell` схлопывает пару и принимает время назад

> **СДЕЛАНО 27.10.2026** (коммит `2d1dd3c`, вместе с планом 045).
>
> Тот же дефект, что в 045: `upsert` принимал только `start` и `end`,
> `h1_end`/`h2_start` выставлялись в `end`. Теперь сигнатура принимает
> перерыв, а команда — необязательный третий отрезок
> (`10:45-11:30-11:55-12:40`).
>
> Вторая половина плана (время назад) закрыта ещё в 027: проверка
> `start >= end`.

**Приоритет:** средний. Команда админская (пользуется один человек),
но портит данные молча: сетка звонков общая для всех.

**Трудоёмкость:** S (~10 строк).

## Проблема 1: пара схлопывается в один интервал

Модель `BellSchedule` хранит **четыре** времени на пару:

```
start, h1_end, h2_start, end
```

Потому что пара — это два академических часа с перерывом:

```
1 пара:  09:00–09:45  /  09:50–10:35
         start h1_end     h2_start end
```

А команда `/setbell` (`admin.py:702`) принимает **два**:

```
/setbell DAY_TYPE COURSE_GROUP PARA HH:MM-HH:MM
```

И `upsert` (`bell_schedule.py:62`) заполняет недостающие поля тем же
значением:

```python
.values(
    start=start,
    h1_end=end,      # <- конец пары вместо конца 1-го академчаса
    h2_start=end,    # <- тоже
    end=end,
)
```

## Что произойдёт при вызове

```
/setbell OTHER I_IV 1 09:00-10:35
```

Запишется:

```
start=09:00, h1_end=10:35, h2_start=10:35, end=10:35
```

А должно быть:

```
start=09:00, h1_end=09:45, h2_start=09:50, end=10:35
```

## Два следствия

**1. Экран покажет пару одним куском.** `_para_full`
(`common/schedule.py:157`):

```python
if bs.h1_end == bs.h2_start:
    return f"{bs.start:%H:%M}–{bs.end:%H:%M}"
```

Раз `h1_end == h2_start == 10:35`, вернётся `09:00–10:35` вместо
`09:00–09:45 / 09:50–10:35`. Перерыв внутри пары исчезает.

**2. Перемена внутри пары не придёт.** `bell.py:63`:

```python
if user.bell_mode == BELL_FULL and bp.h1_end != bp.h2_start:
```

Условие `h1_end != h2_start` — **False**, напоминание «Перемена» и
«Перемена закончилась» не отправится. У кого `bell_mode='full'`
(проверил: 5 человек), тот потеряет эти напоминания навсегда.

## Проблема 2: время назад принимается

Проверил валидацию `/setbell`:

```
day_type in {MONDAY, OTHER}         ДА
course_group in {ALL, I_IV, II_III} ДА
para -> int()                       ДА
start/end -> fromisoformat          ДА

start < end                          НЕТ
para в диапазоне 1..8                НЕТ
```

Опечатка `/setbell OTHER I_IV 2 12:40-10:45` пройдёт обе проверки:
`fromisoformat` разберёт обе строки, и запишется пара, идущая назад.

Тогда:
- `_para_full` вернёт `12:40–10:45` — на экране неверный порядок
- `bell.py` поставит события в 12:40 и 10:45, порядок сломан
- `para` можно задать `99` — строка создастся, но её никто не прочтёт

## Почему это не проявилось

Проверил текущую сетку — все 6 пар на месте, разбивка верная:

```
OTHER I_IV п1 09:00 / 09:45 / 09:50 / 10:35
OTHER I_IV п2 10:45 / 11:30 / 11:55 / 12:40
OTHER I_IV п3 12:50 / 13:35 / 13:40 / 14:25
OTHER I_IV п4 14:35 / 15:20 / 15:25 / 16:10
OTHER I_IV п5 16:20 / 17:05 / 17:10 / 17:55
OTHER I_IV п6 18:05 / 18:50 / 18:55 / 19:40
```

Никто `/setbell` не вызывал после `seed_if_empty`. Команда
зарегистрирована (17 команд), но не использовалась.

## Что сделать

**1. Принимать четыре времени.** Формат уже описан в `DEFAULT_BELL`:

```
/setbell OTHER I_IV 1 09:00-09:45 09:50-10:35
```

Разбор:

```python
parts = message.text.split()
if len(parts) != 6:  # было 5
    ...
start, h1_end = parts[4].split("-")
h2_start, end = parts[5].split("-")
```

**2. Проверять порядок:**

```python
if not (start < h1_end <= h2_start < end):
    await message.answer("Время должно идти по возрастанию: "
                         "09:00-09:45 09:50-10:35")
    return
```

**3. Проверять `para`:**

```python
if not 1 <= para <= 8:
    await message.answer("PARA от 1 до 8")
    return
```

**4. Разрешить одиночную пару** (когда перерыва нет) — тогда
`h1_end == h2_start` осмысленно, и `_para_full` вернёт один интервал.
Это законный случай, его надо поддержать, а не запрещать:

```
/setbell OTHER I_IV 0 09:00-09:20 09:20-09:20
```

## Что проверил и признал корректным

**`seed_if_empty` заполняет верно.** Сверил `DEFAULT_BELL` с живой
базой — совпадает до минуты. Все четыре времени на месте.

**`get_context` не путает поля.** Возвращает
`{(day_type, course_group, para): BellSchedule}` и
`{(day_type, course_group): BellLunch}` — оба ключа совпадают с тем,
как их ищут `format_day` и `bell.py`.

**Обеды не задеты.** `upsert` трогает только `BellSchedule`, таблицу
`BellLunch` не касается. 4 строки обеда на месте.

## Риски

- **Смена формата команды** сломает привычку, если админ её
  использовал. Проверил: `schedule_edit` = 0 строк, сетка не менялась
  с засева. Значит ломать нечего.
- **Проверка `start < h1_end <= h2_start < end`** запретит пары, где
  второй академчас короче первого. В колледже таких нет — сверил все
  22 строки `DEFAULT_BELL`.
