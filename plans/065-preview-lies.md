# План 065: превью показывает не то, что видит студент

**Приоритет:** средний. Превью — единственный способ старосте проверить
правку до того, как её увидят студенты. Если оно врёт, проверка
бесполезна.

**Трудоёмкость:** S (~6 строк).

## Проблема 1: превью всегда `detail="full"`

`editor.py:242`:

```python
def preview_text(group, date, slots, bell=None, lunches=None, course_group=None) -> str:
    """Предпросмотр ровно так, как увидят студенты."""
    ...
    return format_day(date, lessons, bell or {}, lunches or {},
                      detail="full", meta="teacher", group_course_group=gcg)
```

Докстринг обещает «ровно так, как увидят студенты». Но `detail`
зашит в `"full"`, а студент видит своё `user.bell_detail`.

Проверил распределение на проде:

```
brief ×175
lunch  ×26
full   ×26
```

То есть **201 из 227** студентов увидят не то, что показывает превью.

Превью:
```
1) 09:00–10:35  Математика · 204
   Перемена 10:35–10:45
```

Студент с `brief`:
```
1) Математика · 204
```

Данные одинаковые, но староста проверяет экран, которого ни у кого нет.
Хуже: он может решить «всё видно» и не заметить, что часть информации
не доходит.

## Проблема 2: превью строит из слоёв, а студент читает кэш

`cb_preview_day` (`editor.py:780`):

```python
slots = await get_day_slots(repo, group, date)
```

Это **слои**: `base_lesson` + `substitution`, посчитанные на лету.

Студент читает другое — `college_lesson`, материализованную таблицу
(`user.py:362`):

```python
return await repo.college_lessons.get_for_group_date(user.group, date)
```

Обычно они совпадают — `_rebuild` пересобирает после каждой правки.
Но если `_rebuild` упал (находка 9 — ошибка глотается, староста всё
равно видит «✅ Сохранено»), то:

```
превью: правильные новые данные (из слоёв)
студент: старые (из кэша)
```

Староста открывает превью, видит «всё правильно» — и не понимает,
почему студенты жалуются.

## Проблема 3: превью показывает 3 дня, студент — 7

`cb_preview` (`editor.py:763`):

```python
for delta in range(0, 3):
    d = today + datetime.timedelta(days=delta)
```

Три кнопки: сегодня, завтра, послезавтра.

Студент листает больше:

- «Сегодня»/«Завтра» — 2 дня;
- «Неделя» — 7 дней (`today..today+6`);
- материализуется 14 дней (`MATERIALIZE_DAYS = 14`).

При этом правка базы меняет **все** дни окна: `_save_base` вызывает
`_rebuild(repo)` без даты, а это `materialize()` на 14 дней.

Сценарий: сегодня понедельник. Староста правит «среда, чётная, 3 пара».
Это меняет обе среды в окне — эту и следующую через 7 дней. Превью
показывает только эту. Проверить вторую он не может.

## Что сделать

**`detail` — брать у старосты, а не зашивать.** Староста тоже
пользователь с настройкой. Передать её в `preview_text`:

```python
await cb.message.edit_text(
    preview_text(group, date, slots, bell, lunches,
                 bells_group(group, None), detail=detail),
    reply_markup=cancel_kb("ed:preview"),
)
```

`detail` взять из `user.bell_detail` — надо добавить `user: User` в
сигнатуру `cb_preview_day` (middleware инжектит).

Но точнее — **показывать два варианта**: превью должно отвечать на
вопрос «что увидит студент», а студентов 227 с разными настройками.
Разумнее взять самый частый (`brief`, 175 человек) и подписать:
«кратко, как у большинства». Или добавить переключатель.

Минимальный вариант: `detail="brief"` вместо `"full"` — тогда превью
совпадёт с тем, что видит большинство.

**Источник — читать `college_lesson`, а не слои.** Тогда превью
показывает ровно то, что лежит у студента:

```python
lessons = await repo.college_lessons.get_for_group_date(group, date)
```

Это заодно проверяет, что `_rebuild` отработал: если кэш пуст или
старый, староста увидит это в превью.

**Дней — расширить до 7**, чтобы совпадало с «Неделей»:

```python
for delta in range(0, 7):
```

Семь кнопок в столбик — многовато. Лучше по две в ряд.

## Проверено и признано корректным

**`preview_text` правильно копирует `Slot`.** Проверил:

```python
lessons = [Slot(s.para, s.subject, s.teacher, s.room,
                changed=s.changed, action=s.action, comment=s.comment,
                group=group) for s in slots]
```

Все 8 полей `Slot` (`__slots__` в `schedule_layer.py:20`) переданы.
`group` подставляется из аргумента — верно, потому что у `Slot` из
слоёв его нет.

**Комментарий объясняет, почему `meta="teacher"`:**

> под парой студент видит преподавателя и кабинет, а не свою же группу.
> Превью — взгляд студента, не преподавателя.

Верно.

**Докстринг честно описывает, что чинили раньше:**

> Раньше экран собирал текст своей рукой и расходился с реальным: не
> было времени пары (студент видит «11:10–12:45», редактор —
> «Обществознание»), другой порядок строк и не было группы. Теперь
> зовём format_day — тот же код, что и в экране дня.

Это исправление правильное — единый код рендера. Но `detail` и
источник данных остались расходиться.

**`bells_group(group, None)`** — второй аргумент `None` вместо курса.
Для колледжа это правильно: `bells_group` игнорирует `course`, когда
группа задана (проверено в раунде 20). Для вуза тоже работает, потому
что `@vuz` в группе определяет сетку звонков.

## Риски

- **Чтение `college_lesson` вместо слоёв** может показать пусто, если
  день ещё не материализован (например, дальше 14 дней). Но превью
  ограничено 3 (или 7) днями — в окне материализации.
- **`detail="brief"`** может не понравиться старосте, который хочет
  видеть подробно. Компромисс — переключатель, но это уже больше
  строк.
- **Семь кнопок дней** удлинят экран. Две в ряд — четыре ряда.
