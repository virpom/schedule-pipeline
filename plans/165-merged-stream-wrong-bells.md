# План 165: преподаватель после склейки потока видит звонки первой группы

> **СДЕЛАНО 28.10.2026.** Признак — по курсу, не по потоку: «ПРк-25, ЮР-24А» оба в II_III. На проде 6 колледжных склеек разных курсов; строка теперь предупреждает вместо тихой подмены времени.

**Приоритет:** низкий. Сейчас не видно никому: ботом пользуются двое
преподавателей, и у обоих **ноль** склеенных пар. Но механизм уже
сломан — 6 склеек в базе смешивают группы разных курсов.

**Трудоёмкость:** S (~5 строк).

## Что происходит

`format_day` (`common/schedule.py:227-229`) определяет поток звонков по
полю `group`:

```python
grp = getattr(lesson, "group", None)
cg = ((group_course_group or {}).get(grp)
      or course_group_from_group(grp) if grp else None)
lunch = lunches.get((dt, cg)) or lunches.get((dt, "I_IV"))
```

Но `merge_groups=True` вызывается **до** этого (`:219-220`):

```python
if merge_groups:
    lessons = _merge_groups(lessons)
```

А `_merge_groups` пишет в `group` список через запятую:

```python
seen.group = ", ".join(dict.fromkeys(...))     # "ТЭк-26, ТЭф-24"
```

`course_group_from_group` берёт **первые две цифры** найденные в
строке (`common/schedule.py:112`):

```python
m = re.search(r"(\d{2})", group)
```

Для `"ТЭк-26, ТЭф-24"` это `26` — курс 1, поток `I_IV`. Вторая группа
потока (`ТЭф-24`, курс 3, `II_III`) получает **чужие звонки**.

`group_course_group` не спасает: `_course_group_map`
(`user.py:371-376`) для преподавателя возвращает
`repo.users.get_group_course_map()`, а там ключи — реальные имена
групп. Склейка `"ТЭк-26, ТЭф-24"` в нём не встречается никогда.

## Чем отличаются потоки

Не мелочь — вторая половина пары и обед:

```
MONDAY п2:  I_IV  11:10–11:55 / 12:20–13:05    обед 11:55–12:20 (inside)
           II_III 11:10–11:55 / 12:00–12:45    обед 12:45–13:15 (after)

OTHER  п2:  I_IV  10:45–11:30 / 11:55–12:40    обед 11:30–11:55 (inside)
           II_III 10:45–11:30 / 11:35–12:20    обед 12:20–12:50 (after)
```

Разница до 25 минут — преподаватель приходит не к тому времени.

## Масштаб — проверил на проде

Склеек потока в `college_lesson` (группы без `@vuz`, одинаковые
`date+para+para_end+subject+teacher`): **20**. Из них с группами
**разных потоков** — **6**:

```
02.10 п1  Гулиева Н.Г.    ТЭк-26, ТЭф-24              I_IV + II_III
02.10 п2  Рамазанов Т.М.  СМ-26КП, ЮР-24Б             I_IV + II_III
05.10 п3  Ляшко Д.В.      ПРф-26, ЮР-25А, ЭК-23       I_IV + II_III
06.10 п2  Ляшко Д.В.      ЮРф-26, ДОУ-24              I_IV + II_III
06.10 п2  Рамазанов Т.М.  СМ-26КП, ЭК-24              I_IV + II_III
07.10 п3  Рамазанов Т.М.  АТ-26, ЮР-24Б               I_IV + II_III
```

Все шесть сейчас показываются бы неправильно — но показывать некому.

## Кто затронут

`merge_groups=is_teacher` передаётся только из `_fmt`
(`user.py:379-393`), а `_fmt` вызывается для пользователей с
`role='teacher'`. На проде таких **двое**:

```
1039429314  Молчанова Н.А.
1037099659  Боровик И.А.
```

У обоих склеенных пар — **ноль**. Поэтому дефект не проявляется.

**Но `/find_teacher` (`user.py:922`) склейку не делает** — там
`format_teacher_results` (`common/schedule.py:335-337`) вызывает
`format_day` без `merge_groups`. Значит студент, ищущий преподавателя,
видит каждую группу отдельной строкой и правильные звонки. Дефект
касается только преподавателей с ролью.

## Что сделать

**Считать поток по каждой группе отдельно, а не по склейке.** Внутри
цикла по `lesson` разобрать `group` обратно:

```python
raw_group = getattr(lesson, "group", "") or ""
first_group = raw_group.split(",")[0].strip() or None
cg = ((group_course_group or {}).get(first_group)
      or course_group_from_group(first_group) if first_group else None)
```

Это не идеально: поток всё равно берётся по первой группе. Но
**первая группа — та, чьи звонки `_merge_groups` и так оставляет**,
так что поведение становится осознанным, а не случайным следствием
`re.search`.

**Лучше — не склеивать группы разных потоков.** Добавить `cg` в ключ
склейки:

```python
key = (lesson.para, getattr(lesson, "para_end", None) or lesson.para,
       lesson.subject, teacher_base(lesson.teacher),
       course_group_from_group(getattr(lesson, "group", "")))
```

Тогда `ТЭк-26, ТЭф-24` останутся двумя строками, и каждая получит
свой поток. Минус: преподаватель увидит две строки вместо одной — но
это честнее, потому что звонки у них разные.

Рекомендую **второй вариант**: он убирает и эту ошибку, и
необходимость разбирать строку обратно.

## Проверено и признал корректным

**`_merge_groups` не используется для студентов.** `_fmt` передаёт
`merge_groups=is_teacher`, для студента `False`.

**`/find_teacher` не затронут.** `format_teacher_results` вызывает
`format_day` без `merge_groups`.

**Склейка по потоку сама по себе нужна.** Физкультура у шести групп —
одна пара, и преподаватель должен видеть одну строку. Второй вариант
её сохраняет: у всех шести курс одинаковый, значит и поток одинаковый.

**`course_from_group` на одиночных группах корректен** — все 129
реальных групп имеют ровно две цифры подряд (проверено в плане 164).

**Студент не затронут вообще** — его `group` всегда одна, склейки нет.

## Риски

- **Две строки вместо одной** для смешанного потока — заметное
  изменение подачи. Но сейчас эти пары всё равно показываются
  неправильно, так что хуже не станет.
- **Тест:** в `tests/test_teacher_view.py` три вызова с
  `merge_groups=True`, все с группами одного потока. Нужен случай с
  разными — ожидать две строки.
