# План 118: фильтр ручных замен вуза шире, чем нужно (плюс неверный счётчик)

**Приоритет:** низкий. Оба дефекта сейчас безвредны, но оба вводят в
заблуждение и сломаются при изменении формата.

**Трудоёмкость:** S (~3 строки).

## Дефект 1: `manual` в `replace_vuz_changes` не ограничен вузом

`replace_vuz_lessons` (`sync_vuz.py:99`) фильтрует ручные правки
правильно — только вузовские группы:

```python
manual = [
    row for (row,) in await repo.session.execute(
        select(BaseLesson).where(
            BaseLesson.source != SOURCE_VUZ,
            BaseLesson.group.like(f"%{vuz.VUZ_SUFFIX}"),   # <- ограничение
        )
    )
]
```

`replace_vuz_changes` (`sync_vuz.py:208`) — **без ограничения**:

```python
manual = [
    row for (row,) in await repo.session.execute(
        select(Substitution).where(Substitution.source != SOURCE_VUZ)
    )
]
manual_keys = {(r.date, r.group, r.para) for r in manual}
```

Значит в `manual_keys` попадают ключи **колледжных** замен
(`source='site'`). Дальше вставка вузовской замены проверяет:

```python
key = (change.date, change.group, change.para)
if key in seen or key in manual_keys:
    continue        # <- вузовская замена молча теряется
```

## Почему сейчас это безопасно

Проверил на проде: **пространства имён групп разделены суффиксом.**

```
vuz-замены:   151, все с @vuz
site-замены:   96, все без суффикса
общих групп:    0
```

Колледж пишет в `ДП-26`, вуз — в `ДП-26@vuz`. Ключи `(date, group, para)`
не пересекутся никогда, пока суффикс сохраняется.

**Но это не гарантия кода, а совпадение данных.** Если парсер вуза
когда-нибудь отдаст группу без суффикса (`strip_unit` уже есть в
`common/schedule.py` и делает именно это), ключи совпадут — и замена
вуза исчезнет молча.

## Дефект 2: обе функции возвращают не то, что записали

```python
await repo.session.commit()
return added + len(manual)
```

Это в `replace_vuz_lessons` (`:156`) и `replace_vuz_changes` (`:252`).
`added` — сколько записей вставлено, `len(manual)` — сколько **чужих**
строк нашлось в таблице. Второе к числу записанных отношения не имеет.

Сейчас безвредно: `sync_vuz.py:355` возврат игнорирует.

```python
await replace_vuz_changes(repo, parsed.changes, form)
```

А в лог пишется не возврат, а длина входа:

```python
log.info("расписание вуза (%s) обновлено: %d пар, %d замен",
         form, count, len(parsed.changes))
```

То есть даже если бы возврат был нужен, его бы не увидели. Но
следующий, кто на него посмотрит, получит число с потолка.

## Что сделать

**Правка 1** — ограничить `manual` вузовскими группами, как в
`replace_vuz_lessons`:

```python
manual = [
    row for (row,) in await repo.session.execute(
        select(Substitution).where(
            Substitution.source != SOURCE_VUZ,
            Substitution.group.like(f"%{vuz.VUZ_SUFFIX}"),
        )
    )
]
```

**Правка 2** — возвращать записанное:

```python
return added
```

в обеих функциях.

## Проверено и признано корректным

**Изоляция форм обучения работает.** Проверил: `full` — 54 группы и
135 замен, `part` — 38 групп и 16 замен, итого 151. Ни одна замена не
висит на группе вне своего справочника (`0` таких). `delete` чистит
только свою форму — правильно, и это отдельно объяснено в комментарии
(«так и случилось на первом прогоне: после второго файла осталась
только очно-заочная»).

**Ручные правки не затираются.** Обе функции выбирают `source != vuz`
и удаляют только `source = vuz`. Правки старосты (`source='manual'`)
переживут синхронизацию.

**`replace_vuz_groups` полон и корректен.** Чистит по форме, пишет
имя/факультет/курс/форму. Используется для навигации.

**`anchor_fit` и `anchor_looks_off`** вызываются после записи и логируют
`log.error` при расхождении. Это правильная проверка: даты замен должны
попадать в недели, где у группы есть пары.

## Риски

- **Правка 1 может убрать защиту от чужой формы.** Сейчас `manual`
  берёт все `source != vuz`, включая замены второй формы. Но вузовские
  замены обеих форм уже покрыты `source='vuz'` и чистятся по форме
  отдельно, так что фильтр по `@vuz` ничего не ломает.
- **Правка 2 изменит лог, если кто-то начнёт читать возврат.** Сейчас
  никто не читает. Если начнут — увидят честное число.
