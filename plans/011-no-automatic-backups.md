# План 011: автоматический бэкап базы

**Приоритет:** одиннадцатый, но это **единственная** защита от потери
всего. 227 пользователей, 2658 базовых пар, 249 замен — без резервных копий.

**Трудоёмкость:** S (~15 строк скрипта + cron).

## Что сделать

### 1. Скрипт бэкапа через `sqlite3 .backup`

Нельзя копировать файл `cp` — при активной записи копия будет битой.
Правильный способ — `VACUUM INTO` или `.backup`:

```bash
#!/usr/bin/env bash
# /home/virprom/bin/backup-schedule-db.sh
set -euo pipefail

DATA=/home/virprom/schedule-pipeline/data
DB="$DATA/database.db"
STAMP=$(date +%Y%m%d-%H%M%S)
OUT="$DATA/database.backup-$STAMP.db"

# .backup атомарен и безопасен при работающей базе
sqlite3 "$DB" ".backup '$OUT'"

# проверка целостности: битый бэкап хуже отсутствующего
if ! sqlite3 "$OUT" "PRAGMA integrity_check" | grep -q '^ok$'; then
    echo "бэкап битый: $OUT" >&2
    rm -f "$OUT"
    exit 1
fi

# оставить 14 последних
ls -1t "$DATA"/database.backup-*.db | tail -n +15 | xargs -r rm -f
```

**Проверить:** `sqlite3` установлен на хосте. Если нет — `apt install
sqlite3` или запускать через контейнер:
`docker exec <bot> python -c "..."`.

### 2. Cron

```cron
# бэкап базы расписания каждый час
17 * * * * /home/virprom/bin/backup-schedule-db.sh >> /home/virprom/logs/backup.log 2>&1
```

Час — потому что ручные правки старост невосстановимы, а их терять
не хочется. 14 копий по ~2 МБ = 28 МБ, не проблема.

### 3. Убрать мусор

`copy-test.db` — 950 КБ, создан 24.10 при отладке. Удалить после
проверки, что это не чей-то бэкап (имя говорит само за себя).

## Как проверить

```bash
# запустить вручную
/home/virprom/bin/backup-schedule-db.sh
ls -la /home/virprom/schedule-pipeline/data/*.db | tail -3

# проверить, что бэкап открывается и содержит данные
sqlite3 /home/virprom/schedule-pipeline/data/database.backup-*.db \
  "select count(*) from users; select count(*) from base_lesson;"
```

Ожидаемо: 227 и 2658.

## Риски

- **WAL (план 010).** Если включить WAL до бэкапа, `cp` станет ещё
  опаснее. `.backup` работает правильно в обоих режимах — поэтому
  порядок не важен, но `.backup` обязателен.
- **Место на диске.** 14 × 2 МБ = 28 МБ. Проверить `df -h`.
- **Не бэкапить в тот же каталог при катастрофе.** Сейчас копии лежат
  рядом с базой: если умрёт диск, умрут и копии. Минимальное улучшение —
  раз в сутки выкладывать копию в другое место (другой сервер, S3,
  локальная машина). Не входит в этот план, но записать в ROADMAP.
