# План 134: уведомление о правке врёт про отменённые пары

> **УСТАРЕЛ 27.10.2026.** `_slots_text` больше не существует: тело
> уведомления собирает `format_day` (план 040), а он отмену рисует как
> «~~зачёркнуто~~ ❌ отменено». Дефекта нет — проверено вызовом на
> слоте с `action=SUB_CANCEL`.

**Приоритет:** средний. Староста правит расписание, подписчики получают
список — и **отменённые пары выглядят в нём как обычные**.

**Трудоёмкость:** S (~8 строк).

## Проблема

`_slots_text` (`notify_edits.py:48`) рисует пары для уведомления:

```python
def _slots_text(slots: list[Slot]) -> str:
    if not slots:
        return "Занятий нет 🙌"
    lines = []
    for s in slots:
        flag = " 🔄" if s.changed else ""
        lines.append(f"<b>{s.para})</b> {s.subject}{flag}")
        meta = " · ".join(x for x in (s.teacher, s.room) if x)
        if meta:
            lines.append(f"     {meta}")
    return "\n".join(lines)
```

Про `action` здесь **нет ни слова**. А `format_day`
(`common/schedule.py:248`) — тот, что рисует обычное расписание, —
обрабатывает отмену отдельно:

```python
if getattr(lesson, "action", "") == SUB_CANCEL:
    lines.append(f"{p}) <s><b>{time_str}</b>  {lesson.subject}</s>"
                 f"  ❌ <i>отменено</i>")
    continue
```

## Проверил на живых данных

Взял группу `СМк-25` на 26.10 — у неё одна пара отменена. Вызвал
`_slots_text` напрямую:

```
<b>1)</b> Тракторы и автомобили 🔄
     Барахоев А.В. · ауд. 409
<b>2)</b> Тракторы и автомобили 🔄
     Барахоев А.В. · ауд. 409
<b>3)</b> Иностранный язык 🔄
     Гулиева Н.Г. · ауд. 409
<b>4)</b> История России
     Бацунов С.Н.
<b>5)</b> История России 🔄          <-- ЭТА ПАРА ОТМЕНЕНА
     Бацунов С.Н.
```

Пятая пара отменена — в `substitution` у неё `action='cancel'`,
`comment='НЕТ ПАРЫ'`. Но в уведомлении она выглядит **как обычная
пара**, даже со значком 🔄 (значит, ещё и «изменена»).

Тот же день через `format_day`:

```
'5) <s><b>16:45–18:20</b>  История России</s>  ❌ <i>отменено</i>'
```

**Два экрана об одном дне говорят разное.** Студент получает
уведомление «изменение в расписании», видит в списке пару 5 — и идёт
на неё. А её нет.

## Достижимость

Чтобы проявилось, нужны одновременно:

1. Правка старосты (`schedule_edit`), чтобы сработал
   `notify_group_about_edit`
2. Отменённая пара в этот день у этой группы

Проверил базу:

```
отменённых пар:        22
групп с отменами:      ДОУ-24 (4), ЭК-24 (4), ЮР-24А (4), ПРф-24 (3), ПСО-23 (3)
правок старост:        0
```

**Правок пока ноль**, поэтому дефект латентный. Но отмены есть в
пяти группах — первая же правка в любой из них покажет неверный текст.

## Второй дефект рядом: `get_groups()` внутри цикла

`snapshot_past_days` (`:61`):

```python
for delta in range(1, days_back + 1):
    date = today - datetime.timedelta(days=delta)
    if date.isoweekday() == 7:
        continue
    groups = await repo.base_lessons.get_groups()      # <- в цикле по дням
    for group in groups:
        ...
```

`get_groups()` не зависит от `date` — его надо вызвать **один раз
до цикла**. Сейчас при `days_back=3` это три лишних запроса за проход,
а проход идёт каждые 5 минут.

Замерял раньше: `snapshot_past_days` = **0.29 с**. Не критично, но
это чистая потеря.

## Третий дефект: 61% архива — вуз

`get_groups()` возвращает **все** группы из `base_lesson`, включая
`@vuz`. Проверил:

```
всего групп:  129
@vuz:          92
колледж:       37
```

И архив это подтверждает:

```
day_snapshot:  403 строки, 115 КБ
  vuz:         246 (61%)
  college:     157
```

План 120 уже показал, что архив **никто не читает** — `_hist_page`
(`user.py:765`) берёт `college_lessons`. То есть все 403 строки
пишутся впустую. А 246 из них вдвойне бессмысленны: истории вуза в
боте нет вообще, `get_dates_for_teacher` и `_hist_page` работают
только с колледжем.

Если план 120 сделают и историю починят, снимки вуза всё равно
останутся ненужными — читать их нечем.

## Что сделать

**1. Учитывать `action` в `_slots_text`:**

```python
for s in slots:
    if getattr(s, "action", "") == SUB_CANCEL:
        lines.append(f"<b>{s.para})</b> <s>{s.subject}</s>  ❌ <i>отменено</i>")
        continue
    flag = " 🔄" if s.changed else ""
    ...
```

Импорт `SUB_CANCEL` уже есть в `common/schedule.py:35` — переиспользовать,
чтобы константа не разъехалась.

**2. Вынести `get_groups()` из цикла** в `snapshot_past_days`.

**3. Фильтровать вуз** — сохранять снимки только для колледжа:

```python
groups = [g for g in await repo.base_lessons.get_groups() if not is_vuz(g)]
```

Это сразу сократит архив на 61%.

## Что проверил и признал корректным

**Текст уведомления заканчивается правильно.** Проверил `:38`:
`«Проверь расписание командой /start»` — и `start` (`user.py:397`)
действительно показывает сегодняшнее расписание. Указание верное.

**`notify_group_about_edit` не шлёт автору правки** — `:28`
`targets = [u.id for u in subscribers if u.id != author_id]`. Правильно:
староста знает, что он изменил.

**Анкор недель вуза в порядке.** Проверил `anchor_fit` на живых данных:
46 попаданий из 71 (65%), порог `anchor_looks_off` — меньше половины.
Не срабатывает, тревоги нет. Всё верно.

**`anchor_off` тоже уходит только в лог.** `poller.py:81` пишет
`logging.error` без `alerts.alert` — та же дыра, что в плане 133, но
сейчас не активна (якорь сходится). Стоит закрыть заодно.

## Риски

- **Формат `<s>` в уведомлении.** Telegram поддерживает зачёркивание
  в HTML-разметке, `format_day` им уже пользуется. Безопасно.
- **Фильтр `is_vuz` в `snapshot_past_days`** изменит число снимков —
  если план 120 сделают и история вуза понадобится, фильтр придётся
  снять. Но сейчас истории вуза нет вообще.
