# План 070: отмена пары в уведомлении старосты выглядит как правка

**Приоритет:** средний. Студент прочитает «расписание изменилось», увидит
значок 🔄 и решит, что пару перенесли. А её отменили.

**Трудоёмкость:** S (~6 строк).

## Проблема

`notify_edits.py:50`:

```python
def _slots_text(slots: list[Slot]) -> str:
    if not slots:
        return "Занятий нет 🙌"
    lines = []
    for s in slots:
        flag = " 🔄" if s.changed else ""
        lines.append(f"<b>{s.para})</b> {s.subject}{flag}")
        meta = " · ".join(x for x in (s.teacher, s.room) if x)
        if meta:
            lines.append(f"     {meta}")
    return "\n".join(lines)
```

`Slot.action` не проверяется вовсе. Отменённая пара выглядит так:

```
🔄 Изменение в расписании

📅 Понедельник, 26.10 · группа ДП-26
2) Математика 🔄
     Иванов И.И. · 204
```

Студент видит «изменилось» и 🔄. Что именно — не сказано.

## Три места показывают отмену по-разному

**Староста, который её создаёт** (`editor.py:596`):

```python
if sub.action == SUB_CANCEL:
    text += "Замена: ❌ <b>отменена</b>"
```

Явно: «отменена».

**Обычное расписание** (`common/schedule.py:249`):

```python
if getattr(lesson, "action", "") == SUB_CANCEL:
    lines.append(f"{p}) <s><b>{time_str}</b>  {lesson.subject}</s>"
                 f"  ❌ <i>отменено</i>")
    continue
```

Зачёркнуто и «❌ отменено».

**Уведомление группе** (`notify_edits.py:57`) — просто 🔄.

То есть староста нажал «❌ Пара отменена», ему ответили «❌ Пара
отменена», а группе пришло «🔄». Расхождение между тем, что сделано, и
тем, что сообщено.

## Почему это не мелочь

Староста правит расписание, чтобы группа узнала. Если сообщение не
отличает отмену от переноса, студент придёт на пару, которой нет, —
или наоборот, не придёт на перенесённую.

Причём `/start` покажет правильную картину (там `format_day` с
зачёркиванием). Но человек, прочитавший уведомление утром, может не
открыть расписание заново.

## Что сделать

Добавить ветку отмены — по образцу `format_day`:

```python
def _slots_text(slots: list[Slot]) -> str:
    if not slots:
        return "Занятий нет 🙌"
    lines = []
    for s in slots:
        if s.action == SUB_CANCEL:
            lines.append(f"<b>{s.para})</b> <s>{s.subject}</s> ❌ <i>отменено</i>")
            continue
        flag = " 🔄" if s.changed else ""
        lines.append(f"<b>{s.para})</b> {s.subject}{flag}")
        meta = " · ".join(x for x in (s.teacher, s.room) if x)
        if meta:
            lines.append(f"     {meta}")
    return "\n".join(lines)
```

Импорт уже есть в `editor.py`, в `notify_edits.py` нужен добавить:

```python
from common.schedule import SUB_CANCEL, WEEKDAY_FULL
```

Учителя и аудиторию у отменённой пары показывать не надо: в
`substitutions.set(...)` при отмене они не заполняются (передаётся
только `action`), и `Slot` получит пустые строки.

## Что рядом и остаётся как есть

**Время пар в уведомлении не показывается** — это отдельная находка,
[план 040](040-notify-no-time.md). Там же разобрано, почему
`_slots_text` не берёт `bell`.

**Пустая строка после заголовка.** Сейчас текст собирается так:

```python
body = f"📅 <b>{_fmt_day(date)}</b> · группа <b>{group}</b>\n"
body += _slots_text(slots)
```

`\n` в конце первой строки плюс начало `_slots_text` даёт одну пустую
строку — это нормально для читаемости, трогать не надо.

## Проверено и признано НЕ проблемой

Пока разбирал, проверил три подозрения в `notify_edits.py` — все
оказались корректными.

**`snapshot_past_days` вызывает `get_groups()` внутри цикла по дням.**

```python
for delta in range(1, days_back + 1):
    ...
    groups = await repo.base_lessons.get_groups()
    for group in groups:
```

Три лишних запроса вместо одного. Но функция работает раз в час, а
`get_groups()` — это `SELECT DISTINCT` по 129 строкам. Замерять нечего.

**`if not slots: continue` — день без пар не сохраняется.** Архив не
отличит «занятий не было» от «не сохранили». Но пустых учебных дней в
колледже почти не бывает (расписание шестидневное), а для пропущенных
дат запись просто не создаётся — при чтении это то же самое, что
пустой день. Не проблема.

**Архив покрывает и вуз.** В `day_snapshot` 119 групп, из них 82 с
суффиксом `@vuz`. Это не ошибка: `base_lessons.get_groups()` возвращает
все группы из `base_lesson`, а там лежат оба источника — 704 строки
колледжа и 1954 вуза.

**Пробел в истории 9–22 октября** — это не баг кода, а простой бота.
Уже разобран в [плане 039](039-snapshot-never-read.md), там же точные
цифры: `college_lesson` содержит 8 прошедших дат, `day_snapshot` — 5,
и три даты (20, 21, 22 октября) есть в архиве, но не видны в «Истории».
Отдельного плана не нужно.

## Риски

- **`SUB_CANCEL` — строка `"cancel"`.** Проверить, что импорт берёт её
  из `common/schedule` (там она переэкспортируется), а не пишется
  литералом.
- **Зачёркивание в Telegram.** `<s>` поддерживается, `format_day` уже
  его использует — значит рендерится нормально.
