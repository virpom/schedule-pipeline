# План 136: студент вуза видит обед колледжа в неверном порядке

> **УСТАРЕЛ 27.10.2026.** В коде уже стоит `if lunch is None and cg !=
> VUZ_GROUP`. Проверено на проде: АП-26@vuz 27.10 — «08:40–10:10»,
> обеда нет, время не идёт назад.

**Приоритет:** средний. Видно каждому студенту вуза, у кого есть 2-я
пара, и выглядит как сломанные часы.

**Трудоёмкость:** S (~3 строки).

## Что видит студент вуза

Взял `АП-26@vuz` на 27.10 и отрисовал через `format_day` — тот же код,
что рисует экран дня:

```
📅 Вторник, 27 октября

1) 08:40–09:25 / 09:35–10:10  Информационные технологии (лаб.)
Громов В.А.
2) 10:20–11:05 / 🍽 11:30–11:55 / 11:15–11:50  Информационные технологии (лаб.)
Громов В.А.
3) 12:10–12:55 / 13:05–13:40  Информационные технологии (лек)
Громов В.А.
```

**Вторая строка сломана.** Время идёт `11:30` → `11:15` — назад.
И «🍽 обед» у вуза, где обеда нет вообще.

## Откуда берётся

`format_day` (`common/schedule.py:233`):

```python
lunch = lunches.get((dt, cg)) or lunches.get((dt, "I_IV"))
```

Для вуза `cg = "VUZ"` (`bells_group` → `VUZ_GROUP`). В `bell_lunch`
записей `VUZ` **нет**:

```
есть обед: I_IV
есть обед: II_III
```

Значит `lunches.get((dt, "VUZ"))` → `None` → **fallback на `I_IV`** →
подставляется обед колледжа 1-4 курса.

## Почему получается неверный порядок

Звонки вуза для 2-й пары (`OTHER`, `VUZ`, para=2):

```
10:20 – 11:05  (первый академчас)
11:15 – 11:50  (второй академчас)
```

Обед колледжа (`OTHER`, `I_IV`, para=2, `position='inside'`):

```
11:30 – 11:55
```

`_para_full` вставляет обед **внутрь** второго академчаса:

```python
inline = lunch if (lunch and lunch.position == "inside" and lunch.para == p) else None
```

Для колледжа это верно: его 2-я пара идёт `10:45–11:30` + `11:55–12:40`,
и обед ровно между ними:

```
2) 10:45–11:30 / 🍽 11:30–11:55 / 11:55–12:40   <- порядок верный
```

Для вуза 11:30 попадает **в середину** `11:15–11:50` — порядок ломается.

## Масштаб

Проверил 8 групп вуза на 27.10 — у **2** есть 2-я пара, значит обе
показывают сломанную строку. Всего групп вуза 92; у кого есть вторая
пара в расписании, тот это видит.

Колледж не затронут — у него `I_IV`/`II_III` есть в `bell_lunch`,
fallback не срабатывает.

## Что сделать

Не подставлять чужой обед. Fallback нужен только для колледжа, где
`cg` бывает `None` (преподаватель без группы). Для вуза — обед не
предусмотрен:

```python
lunch = lunches.get((dt, cg)) or (None if cg == VUZ_GROUP else lunches.get((dt, "I_IV")))
```

Или чище — вынести в помощник, потому что тот же fallback повторяется
в `bell.py` (`:58`, `:84`) и `format_bell`.

## Что проверил и признал корректным

**Обеда у вуза нет и не должно быть.** Проверил оба `.xls` файла вуза
на слово «обед» — **0 совпадений**. Миграция `0004_vuz:29` задаёт
8 пар подряд без перерыва:

```
1: 08:40–10:10   5: 15:30–17:00
2: 10:20–11:50   6: 17:10–18:40
3: 12:10–13:40   7: 18:50–20:20
4: 13:50–15:20   8: 20:30–22:00
```

Значит сетка вуза полная, обед не потерян.

**Звонки работают.** Проверил `bell_reminder` за сегодня: **119
напоминаний**, ключи симметричны (`s:3 x12`, `e:3 x12`), дублей нет.

**`_tick` быстрый.** Замерил: **0.04 с** на 16 подписчиков. Порог
пропуска минуты — 60 с, запас 1608x. Тревога из плана 123 п.6
(«`t != now_min` пропустит минуту») **не подтвердилась**.

**Часовой пояс верный.** `TZ=Asia/Krasnoyarsk` в контейнере,
`datetime.now()` даёт `+07`. Звонки срабатывают в нужное время.

**`_format_bell_vuz:386` — мёртвый код.** Ищет
`lunches.get(("MONDAY", VUZ_GROUP))`, которого нет никогда. Безвредно,
но стоит убрать вместе с правкой.

## Риски

- **`VUZ_GROUP` придётся импортировать в `common/schedule.py`** — он
  там уже определён (`:44`), циклического импорта не будет.
- **Убрать fallback для вуза целиком** — если вуз когда-нибудь введёт
  обед, его надо будет завести в `bell_lunch` отдельной строкой, а не
  наследовать колледжный. Это правильнее, чем текущее поведение.
