# План 154: правка слота вуза через редактор создаёт дубль вместо обновления

> **СДЕЛАНО 27.10.2026** (коммит `c513256`).
>
> `_save_base` берёт `weeks` из правимой строки, удаление тоже, откат
> восстанавливает `weeks` из журнала (новое поле в `new_value`).
>
> Уточнение по проду на 27.10: редакторы есть **только у ДП-26**
> (колледж), вузовских нет — дефект латентный, но включается в ту же
> минуту, как админ выдаст права на группу `@vuz`. Строк с непустым
> `weeks` на проде 1340 из 1971.
>
> Случай «у слота несколько строк» не делал: плана на выбор строки нет,
> а редактор их сейчас и не показывает — он берёт первую через
> `next()`. При появлении вузовского редактора это надо решать
> отдельно.

**Приоритет:** средний. Сейчас не видно (редактор вуза не открывается —
план 143), но включится в ту же минуту, как админ выдаст права.

**Трудоёмкость:** S (~8 строк).

## Проблема

`upsert` (`base_lesson.py:74`) ключуется по пяти полям:

```python
.on_conflict_do_update(
    index_elements=["group", "week_parity", "weekday", "para", "weeks"],
    ...
)
```

а `weeks` по умолчанию пустой:

```python
async def upsert(self, group, parity, weekday, para, subject, teacher="",
                 room="", source="manual", updated_by=None, weeks: str = "") -> None:
```

У колледжа `weeks` всегда пусто — совпадает с дефолтом, всё работает.
**У вуза 69% строк имеют непустой `weeks`:**

```
base_lesson @vuz: 1956 строк
  с weeks != "":  1340 (69%)
уникальных слотов (group, weekday, parity, para) с непустым weeks: 804
```

Значит `upsert(..., weeks="")` ищет строку `(group, parity, weekday,
para, "")`, **не находит её** и делает `INSERT`.

## Симуляция на копии прод-базы

`АП-25оз@vuz`, вторник, `parity=ANY`, `week=9`. До правки:

```
п7 Компьютерное моделирование, ч.1 (лек.)  weeks='9,10,11,12'
п8 Компьютерное моделирование (прак.)      weeks='9,10,11,12,13'
```

Вызываю `upsert(g, ANY, 2, 7, 'ИСПРАВЛЕННЫЙ ПРЕДМЕТ', ..., weeks="")`.
После:

```
п7 ИСПРАВЛЕННЫЙ ПРЕДМЕТ                    weeks=''          <- НОВАЯ
п7 Компьютерное моделирование, ч.1 (лек.)  weeks='9,10,11,12' <- СТАРАЯ
п8 Компьютерное моделирование (прак.)      weeks='9,10,11,12,13'
```

**Пара 7 теперь дважды.** И новая строка видна **на всех неделях
сразу**, потому что `_fits_week` (`:17`) для пустого `weeks` возвращает
`True`:

```python
def _fits_week(lesson, week):
    raw = (lesson.weeks or "").strip()
    if not raw:
        return True          # <- пусто = идёт всегда
```

Проверил `week=13` — там тоже появился «ИСПРАВЛЕННЫЙ ПРЕДМЕТ», хотя
старая строка для этой недели своя.

## Что видит студент

Пара 7 **дважды**: один раз исправленная (все недели), один раз
исходная (свои недели). `format_day` печатает обе.

## Что видит староста

`✅ Сохранено` — и всё. О дубле не сказано. При следующей правке
`get_day` без `week` вернёт уже больше строк, и `cb_base_slot` покажет
ещё более случайный вариант.

## `delete_slot` — та же причина, но другой симптом

```python
async def delete_slot(self, group, parity, weekday, para, weeks: str = ""):
    ... BaseLesson.weeks == weeks   # == ""
```

Проверил на копии: `delete_slot(g, ANY, 2, 8)` для строки с
`weeks='9,10,11,12,13'` **не удаляет ничего**. Строк было 3, стало 3.

План 143 это уже описал. Здесь — родственный дефект в `upsert`,
которого там нет.

## Почему колледж не страдает

Проверил: у всех **704 колледжных строк** `weeks = ""`. Дефолт совпадает,
`on_conflict` попадает в существующую строку, обновление работает.

## Что сделать

`upsert` и `delete_slot` должны принимать `weeks` явно, а вызывающий
код — знать, какие строки правит.

**Для редактора вуза** минимально: при правке слота, у которого есть
ровно одна строка, передавать её `weeks`:

```python
old = await repo.base_lessons.get_day(group, weekday, parity)
candidates = [l for l in old if l.para == para]
weeks = candidates[0].weeks if len(candidates) == 1 else ""
await repo.base_lessons.upsert(group, parity, weekday, para, subject,
                               teacher, room, weeks=weeks, ...)
```

**Для случая нескольких строк** (как у `АП-25оз@vuz` п7 — четыре
варианта) — сначала показать их старосте и дать выбрать, какую менять.
Иначе любая автоматика угадает неверно.

## Что проверил и признал корректным

**`on_conflict_do_update` сам по себе работает.** Проверил: у колледжа
дублей нет, `(group, week_parity, weekday, para, weeks)` — уникальный
индекс, попадание точное.

**`_fits_week` работает верно для своей задачи.** Пустой `weeks` →
`True` — это правильно: строка без списка недель идёт каждую неделю.
Проблема не в нём, а в том, что `upsert` создаёт такую строку там, где
не надо.

**Слотов, где уже есть и `""` и непустое, всего 1.** Значит в 803
случаях из 804 правка создаст дубль, а не обновит.

**План 143 покрывает `delete_slot`**, но про `upsert` там только
упоминание в контексте отката (`:89`, `:132`) — самого дефекта с
`weeks=""` нет.

**План 042 покрывает диапазон кнопок** (`paras_kb` → 5 пар), это
отдельно.

## Риски

- **Передавать `weeks` из найденной строки** — если у слота несколько
  строк, выбор первой произволен. Нужен явный выбор пользователя.
- **`upsert` вызывается ещё из `cb_undo`** (`editor.py:854`) — там та же
  проблема, и её надо решать вместе.
