# План 107: поиск по фамилии смешивает однофамильцев

**Приоритет:** высокий для затронутых преподавателей. Семь человек видят
чужие пары, и не знают об этом.

**Трудоёмкость:** S (~5 строк + тест).

## Проблема

`teacher_matches` (`common/schedule.py:86`) сравнивает **только первое
слово**:

```python
lb = teacher_base(lesson_teacher)
if lb == selected_name:
    return True
ls = lb.split()
ss = selected_name.split()
if not ls or not ss:
    return False
# Сравниваем первые слова (фамилии) без учёта регистра. Инициалы
# могут быть записаны по-разному или отсутствовать.
return ls[0].casefold() == ss[0].casefold()
```

Логика задумана верно: в файлах встречается «Коленова В.А.» и
«Коленова В. А.», и человек ищет просто «Коленова». Но побочный эффект —
**любые два человека с одной фамилией неразличимы**.

## Что это даёт на проде

Проверил все 234 преподавателя в `college_lesson` 26.10.2026. Нашёл 24
группы однофамильцев. Большинство — варианты написания одного человека
(«Воробьев М.С» и «Воробьев М.С.»), они безвредны. Но **семь пар — это
разные люди с собственными парами**:

```
Горпинченко В.А.   9 пар   |  Горпинченко Е.В.  18 пар
Гулиева Н.Г.      53 пары  |  Гулиева Н.Н.       3 пары
Демченко И.В.     40 пар   |  Демченко О.Н.     12 пар
Золотухина Н.А.    1 пара  |  Золотухина Н.Е.   20 пар
Иванова З.Н.      22 пары  |  Иванова Н.А.      22 пары
Кабышева М.И.     44 пары  |  Кабышева Н.А.      2 пары
Чабаева А.В.       1 пара  |  Чабаева А.Д.      57 пар
```

`teacher_matches` возвращает `True` для **всех семи пар** — проверил
вызовом на каждой.

Прогнал исправленную логику против живого `get_for_teacher_date` на
26.10.2026. Затронуто 11 преподавателей — каждый получает ровно свои
пары:

**Ноль — это правильно.** Проверил: у `Чабаева А.В.` на 26.10 в базе
вообще нет своих пар, обе строки принадлежат `Чабаева А.Д.`. То же у

Раньше они видели чужое расписание и считали его своим.

**Рефлексивность проверена отдельно:** `teacher_matches(x, x)` даёт
`True` для всех 32 вариантов написания с прода — значит никто не
теряет собственные пары.

## Что видит человек

Самый резкий случай — `Чабаева А.В.` с одной парой. Она ищет себя и
получает **все 57 пар `Чабаева А.Д.`** плюс свою одну. Различить их в
списке невозможно: обе подписаны «Чабаева А.В.» / «Чабаева А.Д.», а
фильтр уже отсёк всё остальное.

То же с `Золотухина Н.А.` (1 пара): получает 20 чужих.

**Преподаватель не может понять, что что-то не так.** Он видит пары,
подписанные чужой фамилией с другими инициалами, но думает, что это
опечатка в расписании, а не ошибка поиска.

## Что сделать

Если у выбранного имени есть инициалы — сравнивать их. Если нет
(человек ищет просто «Коленова») — оставить широкое совпадение.

```python
def teacher_matches(lesson_teacher: str, selected_name: str) -> bool:
    lb = teacher_base(lesson_teacher)
    if lb == selected_name:
        return True
    ls = lb.split()
    ss = selected_name.split()
    if not ls or not ss:
        return False
    if ls[0].casefold() != ss[0].casefold():
        return False
    # Фамилия совпала. Если у обеих сторон есть инициалы — сверяем те,
    # что есть у обеих: «Чабаева А.В.» не должна находить пары
    # «Чабаева А.Д.», но «Городиский В.» и «Городиский В.В.» — один
    # человек, у которого во втором файле потерялся инициал.
    li = [c.casefold() for c in re.findall(r"[А-ЯЁA-Z]", " ".join(ls[1:]))]
    si = [c.casefold() for c in re.findall(r"[А-ЯЁA-Z]", " ".join(ss[1:]))]
    if not li or not si:
        return True          # ищем по фамилии — так и задумано
    n = min(len(li), len(si))
    return li[:n] == si[:n]
```

**Проверил обе крайности на живых данных — все 15 случаев верны:**

```
разные люди -> False
  Чабаева А.Д.     vs Чабаева А.В.      False
  Золотухина Н.Е.  vs Золотухина Н.А.   False
  Гулиева Н.Г.     vs Гулиева Н.Н.      False
  Иванова З.Н.     vs Иванова Н.А.      False
  Демченко И.В.    vs Демченко О.Н.     False
  Кабышева М.И.    vs Кабышева Н.А.     False
  Горпинченко В.А. vs Горпинченко Е.В.  False

один человек / варианты -> True
  Городиский В.    vs Городиский В.В.   True
  Воробьев М.С     vs Воробьев М.С.     True
  Кокошка И. П.    vs Кокошка И.П.      True
  Кулян Р.А        vs Кулян Р.А.        True
  Коленова В.А.    vs Коленова          True
  Ляшко Д.В.       vs Ляшко             True
  Иванова З.Н      vs Иванова З.Н.      True
  Сачук Ю.Н.       vs Сачук             True
```

**Почему не «сравнить первый инициал».** Пробовал — ломается на
`Городиский В.` vs `В.В.` (один человек, второй инициал потерян в
источнике). Почему не «сравнить всю строку» — ломается на
`Воробьев М.С` без точки. Работает только сравнение по **общим**
инициалам: сколько есть у обеих сторон, столько и сверяем.

## Проверено и признано корректным

**Все 129 групп разбираются в верный курс.** Прогнал
`course_from_group` по каждой группе из `college_lesson` и сверил с
ожидаемым по году приёма: **0 расхождений**. `ДП-26` → 1 курс,
`ДП-23` → 4, `ГИ-21@vuz` → 4 (обрезано по `min(...,4)`), `ДП-27` → 1
(приём в будущем, `max(1,...)`).

**Варианты написания одного человека не ломаются.** `teacher_base`
(`schedule.py:72`) убирает пробел внутри инициалов:
«Кокошка И. П.» и «Кокошка И.П.» дают одну строку. Проверил — работает.

**`_merge_groups` не задет.** Она склеивает пары по
`teacher_base(lesson.teacher)`, то есть по полному имени с инициалами,
а не по фамилии. Однофамильцы там не смешиваются.

**`get_teachers` отдаёт полные имена.** Человек выбирает
«Чабаева А.Д.» из списка, инициалы у выбранного имени есть — значит
новый фильтр сработает. Если бы список отдавал только фамилии, правка
была бы бесполезна; проверил `repo.college_lessons.get_teachers` — там
`distinct teacher`, полные строки.

**`'вакансия'`/`'Вакансия'` — не однофамильцы.** Два написания одного
служебного слова. Новый фильтр их разведёт (у обоих нет инициалов, значит
`len(ss) == 1`, широкий поиск сохранится). Не регресс.

## Риски

- **Сменился формат инициалов.** Если источник начнёт писать «Чабаева
  А. Д.» с пробелом, `teacher_base` его схлопнет — проверено, работает.
- **Инициалы только у одной стороны.** Например, в паре «Ляшко» без
  инициалов, а человек выбрал «Ляшко Д.В.». Тогда `len(ls) == 1`,
  сработает широкий поиск — вернёт пары обоих. Это компромисс: лучше
  показать лишнее, чем ничего.
- **Тест.** В `tests/` есть проверки `teacher_matches`, но пары
  однофамильцев там нет. Стоит добавить четыре проверки из блоков выше:
  две на «разные люди → False» и две на «варианты → True».
