# План 130: без группы пользователь видит «Занятий нет 🙌»

**Приоритет:** низкий по масштабу (4 человека), но сообщение **ложное**
и выглядит как поломка расписания, а не как «выбери группу».

**Трудоёмкость:** S (~6 строк).

## Проблема

`_day_text` (`user.py:647`) не проверяет, есть ли у пользователя
группа или имя преподавателя. Он сразу идёт за парами:

```python
async def _day_text(repo, user, date) -> str:
    bell, lunches = await repo.bell_schedule.get_context()
    gcg = await _course_group_map(repo, user)
    lessons = await _user_lessons(repo, user, date)
```

`_user_lessons` (`:357`) для студента делает:

```python
return await repo.college_lessons.get_for_group_date(user.group, date)
```

При `user.group is None` запрос вернёт **пустой список** — в таблице нет
строк с `group IS NULL`. Дальше срабатывает ветка «пар нет»:

```python
else:
    ...
    elif published:
        text = format_no_lessons(date)
```

## Что видит человек — проверил на проде

Взял реального пользователя `7749685971` (`@Ural_Phantom`, группа не
выбрана) и вызвал `_day_text` напрямую:

```
📅 Понедельник, 26 октября

Занятий нет 🙌

⚠️ Сайт колледжа не отвечает с 26.10 15:48. Замены с тех пор
не проверены — они могли появиться.
```

**Три неверных утверждения сразу:**

1. «Занятий нет» — он их не видит, потому что **не выбрал группу**,
   а не потому что их нет.
2. Эмодзи 🙌 подразумевает «отдыхай», хотя человек, скорее всего,
   застрял в середине настройки.
3. Предупреждение про сайт добавляет ложную тревогу к ложному выводу.

При этом меню честное:

```
🎓 Расписание ПТК

Группа не выбрана.

Выбери её, чтобы видеть расписание 👇
```

То есть `_render_menu` знает правду, а `_day_text` — нет.

## Второй случай того же дефекта

Пользователь `6602662332` (`@mourvane`): `role='teacher'`, но
`teacher_name=None`. Проверил:

```
_is_teacher   = True      (role == "teacher")
_has_identity = False     (bool(teacher_name) -> False)
```

`_user_lessons` идёт в ветку преподавателя:

```python
college = await repo.college_lessons.get_for_teacher_date(user.teacher_name, date)
```

`get_for_teacher_date` (`college_lesson.py:166`) имеет защиту от пустого
имени:

```python
if not (teacher_name or "").strip():
    return []
```

Защита работает, но результат тот же — пустой список → **«Занятий
нет 🙌»**.

## Кто затронут

```
users с group IS NULL и teacher_name IS NULL:  4
из них активных за последнюю неделю:           2
```

Мало, но:

- **`get_or_create_user` ставит `subscribed=True` при создании**
  (`user.py:47`), ещё до выбора группы. Значит каждый новый человек
  на секунду попадает в это состояние.
- **Двое активны** — они вернутся и снова увидят ложь.
- **Состояние достижимо в любой момент**: `/role_switch`
  (`user.py:449`) сбрасывает группу и имя, но не отписывает.

## Что сделать

Ранний выход в `_day_text`:

```python
async def _day_text(repo, user, date) -> str:
    if not _has_identity(user):
        return ("🎓 <b>Группа не выбрана</b>\n\n"
                "Выбери её в меню — и покажу расписание.")
    ...
```

Текст важен: не «ошибка», а приглашение. `_render_menu` уже говорит
«Группа не выбрана» — стоит переиспользовать формулировку, чтобы
экраны не расходились.

**Дополнительно: `_week_text` (`:722`) имеет ту же дыру — проверил.**

```python
async def _week_text(repo, user) -> str:
    bell, lunches = await repo.bell_schedule.get_context()
    gcg = await _course_group_map(repo, user)
    start = datetime.date.today()
    end = start + datetime.timedelta(days=6)
    lessons = await _user_lessons_range(repo, user, start, end)
```

Проверки идентичности нет, `_user_lessons_range` (`:365`) идёт прямо
в `get_for_group_range(user.group, ...)` с `None`. Результат — пустая
неделя, отрисованная `format_week` как «занятий нет» на все семь дней.

Значит правка нужна в двух местах: `_day_text` и `_week_text`. Логичнее
вынести проверку в общий помощник, чтобы третье место не забылось.

## Что проверил и признал корректным

**Пустой `subject` у 22 замен — это норма, не дефект.** Проверил все:

```
source=site action=cancel: 22
comment = 'НЕТ ПАРЫ'
```

`action='cancel'` означает «пары не будет». Предмета нет, потому что
его и не должно быть. `format_day` (`common/schedule.py:248`)
подставляет предмет **из базового расписания** через `get_day_slots`,
а не из замены. Проверил живой вывод:

```
ПРф-24 26.10: subject='Иностранный язык' action='cancel'
  '1) <s><b>09:25–11:00</b>  Иностранный язык</s>  ❌ <i>отменено</i>'

СМк-25 26.10: subject='История России' action='cancel'
  '5) <s><b>16:45–18:20</b>  История России</s>  ❌ <i>отменено</i>'
```

Зачёркивание и пометка «❌ отменено» на месте. Всё верно.

**Остальные данные полны.** Проверил прямыми запросами:

```
base_lesson:      пустой subject 0, пустой group 0, para=0 0, weekday вне 1-7 0
college_lesson:   пустой subject 0, para=0 0
```

**`get_for_teacher_date` защищён от пустого имени** — комментарий
объясняет зачем: «Без этой проверки фильтр превращался в LIKE '%%' и
человек видел пары всего колледжа и вуза разом». Правильная защита.

## Риски

- **Ранний выход меняет поведение `/start` для новых пользователей.**
  Сейчас `start` (`:397`) при отсутствии идентичности показывает
  «Кто ты?» и до `_day_text` не доходит. Значит правка затрагивает
  только те пути, где `_day_text` зовётся напрямую — кнопки
  «📅 Сегодня», «📅 Завтра», «🗓 Неделя». Это и есть нужное место.
- **`_week_text` не проверял.** Возможно, там та же дыра — стоит
  посмотреть при реализации.
