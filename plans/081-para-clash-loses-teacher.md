# План 081: склейка пар на одном слоте теряет второго преподавателя

> **СДЕЛАНО 27.10.2026** (коммит `bd1f75a`).
>
> Пропускается только полный дубль. Сверх плана нашлись два дефекта в
> самой склейке: `teacher` давал «Иванов / Иванов» для одного
> преподавателя, `room` терял второй кабинет. Оба дописываются по
> различию.

**Приоритет:** низкий. На проде таких пар нет — проверил, ноль. Но
`_merge_para_clash` объявлен в [плане 047](047-migrations-college-lesson-schema.md)
гарантией уникальности слота, а гарантия с дырой.

**Трудоёмкость:** S (две строки).

## Проблема

`_merge_para_clash` (`sync_eios.py:315`) собирает пары, попавшие на один
номер. У вуза так бывает: физкультура потоком и иностранный язык по
подгруппам.

```python
seen: dict[int, Slot] = {}
for slot in slots:
    prev = seen.get(slot.para)
    if prev is None:
        seen[slot.para] = slot
        continue
    subjects = {prev.subject, slot.subject}
    if len(subjects) == 1:
        continue                     # <- выход БЕЗ склейки
    seen[slot.para] = Slot(
        para=slot.para,
        subject=f"{prev.subject} / {slot.subject}"[:256],
        teacher=f"{prev.teacher} / {slot.teacher}"[:128] if prev.teacher or slot.teacher else "",
        ...
    )
```

Если предмет совпал, но преподаватель или кабинет — разные, `continue`
выбрасывает второй слот целиком. Не склеивает, не логирует — просто
теряет.

## Сценарий

```
пара 3: «Иностранный язык»  Иванов И.И.   (подгруппа 1)
пара 3: «Иностранный язык»  Петров П.П.   (подгруппа 2)
        ↓
len({'Иностранный язык'}) == 1  ->  continue
        ↓
студент видит только Иванова
```

Ровно тот случай, ради которого функция написана (подгруппы), но с
одинаковым названием предмета.

## Почему это важно

[План 047](047-migrations-college-lesson-schema.md) обосновывает
отсутствие уникального индекса на `college_lesson` так:

> `_merge_para_clash` (`sync_eios.py:315`) схлопывает слоты с
> одинаковым `para` в один через « / », так что `materialize_day` не
> может передать два слота с одним номером.

Это верно только для **разных** предметов. Для одинаковых функция
пропускает второй слот — но и не вставляет его, так что дубликата в
`college_lesson` не будет. Гарантия держится, теряется содержимое.

## Что на проде

Проверил `base_lesson` на оба случая:

```sql
-- один слот, один предмет, РАЗНЫЕ преподаватели
select group, weekday, para, week_parity, weeks, subject, count(distinct teacher)
from base_lesson
group by group, weekday, para, week_parity, weeks, subject
having count(distinct teacher) > 1
```

Результат: **0 строк**. То же для разных кабинетов — **0**.

Значит дефект латентный. `_merge_slot_clash` в парсере уже склеивает
такие случаи через запятую в `teacher`, поэтому до `_merge_para_clash`
две строки с одним предметом и разными преподавателями не доходят.

## Что сделать

Дописывать второго преподавателя, как это делает
`_merge_slot_clash` (`vuz.py:674`):

```python
subjects = {prev.subject, slot.subject}
teachers = {prev.teacher, slot.teacher}
if len(subjects) == 1 and len(teachers) == 1:
    continue
```

Дальше склейка пойдёт как обычно: предмет тот же, значит
`f"{prev.subject} / {slot.subject}"` даст «Иностранный язык / Иностранный
язык». Это некрасиво. Лучше отделить:

```python
if len(subjects) == 1:
    subject = prev.subject
else:
    subject = f"{prev.subject} / {slot.subject}"[:256]
```

## Проверено и признано корректным

**`materialize_day` обходит все группы, включая вуз.** Проверил
`base_lessons.get_groups()` — `select distinct group from base_lesson`,
без фильтра. На проде это 129 групп: 37 колледжа и 92 вуза. Поэтому
`college_lesson` содержит **1855 строк вуза** и 2072 колледжа — я в
прошлых раундах ошибочно записывал весь слой как колледжный.

**Патч 080 доходит до материализации.** Проверил: `get_day_slots`
вызывает `_fits_week`, а тот проверяет `weeks`. На проде у `ГД-25-1`
28.10 стоит «С нед. № 10 - Сопротивление материалов» — 9-я неделя, пары
быть не должно. После правки `weeks=(10,)`:

```
2026-10-28: неделя 9  -> _fits_week=False -> не покажет
2026-11-04: неделя 10 -> _fits_week=True  -> покажет
```

Пересобирать вручную не нужно: `poller` вызывает `materialize` на
каждом опросе.

**`_merge_para_clash` не теряет `changed`/`action`.** Проверил:
`changed=prev.changed or slot.changed`, `action=prev.action or slot.action`
— оба поля объединяются, а не берутся от первого.

**`comment` берётся только от первого** (`comment=prev.comment`). Но у
вуза `comment` всегда пуст: `replace_vuz_changes` пишет `comment=""`
(`sync_vuz.py:237`). Вреда нет.

## Риски

- **Длина полей.** `teacher` — `String(128)`, склейка режется `[:128]`.
  При двух ФИО влезает, при четырёх — обрежется. Сейчас максимум два.
- **Склейка «Иностранный язык / Иностранный язык»** выглядит глупо.
  Поэтому в разделе «Что сделать» предложено не дублировать предмет,
  когда он один.
