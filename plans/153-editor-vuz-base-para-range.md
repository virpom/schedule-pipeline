# План 153: редактор базы вуза показывает дубли и прячет пары выше пятой

**Приоритет:** средний. Редактор вуза уже сломан (план 143), но это
отдельный дефект: даже если дать ему права, экран показывает чепуху.

**Трудоёмкость:** S (~6 строк).

## Две проблемы на одном экране

`_save_base` (`editor.py:483`) после сохранения собирает экран так:

```python
lessons = await repo.base_lessons.get_day(group, weekday, parity)
slots = [Slot(l.para, l.subject, l.teacher, l.room) for l in lessons]
text = (... + base_day_text(group, weekday, parity, slots))
```

и `paras_kb(weekday, parity, slots)` для кнопок.

`get_day` вызывается **без `week`**. У колледжа `weeks` всегда пусто,
поэтому это неважно. У вуза в одном слоте живут несколько пар с
разными списками недель — и они все приходят сразу.

## Проверил на живой группе

`АП-25оз@vuz`, вторник, `parity=ANY` — `get_day` вернул **6 слотов**:

```
7) Компьютерное моделирование, ч.1      weeks='13'
7) Основы военной подготовки (лек.)     weeks='5,6'
7) Основы военной подготовки            weeks='7,8'
7) Компьютерное моделирование, ч.1 (лек.) weeks='9,10,11,12'
8) Основы военной подготовки (прак.)    weeks='5,6,7,8'
8) Компьютерное моделирование (прак.)    weeks='9,10,11,12,13'
```

**Текст** печатает все шесть подряд:

```
7) Компьютерное моделирование, ч.1
7) Основы военной подготовки (лек.)
7) Основы военной подготовки
7) Компьютерное моделирование, ч.1 (лек.)
8) Основы военной подготовки (прак.)
8) Основы военной подготовки (прак.)
```

**Кнопки** — пять штук, все пустые:

```
1) — пусто
2) — пусто
3) — пусто
4) — пусто
5) — пусто
```

## Почему кнопки пустые

`paras_kb` (`:110`) перебирает жёсткий диапазон:

```python
for p in range(1, 6):
    slot = by_para.get(p)
```

У вуза 8 пар. Всё, что выше пятой, в кнопки не попадает — а у этой
группы **все пары на 7 и 8**.

## Почему текст дублируется

`base_day_text` (`:211`) печатает список как есть:

```python
for s in slots:
    lines.append(f"<b>{s.para})</b> {s.subject}")
```

`get_day` без `week` возвращает все недели, и на одну пару приходится
несколько предметов. Дедупликации нет.

## Что видит староста вуза

Сохранил правку — получил экран, где:

- текст говорит «7) Компьютерное моделирование» четыре раза;
- кнопки под ним пустые;
- нажать не на что, чтобы продолжить правку.

**Правка сохранилась** — `upsert` прошёл, `_rebuild` пересобрал. Но
проверить результат нельзя.

## Что сделать

**Для кнопок:** брать диапазон из самих слотов, а не жёсткий `1..5`:

```python
max_para = max((s.para for s in slots), default=5)
for p in range(1, max(max_para, 5) + 1):
```

**Для текста:** схлопнуть по `(para, subject)` — или, лучше, передать
`week` в `get_day`, чтобы получить ровно одну пару на слот. Но
`_save_base` не знает, на какую неделю смотреть: правка применяется ко
всем.

Значит правильнее — группировать по паре и печатать предметы списком:

```
7) Компьютерное моделирование, ч.1 · Основы военной подготовки
```

## Что проверил и признал корректным

**`get_day` работает верно.** Проверил с настоящими константами:
`PARITY_ODD='ODD'`, `PARITY_EVEN='EVEN'`, `PARITY_ANY='ANY'`. Для
`ТМ-26-1@vuz` вторник: `ODD` → 2 строки, `EVEN` → 3, `ANY` → 0. Всё
логично.

**Для колледжа проблемы нет.** Проверил: `weeks != ""` только у
**1340 строк, все `@vuz`**, у колледжа 0. Колледж учится в 5 пар, пары
выше пятой — 3 строки на прошлых датах.

**Правка сохраняется.** `upsert` (`base_lesson.py:74`) пишет в
`(group, parity, weekday, para, weeks)`, `_rebuild` пересобирает окно.
Дефект только в отображении.

**Мои прошлые `'odd'`/`'even'` в нижнем регистре** дали 0 строк — это
была ошибка скрипта, не кода. Константы в проекте в верхнем регистре.

## Риски

- **Расширение диапазона кнопок до 8** — 8 кнопок вместо 5, экран
  вырастет. Приемлемо: у вуза столько пар и есть.
- **Группировка текста** может склеить пары, которые правда разные.
  Проверил: у вуза на один `(para)` приходится до 4 предметов — их и
  надо показать вместе, а не потерять.
