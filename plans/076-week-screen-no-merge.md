# План 076: недельный экран преподавателя не склеивает поток

**Приоритет:** средний. Экран дня и экран недели показывают одно и то
же по-разному. Преподаватель физкультуры видит 6 одинаковых строк вместо
одной.

**Трудоёмкость:** S (~4 строки).

## Проблема

`format_day` умеет склеивать пары одного преподавателя на потоке — это
делает `_merge_groups` (`common/schedule.py:170`), включается флагом
`merge_groups`:

```python
def format_day(..., merge_groups: bool = False) -> str:
    ...
    if merge_groups:
        lessons = _merge_groups(lessons)
```

Экран дня флаг передаёт (`user.py:392`):

```python
return format_day(..., merge_groups=is_teacher)
```

А `format_week` (`common/schedule.py:328`) параметра **не имеет вовсе**:

```python
def format_week(entries, bell, lunches, detail=DETAIL_BRIEF, meta="teacher",
                show_rov=True, group_course_group=None) -> str:
    return "\n\n".join(
        format_day(d, les, bell, lunches, detail, meta, show_rov, group_course_group)
        for d, les in entries)
```

Внутри вызывается `format_day` без `merge_groups`, то есть `False`.
Вызов из `_week_text` (`user.py:734`) тоже флаг не передаёт.

## Что видит преподаватель

Проверил прод — физкультуру ведёт один человек на шесть групп:

## Почему это не то же, что план 006

[План 006](006-vuz-teacher-misses-substitutions.md) разбирает
**дублирование** — когда `get_for_teacher` возвращает несколько строк
на одну и ту же пару одной и той же группы, потому что предмет записан
с разницей в точку: «(лек.)» и «(лек)». Там чинится **источник**: пары
собираются через `get_day_slots`.

Здесь другое: шесть строк — это **шесть разных групп**, а не дубли.
Даже после правки 006 они останутся шестью, потому что каждая —
законная запись про свою группу. Чинится **отображение**: тот же
`_merge_groups`, что уже работает в экране дня.

## Что сделать

Добавить параметр и прокинуть его:

```python
def format_week(entries, bell, lunches, detail=DETAIL_BRIEF, meta="teacher",
                show_rov=True, group_course_group=None,
                merge_groups: bool = False) -> str:
    return "\n\n".join(
        format_day(d, les, bell, lunches, detail, meta, show_rov,
                   group_course_group, merge_groups)
        for d, les in entries)
```

И в `_week_text` (`user.py:734`):

```python
return format_week(entries, bell, lunches, user.bell_detail, meta,
                   show_rov, gcg, merge_groups=_is_teacher(user))
```

`_is_teacher(user)` там уже вычисляется — переменная `meta` строится из
него на строке 733.

## Проверено и признано корректным

**Студент потока видит одну строку.** `_user_lessons` фильтрует по
своей группе (`get_for_group_date(user.group, date)`), поэтому шесть
записей потока до него не доходят вовсе. `merge_groups` ему не нужен.

**`_merge_groups` не склеит разных людей с одной фамилией.** Проверил:
ключ строится по `teacher_base(teacher)`, а `teacher_base` сохраняет
инициалы — `«Иванова З.Н.»` и `«Иванова Н.А.»` дают разные ключи.
Склейка возможна только при полном совпадении фамилии и инициалов.

**`_merge_groups` не теряет кабинеты на проде.** Запрос по
`college_lesson` (группы `@vuz`, одинаковые `date+para+subject+teacher`,
разные `room`) вернул **0 строк**. Комната у потока общая, как и
описано в докстринге.

**`seen.group` мутирует объект из списка.** `_merge_groups` пишет
`seen.group = ...` прямо в переданный слот. Это безопасно: `format_day`
получает либо свежий список из репозитория, либо результат
`_user_lessons`, и никто не переиспользует эти объекты после
отрисовки. Но если появится кэш — поведение станет неожиданным.

**`dict.fromkeys` сохраняет порядок.** Группы в подписи идут в порядке
появления в выборке, дубликаты убираются. Ровно то, что нужно.

## Риски

- **`format_week` вызывается ещё где-то?** Проверил
  `grep -rn "format_week" --include="*.py"` — только определение
  (`common/schedule.py:328`) и вызов в `user.py:734`. Тестов на
  `format_week` нет. Добавление параметра с дефолтом `False` ничего не
  ломает.
- **Длинная подпись.** Шесть групп в строке `meta="group"` дают
  «АП-25, ИС-25, ИЭ-25, МН-25, ЭК-25, ЭЭ-25» — около 45 символов.
  Влезает в лимит сообщения, но на узком экране переносится. Это уже
  так работает в экране дня, новых проблем не появится.
