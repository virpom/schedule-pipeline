# План 114: поиск по предмету показывает не «последние занятия»

**Приоритет:** средний. Задевает и студентов, и преподавателей, но
только тех, кто пользуется поиском по предмету.

**Трудоёмкость:** S (~2 строки).

## Проблема

`subject_answer` (`user.py:897`) обещает «последние занятия»:

```python
results = matched[:5]          # <- :908, до сортировки
...
parts = [_fmt(user, d, by_date[d], bell, lunches, gcg)
         for d in sorted(by_date, reverse=True)]
await message.answer(f"🔎 «{subj}» — последние занятия:\n\n" + "\n\n".join(parts))
```

**Срез `[:5]` берётся из `matched` — списка в том порядке, в каком его
вернул репозиторий.** А репозиторий отдаёт разные порядки для двух
веток:

`get_all_for_group` (`college_lesson.py:81`), ветка студента:

```python
.order_by(CollegeLesson.date.desc(), CollegeLesson.para)   # новые первыми
```

`get_all_for_teacher` (`college_lesson.py:204`), ветка преподавателя:

```python
.order_by(CollegeLesson.date, CollegeLesson.para)          # СТАРЫЕ первыми
```

**Итог:**
- Студент получает 5 **самых новых** занятий — верно.
- Преподаватель получает 5 **самых старых** занятий из окна — и подпись
  «последние занятия» над ними.

## Что это даёт на проде — проверил на живой базе

Взял реального преподавателя `Гулиева Н.Г.` и реальный запрос
«Иностранный». Совпадений 44. Вот что попадает в срез:

```
СЕЙЧАС (первый [:5] — старые первыми):
  2026-10-02 п1  Иностранный язык
  2026-10-02 п1  Иностранный язык
  2026-10-02 п2  Иностранный язык
  2026-10-02 п3  Иностранный язык
  2026-10-05 п3  Иностранный язык

ПОСЛЕ ФИКСА ([:5] от новых):
  2026-11-05 п2  Иностранный язык
  2026-11-05 п3  Иностранный язык
  2026-11-04 п1  Иностранный язык в профессиональной…
  2026-11-04 п2  Иностранный язык
  2026-11-04 п3  Иностранный язык

диапазон: сейчас 02.10–05.10   фикс 04.11–05.11
```

**Промах на месяц.** Подпись «последние занятия» врёт ровно настолько.

И подтвердилось второе подозрение: **четыре из пяти** результатов
приходятся на один день (02.10) — потому что внутри дня сортировка идёт
по номеру пары. Преподаватель видит почти пять одинаковых строк и
решает, что других занятий нет.

## Что сделать

Сортировать до среза, а не после:

```python
matched = [l for l in lessons if subj.casefold() in l.subject.casefold()]
if not matched:
    await message.answer(f"По «{subj}» ничего не нашлось", reply_markup=BACK_KB)
    return
matched.sort(key=lambda l: (l.date, l.para), reverse=True)   # <- добавить
results = matched[:5]
```

Две строки. `reverse=True` даёт и новые даты первыми, и пары в
обратном порядке — но группировка ниже всё равно собирает по датам, а
`by_date` потом сортируется отдельно (`sorted(by_date, reverse=True)`),
так что порядок внутри дня не важен.

**Проще и надёжнее** — отсортировать по одной дате:

```python
matched.sort(key=lambda l: l.date, reverse=True)
results = matched[:5]
```

Тогда пять результатов могут прийтись на разные дни, что и нужно для
«последних занятий».

## Проверено и признано корректным

**`_fmt` и группировка работают верно.** `by_date` собирается после
среза, `sorted(by_date, reverse=True)` даёт новые дни первыми.
Проблема только в том, **что** попало в срез.

**Студенческая ветка не задета.** `date.desc()` в SQL даёт нужный
порядок, `matched[:5]` берёт новые.

**`materialize` вызывается всегда и стоит 6.41 с.** Замерил на проде:
129 групп × 14 дней = 1806 вызовов `get_day_slots`, 6.41 с на проход.
Это каждые 5 минут. Работает, но дорого — и всегда, даже когда файлы
не менялись. Комментарий в `poller.py:109` объясняет почему (окно дат
должно сдвигаться вперёд). Стоит подумать о материализации только
новых дат, но это отдельная задача.

**`/setvuzanchor` доедет до студентов за ≤5 минут.** Проверил:
`materialize` вызывается в каждом цикле независимо от изменения файлов
(`poller.py:109-118`), значит новый якорь применится на следующем
проходе. Текст команды («при следующей синхронизации») честен.

**`_preview_for_user` не учитывает вуз** — но это уже план 111,
отдельный дефект в том же классе. Здесь только отмечаю, что нашёл
второе место.

## Риски

- **`l.date` может отсутствовать у вузовских пар.** В ветке
  преподавателя `lessons` приходят из `get_all_for_teacher`, то есть
  из `college_lesson` — там `date` есть. Безопасно.
- **Срез `[:5]` — продуктовое решение.** Возможно, стоит показывать
  все совпадения или листать. Но менять это — не задача анализа.
