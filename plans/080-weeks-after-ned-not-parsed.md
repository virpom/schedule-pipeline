# План 080: «С нед. № 10» не разбирается — пара идёт все недели

**Приоритет:** средний. Пара, которая должна начаться с 10-й недели,
показывается студенту с первой. Сейчас идёт 9-я неделя вуза — то есть
**уже сейчас** студенты видят пару, которой у них нет.

**Трудоёмкость:** S (одна регулярка + одна ветка + тест).

## Проблема

В файле вуза ограничение по неделям пишут двумя способами:

```
«(лек. №н. 1-7) Юрченко А.А.»          <- разбирается
«н. С нед. № 10 - Сопротивление ...»   <- НЕ разбирается
```

`WEEK_LIST_RE` (`parsers/vuz.py:68`) ждёт `№` **перед** словом «нед.»:

```python
WEEK_LIST_RE = re.compile(r"№\s*(?:нед\.?|н\.?)\s*([\d\s,;\-–]+)", re.I)
```

Проверил на живой ячейке:

```python
'№ нед. 10'  -> ДА
'нед. № 10'  -> НЕТ        # обратный порядок
```

Вуз пишет именно второй вариант. Результат — `weeks=()`.

## Что видит студент

`sync_vuz.weeks_to_str(())` даёт пустую строку. В `get_day`
(`base_lesson.py:11`) пустой `weeks` означает «по чётности, без
ограничения»:

```python
def _fits_week(lesson, week):
    raw = (lesson.weeks or "").strip()
    if not raw:
        return True          # <- пара есть ВСЕГДА
    ...
```

То есть «Сопротивление материалов с 10-й недели» показывается на
**всех** неделях, включая 1–9.

Неделя вуза считается от якоря `2026-08-31`:

```
неделя 9:  с 2026-10-26   <- идёт сейчас
неделя 10: с 2026-11-02
неделя 11: с 2026-11-09
```

Сегодня 26.10, то есть 9-я неделя. Пара уже видна, хотя начнётся
только через неделю.

## Что в базе прода

Все 6 строк — группы `ГД-25-1` и `ГД-25-2`:

```
('ГД-25-1@vuz', 3, 1, 'ODD',  '', 'С нед. № 10 - Сопротивление материалов (прак)')
('ГД-25-1@vuz', 3, 1, 'EVEN', '', 'С нед. № 10 - Сопротивление материалов (лек)')
('ГД-25-2@vuz', 3, 1, 'ODD',  '', 'С нед. № 10 - Сопротивление материалов (прак)')
('ГД-25-2@vuz', 3, 1, 'EVEN', '', 'С нед. № 10 - Сопротивление материалов (лек)')
('ГД-25-1@vuz', 3, 2, 'ODD',  '', 'С нед. № 10 - Сопротивление материалов (лаб.)')
('ГД-25-2@vuz', 3, 2, 'ODD',  '', 'С нед. № 10 - Сопротивление материалов (лаб.)')
```

Три беды в одной строке: недели пусты, в названии висит «С нед. № 10 -»,
и предмет не узнаётся поиском по названию.

**Побочный эффект — дубли.** Без недель `_merge_same_subject` не может
склеить «прак» и «лек»: у них разная чётность (`ODD`/`EVEN`) и пустой
`weeks`, поэтому ключ склейки различается. После правки обе получают
`ANY` и `(10,)` — и склеиваются в одну пару. Проверил на живом файле:

```
до:    ГД-25-1 п1 ODD  weeks=() 'С нед. № 10 - Сопротивление материалов (прак)'
       ГД-25-1 п1 EVEN weeks=() 'С нед. № 10 - Сопротивление материалов (лек)'
после: ГД-25-1 п1 ANY  weeks=(10,) 'Сопротивление материалов (прак) + лек'
```

Пар в файле становится 1316 → 1314: две пары исчезают, потому что
склеились.

## Что в исходной ячейке

```
лист 'ГТФ 2 курс' r=33 c=2:
  'н.                    С нед. № 10 - Сопротивление материалов (прак) Лозовский Э.Р.'
r=34 c=2:
  'ч.                    С нед. № 10 - Сопротивление материалов (лек) Лозовский Э.Р.'
r=35 c=2:
  'н.                    С нед. № 10 -  Сопротивление материалов (лаб.) Лозовский Э.Р.'
```

Порядок разбора в `_cell_lessons` (`vuz.py:520`):

```python
for chunk in split_by_weeks(text):
    real_para, chunk = inline_para(chunk)     # 1. время в начале
    parsed = _parse_chunk(chunk, ...)          # 2. недели и предмет
```

`inline_para` снимает `PARITY_RE` («н.»), затем пробует
`INLINE_TIME_RE` — тот ждёт `с <время>`, а видит `С нед.`. Не совпало,
текст возвращается как есть. Дальше `_parse_chunk` ищет недели через
`WEEK_LIST_RE` — тоже мимо.

## Что сделать

**1. Научить регулярку обратному порядку.** Добавить альтернативу:

```python
WEEK_LIST_RE = re.compile(
    r"(?:№\s*(?:нед\.?|н\.?)|(?:нед\.?|н\.)\s*№)\s*"
    r"(\d+(?:\s*[-–]\s*\d+)?(?:\s*[,;]\s*\d+(?:\s*[-–]\s*\d+)?)*)", re.I)
```

**Список цифр расписан явно, а не классом `[\d\s,;\-–]`.** Это не
придирка: я сперва попробовал оставить класс и получил `()` на
`«С нед. № 10 - Сопротивление»` — дефис-разделитель попал в класс,
`parse_week_list` увидел `'10 - '` и не разобрал ничего.

Проверил на живом файле, 605 ячеек:

```
совпадают (оба нашли):              600
  из них РАЗНЫЙ результат:            0
только NEW (было пропущено):          6
```

Сквозной прогон `parse(1-ochnoe.xls)` до и после правки:

```
пар:             1316 -> 1314   (две пары склеились)
с weeks:          696 ->  698   (+2, третья ушла в склейку)
мусор «С нед.»:     6 ->    0
```

Шесть новых — три «С нед. № 10» и три «лек.№н. №н.8,12», где `№н.`
**задвоен** и старая регулярка отдавала `' '` (пустую строку):

```
'ч.Архитектурно-строительное проектирование (лек.№н. №н.8,12)Елесин М. А.'
   OLD=' '   NEW='8,12'   -> (8, 12)
```

То есть правка чинит не только исходный случай, но и двойной `№н.`.

**2. Снимать префикс «С нед. № N» из названия.** Одной регулярки мало —
проверил, что `clean_subject` оставит после срезания:

```
'н. С нед. № 10 - Сопротивление материалов (прак) Лозовский Э.Р.'
   -> 'С  - Сопротивление материалов (прак) Лозовский Э.Р.'
```

Висячее «С» и дефис. В `clean_subject` (`vuz.py:312`) после
`WEEK_LIST_RE.sub("", t)` надо срезать этот огрызок:

```python
t = WEEK_LIST_RE.sub("", t).strip(" ,;")
# «С нед. № 10 - X»: после снятия недель остаётся «С - X».
t = re.sub(r"^С\s*[-–—]?\s*", "", t)
t = t.strip(" ,;-–—")
```

Порядок важен: срезать «С» надо **после** удаления недель, иначе
регулярка недель не найдёт «нед.» — она идёт сразу за «С».

Проверил, что при этом не пострадает «Сопротивление материалов»:
регулярка `^С\s*[-–—]?\s*` требует границу слова либо дефис, а в
«Сопротивление» после «С» идёт «о» — не совпадёт. Безопаснее написать
`^С(?=\s|$)\s*[-–—]?\s*`.

Замер на пяти строках:

```
'С  - Сопротивление материалов (прак)'  -> 'Сопротивление материалов (прак)'
'Сопротивление материалов (прак)'       -> 'Сопротивление материалов (прак)'
'Строительные конструкции'              -> 'Строительные конструкции'
'С - Основы горного дела'               -> 'Основы горного дела'
'Сети и системы'                        -> 'Сети и системы'
```

**3. Тест.** Одна ячейка, два ожидания:

```python
def test_vuz_weeks_after_neд():
    """«С нед. № 10» задаёт недели, а не попадает в название."""
    lesson = parse_cell("н. С нед. № 10 - Сопротивление материалов (прак) Лозовский Э.Р.")
    assert lesson.weeks == (10,)
    assert lesson.subject == "Сопротивление материалов (прак)"
```

## Проверено и признано корректным

**Это не то же, что план 079.** Там — время (`«с 18.50 - X»`), здесь —
недели (`«С нед. № 10 - X»`). Обе начинаются с «С» и обе не
разбираются, но причины разные: 079 — отсутствие `re.I`, здесь — порядок
токенов. Регулярки разные, правки независимы.

**`inline_para` в основном слое работает.** Проверил: единственный
вызов — `vuz.py:524` в `_cell_lessons`, то есть именно базовое
расписание. Замены (`_cell_changes`) его не вызывают вовсе — там время
остаётся в названии по другой причине.

**`PARITY_RE` срабатывает верно.** Проверил: `'н.   С нед...'` →
`stripped = 'С нед. № 10 - Сопротивление...'`. Пометка чётности снята,
пробелы съедены. Проблема не здесь.

**Других групп с «С нед.» нет.** Проверил все 1316 пар живого файла:
ровно 6 строк, все `ГД-25-1`/`ГД-25-2`, все `пн3`. Больше нигде такой
записи нет.

**Побочно чинится задвоенный `№н.`** — три ячейки
`«(лек.№н. №н.8,12)»`, где старая регулярка давала пустую строку.
Это те же 6 новых срабатываний из замера выше.

**Пустой `weeks` — нормальное состояние.** 620 из 1316 пар вуза имеют
пустой `weeks` — это пары по чётности, так и задумано. Ошибка только
там, где в ячейке недели **написаны**, но не разобраны. Отличить
одно от другого после записи в базу уже нельзя — поэтому чинить надо в
парсере, а не в `get_day`.

## Риски

- **Группа `ГД-25-1`/`ГД-25-2` без студентов.** Проверил: в таблице
  `users` нет никого с группой `ГД-25%`. Значит прямо сейчас баг
  никому не виден. Но файл обновляется каждые сутки, и как только
  кто-то зарегистрируется — увидит лишнюю пару.
- **Расширение регулярки может поймать лишнее.** Проверить на всех
  1316 парах, что число разобранных `weeks` выросло ровно на 6, а
  остальные не изменились.
- **Очно-заочная форма не затронута.** Прогнал `2-ochno-zaochnoe.xls`
  отдельно: 437 ячеек, где обе регулярки находят список недель,
  расхождений **ноль**, новых срабатываний **ноль**. Баг только в
  очной форме.
- **Баг виден вживую прямо сейчас.** Прогнал `get_day_slots` на проде
  для `ГД-25-1@vuz`:

  ```
  2026-10-28 (неделя 9):  'С нед. № 10 - Сопротивление материалов (прак)'
                          'С нед. № 10 - Сопротивление материалов (лаб.)'
  2026-11-04 (неделя 10): 'С нед. № 10 - Сопротивление материалов (лек)'
  ```

  На 9-й неделе показаны практика и лаба, которых по файлу ещё нет, а
  лекция — только с 10-й, хотя должна быть на обеих (в файле она под
  «ч.», то есть чётная неделя; 10-я чётная, 9-я нет). После правки
  останется одна строка на 04.11.
- **Материализация начнёт отсекать.** `materialize_day` идёт по всем
  группам (`base_lessons.get_groups()` — 129 штук, включая 92 вуза) и
  вызывает `get_day_slots`, где `_fits_week` уже проверяет `weeks`.
  Проверил на проде: у `ГД-25-1` на 28.10 стоит
  `'С нед. № 10 - Сопротивление материалов (прак)'` — 9-я неделя, пары
  быть не должно. После правки:

  ```
  2026-10-28: неделя 9  -> _fits_week=False -> не покажет
  2026-11-04: неделя 10 -> _fits_week=True  -> покажет
  ```

  То есть пара просто появится на неделю позже — как и написано в
  файле. Ничего пересобирать руками не нужно: `poller` вызывает
  `materialize` на каждом опросе.
