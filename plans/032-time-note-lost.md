# План 032: время пары теряется — студент приходит не в тот час

**Приоритет:** высокий. 5 пар идут по особому времени, бот показывает
звонок от обычной пары. Ошибка до 3 часов.

**Трудоёмкость:** M (~40 строк + миграция).

## Проблема

В файле колледжа время пары иногда стоит прямо в тексте ячейки:

```
с 18.00 до 21.00 - Общая энергетика и электроснабжение
```

Парсер это **корректно разбирает** (`parsers/eios.py:230`
`_strip_time_note`), складывает в `BaseLesson.time_note` (dataclass,
строка 90) — и **дальше некуда**: в модели `base_lesson` такой колонки
нет, в `college_lesson` тоже, в `Slot` тоже.

```
parsers/eios.py:359   lesson.subject, lesson.time_note = _strip_time_note(...)
sync_eios.py          time_note не пишется в БД   <- обрыв
```

То есть данные добыты, вычищены, проверены тестами
(`test_eios_parser.py:227,229,451`) — и выброшены.

## Что это значит для студента

Пять пар в файле идут по особому времени. Сравнение с сеткой звонков
(`bell_schedule`, `OTHER/I_IV/5` = `16:20–17:55`):

| Группа | День | Пара | Реально | Бот показывает |
|---|---|---|---|---|
| ТЭф-25 | чт | 5 | **16:20–19:40** | 16:20–17:55 |
| ТЭф-24 | пн | 5 | **16:20–19:40** | 16:45–18:20 |
| ТЭф-24 | вт | 5 | **18:00–21:00** | 16:20–17:55 |
| СМф-24 | вт | 5 | **18:05–19:30** | 16:20–17:55 |
| ЭОф-23 | пт | 5 | **18:00–21:00** | 16:20–17:55 |

Худший случай — `ТЭф-24` вторник: пара с 18:00, а бот говорит 16:20.
Студент приходит на два часа раньше (или, прочитав «5 пара», вообще
не приходит вечером).

Проверено на проде: в `college_lesson` у `ТЭф-24` на `2026-10-26` п5
лежит `Техническое обслуживание основного турбинного оборудования…`,
и всё — ни времени, ни пометки.

Заметить: у понедельника и остальных дней **разные** звонки
(`MONDAY/I_IV/5` = `16:45–18:20`, `OTHER/I_IV/5` = `16:20–17:55`),
так что для понедельника расхождение двойное: начало на 25 минут
позже, конец на 80 минут раньше реального.

## Почему это ещё и путает

У трёх групп (`ТЭф-24`, `СМф-24`, `ЭОф-23`) на одной паре стоят
**две разные пары с разной чётностью**:

```
ТЭф-24, вторник, п5:
  EVEN  «Основы философии»                       note = «5-я пара»
  ODD   «Техническое обслуживание…»               note = «с 18.00 до 21.00»
```

Без `time_note` это выглядит как «в чётную неделю философия, в
нечётную техобслуживание» — и непонятно, почему одна из них вечером.
С `time_note` картина читается: в нечётную неделю пара переезжает на
вечер.

## Что сделать

1. **Колонка в БД.** `base_lesson.time_note` `String(64)`,
   `default=""`. Миграция `0007_time_note`.

```python
time_note: Mapped[str] = mapped_column(String(64), default="",
                                       server_default=text("''"))
```

2. **Писать при синхронизации.** В `replace_base_lessons` добавить
   `time_note=(lesson.time_note or "")[:64]` рядом с `room`.

3. **Протащить в слой.** `Slot` получает поле `time_note`;
   `get_day_slots` копирует из `BaseLesson`; `materialize` пишет в
   `college_lesson` (тоже нужна колонка — либо только в `Slot`, если
   материализация не обязательна для отображения).

4. **Показать.** В `common/schedule.py` при рендере пары: если
   `time_note` задан — выводить его вместо звонка.

```python
if slot.time_note:
    meta.append(f"🕐 {slot.time_note}")
else:
    meta.append(bell_time)      # обычный звонок
```

## Как проверить

```python
def test_time_note_survives_to_db():
    """Время пары из ячейки доходит до college_lesson."""

def test_evening_lesson_shows_own_time():
    """Пара «с 18.00 до 21.00» не показывает звонок 16:20."""
```

Вживую: `ТЭф-24`, вторник нечётной недели → должно быть
«🕐 с 18.00 до 21.00», а не «16:20–17:55».

## Риски

- **Миграция и бэкфилл.** Старые строки получат `""` — это нормально,
  но пока файл не перекачан, время не появится. Форсить перекачку не
  надо: хеш файла не менялся, но `sync_once` обновит при следующем
  изменении. Можно разово сбросить `eios_hash_ochoe`, чтобы
  перечитать.
- **`time_note` бывает и бесполезным.** «5-я пара» (3 случая) —
  просто подтверждение обычного времени. Показывать его не вредно, но
  можно отфильтровать: если note == «N-я пара» и N совпадает с
  `para`, не выводить.
- **Формат «с 18.05 до 19:30»** — с точкой вместо двоеточия (опечатка
  в источнике). Парсер уже чинит точку перед цифрой, но не двоеточие.
  Выводить как есть — читаемо.
- **Вузу это не нужно:** там время в отдельной колонке (`Время`), и
  `time_note` не заполняется. Правка его не затронет.
