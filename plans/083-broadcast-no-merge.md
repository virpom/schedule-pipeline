# План 083: рассылка преподавателю не склеивает поток

> **СДЕЛАНО 27.10.2026** (коммит `e678f3b`).
>
> `merge_groups=is_teacher` в рассылке. Неделю починил в раунде 209.

**Приоритет:** низкий. Задевает 2 человека, но каждый день.

**Трудоёмкость:** S (одна строка).

## Проблема

`_merge_groups` (`common/schedule.py:170`) склеивает пары одного
преподавателя на потоке: физкультура у шести групп — одна строка
`Г-1, Г-2, … Г-6`, а не шесть подряд.

Включается флагом `merge_groups` у `format_day`. Флаг передаёт **только**
`_fmt` (`user.py:392`):

```python
return format_day(..., merge_groups=is_teacher)
```

В рассылке (`poller.py:176`) его нет:

```python
if lessons:
    text = format_day(
        date, lessons, bell, lunches, user.bell_detail,
        meta="group" if is_teacher else "teacher",
        show_rov=not is_teacher,
        group_course_group=gcg,
    )
```

Тот же пропуск в `_week_text` — это [план 076](076-week-screen-no-merge.md).
Рассылка там не упомянута, поэтому отдельный план.

## Что видит преподаватель

Проверил на модели — шесть групп, одна пара, `meta="group"`:

```
рассылка (флага нет):
  1) 09:00–10:30  Физическая культура
  Г-1
  1) 09:00–10:30  Физическая культура
  Г-2
  ... ещё четыре

экран дня (флаг есть):
  1) 09:00–10:30  Физическая культура
  Г-1, Г-2, Г-3, Г-4, Г-5, Г-6
```

Одно и то же расписание, два разных текста. Причём рассылка приходит
без спроса — преподаватель видит шесть строк каждый день.

## Что на проде

```
преподавателей с подпиской:   2
из них с send_image:          1

потоковые пары 28.10:
  Преображенский А.В.  пара 1   6 групп
  Кабышева М.И.        пара 6   3 группы
  Фидарова М.Г.        пара 7   3 группы
  Фидарова М.Г.        пара 8   3 группы

максимум групп на одну пару препода: 8
```

То есть у Преображенского А.В. в рассылке шесть строк на одну пару —
каждый день, когда у него физкультура.

## Что сделать

```python
text = format_day(
    date, lessons, bell, lunches, user.bell_detail,
    meta="group" if is_teacher else "teacher",
    show_rov=not is_teacher,
    group_course_group=gcg,
    merge_groups=is_teacher,
)
```

Для чатов (`poller.py:188`) флаг не нужен: там `meta` по умолчанию
(`"teacher"`), и склеивать нечего — у чата одна группа.

## Риски

- **Длина строки.** Шесть групп через запятую — 40–50 символов. Влезает.
  При восьми — тоже. `_merge_groups` не режет длину, но и исходные
  шесть строк были длиннее.
- **`_merge_groups` мутирует объект на месте.** Проверил: `seen.group =
  ...` меняет первый `lesson`, а он же лежит в исходном списке.

  ```
  до:     ['Г-1', 'Г-2', 'Г-3']
  после:  ['Г-1, Г-2, Г-3', 'Г-2', 'Г-3']
  ```

  То есть мутация реальна. Но протечь не может: `_fmt` — единственный
  вызывающий с `merge_groups=True`, и каждый вызов берёт свежий список
  из запроса (`_user_lessons`). Проверил все четыре места вызова
  `_fmt` (`user.py:664, 698, 830, 914`) — ни одно не переиспользует
  объекты. Отдельного плана не завожу.

- **`range(1, 8)` в поиске «Ближайшего» — не баг.** Подозревал, что
  семь дней не достанут до следующей пары, раз у 33 групп колледжа
  разрыв между датами 15 дней. Проверил на проде: прогнал для
  `ГД-25-1@vuz`, `ТМ - 24оз@vuz`, `ДП-26` все пустые дни вперёд на 20 и
  сравнил, что находит `range(1, 8)` с реальным ближайшим — **ни одного
  потерянного случая**. Разрыв 15 дней исторический (08.10 → 23.10,
  праздники), вперёд разрывы 2–3 дня.
