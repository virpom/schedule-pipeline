# План 092: день из одних отмен не показывает «Ближайшее»

> **СДЕЛАНО 27.10.2026** (коммит `89f53ee`).
>
> «Ближайшее» показывается, если слотов нет ИЛИ все отменены. Сверх
> плана: следующий полностью отменённый день больше не считается
> ближайшим — иначе блок вёл бы на такой же пустой день.
>
> На момент проверки на проде полностью отменённых дней не было
> (план опирался на 26.10), дефект латентный.

**Приоритет:** низкий. 8 студентов затронуты сегодня, но сценарий
повторится: полная отмена дня — штатная ситуация.

**Трудоёмкость:** S (~5 строк).

## Проблема

`_day_text` (`user.py:647`) делит вывод по одному признаку — есть ли
слоты:

```python
if lessons:
    text = format_day(...)
    ...
else:
    ...
    for i in range(1, 8):
        d = date + datetime.timedelta(days=i)
        nxt = await _user_lessons(repo, user, d)
        if nxt:
            text += "\n\nБлижайшее —\n" + _fmt(user, d, nxt, bell, lunches, gcg)
            break
```

Блок «Ближайшее» стоит **только в ветке `else`** — то есть когда слотов
нет вовсе.

Но `get_day_slots` для отменённой пары возвращает слот с
`action=SUB_CANCEL` (`schedule_layer.py:77`) — комментарий объясняет
почему: «Отменённую пару показываем зачёркнутой, а не выбрасываем.
Раньше она молча исчезала: студент видел "Занятий нет 🙌" и не
понимал, отменили пару или её никогда не было».

Значит если **все** пары дня отменены, `lessons` непуст → ветка `if` →
«Ближайшее» не показывается, хотя фактически пар нет и знать, когда
они будут, — самое нужное.

## Что на проде

Сегодня, 26.10, четыре группы полностью отменены:

```
ДОУ-24    3 пары, все отменены   подписчиков: 8
ПСО-23    3 пары, все отменены   подписчиков: 0
ЭК-24     4 пары, все отменены   подписчиков: 0
ЮР-24А    4 пары, все отменены   подписчиков: 0
```

Задеты **8 студентов**. Всего `action='cancel'` в `college_lesson` — 19
строк, полных отмен — 4 дня (все сегодня).

Проверил, что у них завтра:

```
ДОУ-24   27.10: 4 пары   <- есть что показать, но не покажется
ПСО-23   27.10: 3 пары
ЭК-24    27.10: 3 пары
ЮР-24А   27.10: 0 пар    <- и тут показать нечего, честно
```

## Что видит студент

Проверил на живом коде:

```
📅 Понедельник, 26 октября

1) ~~пара 1  Математика~~  ❌ отменено
2) ~~пара 2  Физика~~      ❌ отменено
3) ~~пара 3  История~~     ❌ отменено
```

Строки «Занятий нет» нет — и это **правильно**: отменённые пары надо
показывать. Но и «Ближайшее —» нет, хотя оно было бы к месту: три
зачёркнутые строки без единого слова о том, когда учиться.

## Что сделать

Считать «пустым» день, где все слоты отменены:

```python
real = [s for s in lessons if getattr(s, "action", "") != SUB_CANCEL]
if lessons:
    text = format_day(...)
    if not real:                       # всё отменено — подсказать, что дальше
        for i in range(1, 8):
            ...
else:
    ...
```

Блок «Ближайшее» стоит вынести в отдельную функцию и вызвать из обеих
ветвей — сейчас он в одной.

**Не забыть импорт.** `SUB_CANCEL` в `user.py` **не импортирован** —
проверил шапку файла, там `format_day`, `is_vuz`, `strip_unit` и другие,
а `SUB_CANCEL` нет. Без него правка даст `NameError` при первом же
открытии дня.

## Проверено и признано корректным

**Отменённые пары не выбрасываются — это замысел.** Комментарий в
`schedule_layer.py:74` прямо говорит, почему: иначе студент не отличит
«отменили» от «не было». Менять это не надо.

**Заметка `no_lessons` не конфликтует с заменами.** Ветка `if lessons`
заметку не читает вообще — и правильно: если есть слоты (даже
отменённые), заметка «Занятий нет» была бы противоречием.

**`format_no_lessons` при полной отмене не нужен.** Текст
«Занятий нет 🙌» стёр бы информацию о том, **что именно** отменили.
Текущий вывод лучше.

**`_fmt` в блоке «Ближайшее» передаёт `merge_groups`.** Проверил
`_user_lessons` → `_fmt(user, d, nxt, bell, lunches, gcg)` →
`merge_groups=is_teacher`. Корректно.

## Риски

- **Лишний запрос в цикле.** Блок «Ближайшее» делает до 7 запросов
  `_user_lessons`. Если вызвать его ещё и при полной отмене, запросов
  станет больше — но только для тех дней, где все пары отменены, а это
  редко.
- **Пустой день без отмен** должен вести себя как раньше. Правка
  добавляет ветку только для «слоты есть, но все отменены» — остальное
  не трогает.
