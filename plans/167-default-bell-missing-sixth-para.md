# План 167: запасная сетка звонков короче настоящей — 6-я пара без времени

**Приоритет:** низкий. Срабатывает только на чистой базе и только до
первой успешной синхронизации, но тогда студент видит «6) пара 6» без
времени.

**Трудоёмкость:** S (одна строка).

## Что происходит

`seed_if_empty` (`bell_schedule.py:112-140`) заполняет сетку звонков
при старте, если таблица пуста:

```python
async def seed_if_empty(self) -> None:
    result = await self.session.execute(select(func.count()).select_from(BellSchedule))
    if result.scalar_one() > 0:
        return
    rows = [... for d, c, p, s, h1e, h2s, e in DEFAULT_BELL]
    await self.session.execute(insert(BellSchedule).values(rows))
```

`DEFAULT_BELL` (`:9-31`) — **21 строка**, пары 1..5 для `MONDAY` и
`OTHER`, плюс «Разговоры о важном».

Но сайт отдаёт **6 пар** в стандартном дне. Проверил, распарсив живой
`стандартное.docx`:

```
OTHER I_IV   п1 09:00–09:45 / 09:50–10:35
             п2 10:45–11:30 / 11:55–12:40
             п3 12:50–13:35 / 13:40–14:25
             п4 14:35–15:20 / 15:25–16:10
             п5 16:20–17:05 / 17:10–17:55
             п6 18:05–18:50 / 18:55–19:40     <- В DEFAULT_BELL НЕТ
```

То же для `II_III`. В понедельнике пар 1..5 — там совпадает.

## Что видит студент

`format_day` (`common/schedule.py:236-243`) ищет звонок, не находит и
подставляет заглушку:

```python
bs = bell.get((dt, cg, p)) or bell.get((dt, "I_IV", p))
if not bs:
    time_str = f"пара {p}"
```

Воспроизвёл на локальной копии `DEFAULT_BELL` (21 строка) с парой 6:

```
📅 Среда, 28 октября

6) пара 6  Архивное дело
Тест Т.Т.
```

Вместо `18:05–19:40 / 18:55–19:40` — просто «пара 6».

## Кого касается

В `college_lesson` 6-я пара есть у трёх групп:

```
ДОУ-24, ПРф-24, ЭОф-24   — 3 строки
```

В `base_lesson` 6-й пары нет ни у колледжа, ни в постоянном
расписании — она приходит только заменой.

## Когда срабатывает

Только **на чистой базе** и **до первой успешной синхронизации**.
Дальше `replace_bells` (`sync_eios.py:155-192`) перезаписывает сетку
из docx, и 6-я пара появляется.

Порядок в `main.py`:

```python
await run_migrations(engine, config)
...
await on_startup(session_pool)          # seed_if_empty
poller_task = asyncio.create_task(poller_loop(...))
```

То есть окно — от старта до первого опроса (до 5 минут, а если сайт
лежит — дольше).

## Почему это не то же, что план 023

[План 023](023-sixth-para-missing-bells.md) — про `format_bell`
(`common/schedule.py:358`), где `range(1, 6)` не печатает 6-ю пару в
экране «Звонки». Это **отображение** уже имеющейся строки.

Здесь — про **отсутствие строки** в `DEFAULT_BELL`. Даже если починить
`range(1, 6)` в `format_bell`, показывать будет нечего.

[План 140](140-setbell-collapses-pair.md:165) утверждает:

> **`seed_if_empty` заполняет верно.** Сверил `DEFAULT_BELL` с живой
> базой — совпадает до минуты.

Сверка была неполной: 21 строка `DEFAULT_BELL` действительно совпадает
с одноимёнными строками базы, но в базе есть **39** строк — 18 лишних,
и среди них 6-я пара `OTHER`.

## Что сделать

Добавить две строки в `DEFAULT_BELL`:

```python
("OTHER", "I_IV", 6, "18:05", "18:50", "18:55", "19:40"),
("OTHER", "II_III", 6, "18:05", "18:50", "18:55", "19:40"),
```

Значения взял из живого `стандартное.docx` — обе группы идут
одинаково.

## Проверено и признал корректным

**`seed_if_empty` не перезаписывает непустую таблицу** — `if count > 0:
return`. На проде 39 строк, засев не сработает.

**`replace_bells` сохраняет `ALL` и `VUZ`** — `keep = ("ALL",
VUZ_GROUP)`, остальное удаляет и вставляет заново. 6-я пара приедет
из docx.

**`DEFAULT_LUNCH` полон.** Четыре строки обеда на месте, совпадают с
базой.

**Понедельник верен.** В `понедельник.docx` пары 1..5, `DEFAULT_BELL`
тоже 1..5. Расхождения нет.

**Сетка вуза не в `DEFAULT_BELL`.** 16 строк `VUZ` приходят из
`sync_vuz`, а `seed_if_empty` их не создаёт. Это не дефект: сетка вуза
появляется при первой синхронизации, а до неё студент вуза видит
«Сетка звонков вуза не загружена» (`common/schedule.py:380-382`).

## Риски

- **Засев сработает только на чистой базе.** На проде правка ничего не
  изменит — там уже 39 строк. Ценность в том, чтобы новый стенд
  стартовал с полной сеткой.
- **Тест:** нужен `test_bell_seed.py` — проверить, что
  `len(DEFAULT_BELL)` покрывает все пары из реальных docx. Сейчас
  тестов на `bell_schedule` нет вообще.
