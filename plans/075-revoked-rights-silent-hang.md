# План 075: отзыв прав посреди диалога вешает старосту в молчании

> **СДЕЛАНО 27.10.2026** (коммит `38f286c`, раунд 198).
>
> `_save_base` и `_save_sub` больше не выходят молча: пишут «Права
> редактора отозваны. Правка не сохранена.», показывают `_no_rights_kb()`
> и зовут `state.clear()` — иначе следующее сообщение снова уходило в
> `on_room`. Сценарии «перезапуск бота» и `KeyError` из плана признаны
> недостижимыми: `MemoryStorage` чистит state и data одной записью.

**Приоритет:** низкий по вероятности (нужно совпадение: админ отзывает
права, пока староста вводит пару), но высокий по эффекту — человек
теряет управление ботом и не понимает почему.

**Трудоёмкость:** S (~6 строк).

## Проблема

В редакторе 22 проверки прав. Двадцать из них показывают «Нет прав»:

```python
if not group:
    await cb.answer("Нет прав", show_alert=True)
    return
```

А две — `_save_base` (`editor.py:442`) и `_save_sub` (`editor.py:706`) —
просто выходят:

```python
async def _save_base(event, repo, state, via_cb):
    data = await state.get_data()
    group = await editor_group(repo, event.from_user.id)
    if not group:
        return                      # <- ни сообщения, ни state.clear()
```

## Как до этого дойти

Промежуточные шаги диалога прав **не проверяют** вовсе. `on_subject`
(`editor.py:931`), `on_teacher` (`:948`), `on_room` (`:958`) вызывают
только `state.update_data` и `state.set_state`.

Попасть в эти состояния можно лишь через `cb_edit_base`/`cb_sub_edit`,
а те права проверяют. Значит штатный путь защищён. Но права могут
исчезнуть **между** шагами:

```
13:00:00  староста нажал «✏️ Изменить»   -> права есть, EditorState.subject
13:00:10  админ жмёт «🗑» в меню редакторов (cb_editor_revoke)
13:00:20  староста пишет «Математика»    -> on_subject, проверки нет
13:00:35  староста пишет «Иванов»        -> on_teacher, проверки нет
13:00:50  староста пишет «204»           -> on_room -> _save_base
13:00:50  _save_base: if not group: return   <- ТИШИНА
```

Староста ввёл три поля и не получил ничего. Ни «сохранено», ни ошибки.

## Почему это хуже, чем просто тишина

`_save_base` не вызывает `state.clear()`. Состояние остаётся
`EditorState.room`. Дальше:

```
13:01:10  староста пишет «привет»        -> on_room -> _save_base -> тишина
13:01:30  староста пишет «есть кто?»     -> on_room -> _save_base -> тишина
13:02:00  староста нажимает «📅 Сегодня» -> on_room -> _save_base -> тишина
```

**Любое** сообщение снова попадает в `on_room`, потому что
`editor_router` стоит в `routers_list` **до** `user_router`:

```python
# tgbot/handlers/__init__.py
routers_list = [
    admin_router,
    editor_router,      # <- on_room здесь
    user_router,        # <- any_text здесь
]
```

И комментарий в том же файле объясняет, почему такой порядок:

> ВАЖНО: editor_router идёт ДО user_router — у пользователя есть
> catch-all any_text, который иначе перехватил бы текстовый ввод
> старосты.

То есть `any_text` («не молчим на непонятный текст — показываем меню»)
до пользователя **не дойдёт**: `on_room` перехватит раньше и промолчит.

Единственный выход — `/start`: он единственный обработчик, который
чистит состояние до проверки прав (`user.py:398`).

## Что сделать

Не выходить молча — сказать и почистить состояние:

```python
async def _save_base(event, repo, state, via_cb):
    data = await state.get_data()
    group = await editor_group(repo, event.from_user.id)
    if not group:
        await state.clear()
        await event.answer("❌ Права редактора отозваны. Правка не сохранена.")
        return
```

То же в `_save_sub`. Но `_save_base` вызывается двумя путями —
`via_cb=True` (из кнопки) и `via_cb=False` (из сообщения), и у `event`
разные типы:

```python
if via_cb:
    await event.message.answer(text)
else:
    await event.answer(text)
```

Значит и здесь нужна та же развилка — по образцу того, как уже сделано
для «Предмет не может быть пустым» на строке 455:

```python
if not group:
    await state.clear()
    text = "❌ Права редактора отозваны. Правка не сохранена."
    if via_cb:
        await event.message.answer(text)
    else:
        await event.answer(text)
    return
```

## Проверено и признано корректным

**`get_group_for` фильтрует `is_active`.** Проверил
`schedule_editor.py:14`:

```python
select(ScheduleEditor.group).where(
    ScheduleEditor.user_id == user_id,
    ScheduleEditor.is_active == True,  # noqa: E712
)
```

Отзыв прав через `revoke()` ставит `is_active=False`, и следующий вызов
`editor_group` вернёт `None`. Права действительно отзываются сразу.

**`scalar_one_or_none` не упадёт на двух строках.** `user_id` —
первичный ключ (`models/schedule_editor.py:15`), значит у человека не
может быть двух записей. `grant()` делает upsert по `user_id`.

**`editor_entry` и `cb_back` показывают причину.** Первый — «У тебя нет
прав редактора», второй — «Нет прав». Оба корректны.

**Порядок роутеров правильный.** `editor_router` до `user_router` —
единственный способ дать старосте вводить текст. Менять порядок нельзя,
иначе `any_text` съест ввод.

**Тесты этого не ловят.** В тестах права не отзываются посреди
диалога — сценарий не воспроизводится.

## Риски

- **`state.clear()` перед сообщением.** Если сначала очистить, а потом
  отправить — порядок не важен, `clear` не влияет на отправку. Но если
  отправка упадёт, состояние уже чистое, и человек хотя бы не застрянет.
- **Тот же дефект в других слоях?** Проверил `grep -n "if not group:"`
  по всему `editor.py` — молчат ровно два места (442, 706). Остальные
  двадцать отвечают.
- **Отзыв — это кнопка, а не команда.** Проверил `admin.py`: команды
  `/seteditor` нет. Права отзываются через `cb_editor_revoke`
  (`admin.py:1114`), которая вызывается кнопкой «🗑» в меню редакторов
  и сразу делает `repo.editors.revoke(user_id)`. Значит админу нужно
  два тапа, чтобы попасть в окно, когда староста уже в диалоге, — но
  вероятность от этого не нулевая.
