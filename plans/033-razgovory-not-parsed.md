# План 033: «Разговоры о важном» не разбираются из файла звонков

> **СДЕЛАНО 27.10.2026** (коммит `36fa196`).
>
> Строка распознаётся по тексту (`_is_razgovory`), время разбирается из
> одной ячейки (`_parse_range`), кладётся в `para=0` с
> `course_group=ALL`.
>
> Проверено на настоящем файле с сайта: было 10 записей, стало 11,
> `para=0 → ALL / 09:00–09:20`. Файл добавлен в фикстуры
> (`tests/fixtures/bells-monday.docx`), тесты идут на нём, а не на
> синтетике.
>
> `DEFAULT_BELL` оставлен как seed для пустой БД — `replace_bells`
> теперь перезаписывает его значением из файла.

**Приоритет:** низкий. Сейчас значение совпадает с реальным, но
держится на константе в коде, а не на источнике.

**Трудоёмкость:** S (~10 строк).

## Проблема

Файл звонков на понедельник (`понедельник.docx`) содержит строку:

| cell0 | cell1 | cell2 … |
|---|---|---|
| `''` | `с 9.00 до 9.20 – «Разговоры о важном»` | то же |

`parse_bells` ищет номер пары в **первой** колонке:

```python
m = re.match(r"\s*(\d)\s*пара", cells[0])
if not m:
    continue        # <- строка «Разговоров» пропускается
```

`cells[0]` пуст → строка отбрасывается. В результате `parse_bells`
возвращает 10 записей для понедельника (пары 1–5 × 2 потока), без
«Разговоров».

Проверено: разобрал оба файла — `para=0` в выводе нет ни одного.

## Почему это пока не видно

В `bell_schedule` на проде есть строка:

```
MONDAY | ALL | para=0 | 09:00–09:20
```

Она попала туда из `DEFAULT_BELL` (`bell_schedule.py:11`) при первом
запуске (`seed_if_empty`), а не из файла. Значение **совпадает** с
файлом (9:00–9:20), поэтому студент видит правильное время.

То есть фича работает по совпадению.

## Что сломается

Если колледж сдвинет «Разговоры» (скажем, на 8:50–9:10), бот этого
не заметит: `parse_bells` строку пропустит, `replace_bells` не тронет
`ALL/0` (он в списке `keep`), а `DEFAULT_BELL` перезаписывать никто не
будет. В БД останется 09:00.

Студент придёт не в то время — ровно та же проблема, что в плане 032,
но здесь она ещё не проявилась.

## Что сделать

Разбирать строку без номера пары как `para=0`:

```python
m = re.match(r"\s*(\d)\s*пара", cells[0])
if m:
    para = int(m.group(1))
elif re.search(r"разговоры\s+о\s+важном", " ".join(cells), re.I):
    # Строка без номера пары — «Разговоры о важном» (слот para=0).
    # Время лежит в первой колонке потока, а не в нулевой.
    para = 0
else:
    continue
```

Дальше существующий код обработает её как обычную пару, но с `para=0`.
Надо будет только проверить, что `halves[0]` соберётся корректно:
сейчас там ожидается **две** половины (`len(pairs) >= 2`), а у
«Разговоров» одна строка и одно значение времени.

```python
if len(pairs) >= 2:
    (s1, e1), (s2, e2) = pairs[0], pairs[1]
elif para == 0:
    # «Разговоры о важном» — одна строка, без деления на половины.
    (s1, e1), (s2, e2) = pairs[0], pairs[0]
```

## Что это не ломает

- Пары 1–5 разбираются как раньше (10 записей для понедельника,
  12 для остальных дней — проверено).
- `replace_bells` сохраняет `("ALL", VUZ_GROUP)` в списке `keep`,
  так что новые `ALL/0` не сносятся.
- Для `OTHER` такой строки в файле нет — поведение не изменится.

## Как проверить

```python
def test_razgovory_parsed_from_file():
    """Строка «Разговоры о важном» без номера пары даёт BellSlot(para=0)."""
    rows = eios.parse_bells(MONDAY_DOCX, "MONDAY")
    rov = [r for r in rows if r.para == 0]
    assert len(rov) == 1
    assert rov[0].course_group == "ALL"
    assert rov[0].start == datetime.time(9, 0)
```

Вживую: `/bell` на понедельник → «Разговоры о важном 09:00–09:20».
После смены времени в файле — новое время.

## Риски

- **`para=0` используется ещё и в `format_bell`** как отдельный слот
  (`show_rov`). Если разбирать его из файла, надо убедиться, что
  `course_group` ставится `ALL`, иначе `bell.get((day_type, "ALL", 0))`
  не найдёт.
- **`parse_time` на «с 9.00 до 9.20»** — текущая реализация ждёт две
  отдельные ячейки (`start_cell`, `end_cell`). В строке «Разговоров»
  обе даты лежат в **одной** ячейке. Понадобится либо разбить строку
  регуляркой, либо использовать `_TIME_HEAD_RE`-подобный разбор. Это
  и есть основная работа, а не сам `if`.
- **Дублирование с `DEFAULT_BELL`.** После фикса значение из файла
  будет перезаписывать константу при каждой синхронизации. Константу
  стоит оставить только как seed для пустой БД — это она и делает.
