# План 030: таблица `no_lessons` больше не заполняется

**Приоритет:** низкий. Данные не портятся, но фича «объяснить пустой
день заметкой старосты» перестала существовать молча.

**Трудоёмкость:** S (решение + ~15 строк, либо удаление).

## Проблема

`no_lessons` хранит заметки вида «Занятий нет. Смотреть расписание на
08.10.2026». Их показывают два места:

```python
# user.py:673
note = await repo.no_lessons.get_note(date, user.group)
...
if note:
    text = format_no_lessons(date, note)

# poller.py:167, :191
note = await repo.no_lessons.get_note(date, user.group) if not lessons else None
```

Но **писать в таблицу некому**. `NoLessonsRepo.replace_date` —
единственный метод записи — не вызывается ни из одного места:

```
grep -rn "no_lessons.replace_date" -> пусто
```

В таблице 4 строки, все на 07–08.10.2026 (прошлое):

```
(1, '2026-10-07', 'ПРк-25',  'Занятий нет. Смотреть расписание на 08.10.2026')
(2, '2026-10-07', 'ЭК-25',   'Занятий нет. Смотреть расписание на 08.10.2026')
(3, '2026-10-07', 'ЮР-25А',  'Занятий нет. Смотреть расписание на 08.10.2026')
(4, '2026-10-08', 'ПРф-25',  'Занятий нет. Смотреть расписание на 08.10.2026')
```

## Откуда взялось

Старый парсер (до перехода на ЭИОС) разбирал файл расписания, где
такие фразы были написаны прямо в ячейках. После перехода на ЭИОС
`parsers/eios.py` это поле **не разбирает** — в файле `.xlsx` его нет
как структуры, а текст «Занятий нет» в `common/schedule.py:289` — это
шаблон вывода, а не разбираемые данные.

То есть таблица осталась от прошлой архитектуры, а читатели — нет.

## Следствие

Для любого будущего дня `note = None` всегда. Ветка `if note:`
в `user.py:676` мертва для будущего (сработает только на тех 4 датах
из прошлого, если студент листает историю).

Функционально ничего не ломается: `format_no_lessons(date)` без
заметки показывает обычное «Занятий нет 🙌».

## Что решить

**Вариант А — удалить.** Таблица, модель, репозиторий, обе ветки
чтения. Минус 4 файла, минус 2 вызова в хот-пути.

```python
# user.py — было
note = await repo.no_lessons.get_note(date, user.group)
...
if note:          text = format_no_lessons(date, note)
elif published:   text = format_no_lessons(date)
# станет
if published:     text = format_no_lessons(date)
```

**Вариант Б — оживить.** Парсить из ЭИОС, если там есть такие ячейки.
Но в `.xlsx` колледжа их нет — проверено, парсер их не находит.
Значит вариант Б требует ручного ввода (староста пишет заметку через
редактор). Это новая фича, а не починка.

**Рекомендация: вариант А.** Фича не работает не по недосмотру, а
потому что источник данных исчез. Держать мёртвую таблицу и два
запроса в каждом показе дня — платить за несуществующее.

Если заметки старосты нужны — это отдельная фича: `schedule_edit`
уже хранит ручные правки, к нему и пристроить.

## Как проверить

```python
def test_no_lessons_note_not_queried():
    """Пустой день не делает лишний запрос к несуществующей фиче."""
```

Вживую: пустой день показывает «Занятий нет 🙌» без заметки — как
и сейчас.

## Риски

- **4 строки в истории.** Если их удалить, история 07–08.10 потеряет
  пояснение. Даты в прошлом, студенты туда почти не ходят. Если
  жалко — оставить таблицу, убрать только вызовы из хот-пути.
- **Миграция.** Удаление таблицы — `0007_drop_no_lessons`. Откат
  (`downgrade`) должен её воссоздать, иначе alembic несимметричен.
- **`format_no_lessons(date, note)`** — параметр `note` используется
  и в тестах (`test_source_state.py`). Убирать его из сигнатуры или
  оставить с `None` по умолчанию — второе безопаснее.
