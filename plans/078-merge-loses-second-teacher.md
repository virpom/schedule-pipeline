# План 078: склейка лекции и практики теряет второго преподавателя

> **СДЕЛАНО 27.10.2026** (коммит `4f1f198`).
>
> `_merge_same_subject` дописывает преподавателя через запятую — тот
> же приём, что в `_merge_slot_clash`. Связка с планом 021 проверена:
> `room` уже читается из колонки «ауд», там ничего не осталось.

**Приоритет:** низкий. На проде пока не проявилось — оба случая склейки
обошлись одним преподавателем. Но механизм теряет данные молча.

**Трудоёмкость:** S (три строки).

## Проблема

Две функции склеивают пары вуза в одну строку. Обрабатывают
преподавателя они **по-разному**.

`_merge_slot_clash` (`parsers/vuz.py:674`) — дописывает через запятую:

```python
if lesson.teacher and lesson.teacher not in found.teacher:
    found.teacher = (f"{found.teacher}, {lesson.teacher}"
                     if found.teacher else lesson.teacher)
```

`_merge_same_subject` (`parsers/vuz.py:699`) — только если поле пустое:

```python
if not found.teacher and lesson.teacher:
    found.teacher = lesson.teacher
```

То есть если у лекции преподаватель уже записан, а у практики — другой,
**второй исчезает**.

## Сценарий

В вузе бывает «Страхование (лек.)» и «Страхование (прак.)» в одну пару
на одни и те же недели. Студенту это одна пара — потому и склеивается.

```
"Страхование (лек.)"  Иванов И.И.
"Страхование (прак.)" Петров П.П.
        ↓ _merge_same_subject
"Страхование (лек.) + прак"  Иванов И.И.     <- Петров П.П. потерян
```

Студент идёт на практику и не знает, кто её ведёт. В расписании
преподавателя Петров П.П. эту пару тоже не увидит — она записана на
Иванова.

## Что на проде сейчас

Склеенных предметов три:

```
'Основы элементарной математики и элементарной физики / История России (прак. )'
    Багомедова У.М., Левочкина Н.А.        ×2
'Электрические машины (лек.) + лаб'
    Саушкин С. А.                          ×1
```

Первая — через `_merge_slot_clash`, оба преподавателя на месте.
Вторая — через `_merge_same_subject`, но преподаватель один и в
источнике, потери нет.

Значит баг **латентный**: данных, где лекцию и практику ведут разные
люди, пока не встретилось. Но файл обновляется каждые сутки, и вуз
ничего не мешает выложить такую пару завтра.

## Что сделать

Привести к тому же приёму, что в `_merge_slot_clash`:

```python
if lesson.teacher and lesson.teacher not in found.teacher:
    found.teacher = (f"{found.teacher}, {lesson.teacher}"
                     if found.teacher else lesson.teacher)
```

## Связь с планом 021

[План 021](021-vuz-rooms-lost.md) разбирает **кабинеты**: сейчас
`vuz.py` вообще не читает колонку «ауд», поэтому у всех 1316 пар вуза
`room` пуст. Там же сказано: «`_merge_slot_clash` и
`_merge_same_subject` склеивают пары. При склейке кабинеты надо
объединять, а не терять» — с готовым сниппетом.

Этот план — про **ту же пару функций**, но про поле `teacher`, и
`_merge_same_subject` в 021 упомянут только для кабинетов. Чинить
логично вместе: одна правка на оба поля в обеих функциях.

| Функция | `teacher` | `room` |
|---|---|---|
| `_merge_slot_clash` | дописывает ✅ | теряет (021) |
| `_merge_same_subject` | **теряет** (этот план) | теряет (021) |

## Проверено и признано корректным

**`_merge_slot_clash` не теряет преподавателя при пустом поле.**
Проверил все три случая:

```
found="" Иванов И.И.   -> "Иванов И.И."             верно
found="Петров П.П." Иванов И.И. -> "Петров П.П., Иванов И.И."  верно
found="Петров П.П." Петров П.П. -> без изменений    верно
```

Подстрочная проверка `not in` теоретически может схлопнуть
«Иванов И.И.» и «Иванов И.», но в файлах инициалы всегда с точкой
после каждой буквы, так что обрубков не бывает.

**`_dedupe` не схлопывает ODD+EVEN в ANY.** Проверил докстринг и код:
ключ включает `parity` и `weeks`, поэтому «одинаковый текст в двух
половинах блока» остаётся двумя записями. Это осознанно — иначе разные
предметы в одну пару слились бы.

**`parse_week_list` защищён от опечаток.** Проверил: диапазон
`b - a < 40` отсекает «2026-2027», а `n > 60` с чётной длиной
разбивает «1218» на «12, 18». Комментарий в коде объясняет оба случая.

**`para_from_time` ищет по началу времени.** Опечатка «18.50 - 22.00»
вместо «18.50-20.20» всё равно даст 8-ю пару, потому что сравнивается
только часть до дефиса.

**`_base_name` срезает скобки корректно.** Проверил на трёх примерах:
`'Электрические машины (лек.)'` → `'Электрические машины'`,
`'История России (прак. )'` → `'История России'` (пробел внутри скобок
не мешает).

## Риски

- **Слишком длинное поле.** `teacher` — `String(128)`, а `sync_vuz`
  уже режет: `teacher=(lesson.teacher or "")[:128]`. Три-четыре
  фамилии влезают, но при склейке четырёх имён можно обрезать
  последнее. Сейчас максимум два.
- **Поиск по преподавателю.** `teacher_matches` сравнивает по фамилии,
  а склеенная строка содержит две. Для поиска это работает — обе
  фамилии присутствуют в тексте, и `LIKE` найдёт любую. Но
  `teacher_base` берёт только часть до запятой, так что второй
  преподаватель в списке «Преподаватели» может не появиться. Проверить
  при правке.
