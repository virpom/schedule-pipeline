# План 170: `replace_vuz_lessons` без справочника сносит обе формы

**Приоритет:** низкий по достижимости, высокий по последствию. В проде
ветка мертва — `sync_once` всегда пишет справочник первым. Но контракт
функции её допускает, и в тестах она срабатывает по-настоящему.

**Трудоёмкость:** S (~6 строк).

## Что происходит

`replace_vuz_lessons` (`sync_vuz.py:109-125`) решает, что удалять:

```python
own_groups = [
    g for (g,) in await repo.session.execute(
        select(VuzGroup.name).where(VuzGroup.form == form)
    )
]
own = set(own_groups)
...
# Чистим только свою форму. Если справочника ещё нет (первый запуск),
# берём группы из самого файла.
if own:
    await repo.session.execute(
        delete(BaseLesson).where(
            BaseLesson.source == SOURCE_VUZ,
            BaseLesson.group.in_(own),
        )
    )
else:
    await repo.session.execute(
        delete(BaseLesson).where(
            BaseLesson.source == SOURCE_VUZ,
            BaseLesson.group.like(f"%{vuz.VUZ_SUFFIX}"),   # <- ВСЕ формы
        )
    )
```

Комментарий обещает «берём группы из самого файла», но **групп из файла
у функции нет** — параметра с ними нет, `form` только выбирает, что
читать из справочника. Поэтому `else` сносит **все** группы вуза,
включая чужую форму.

## Воспроизвёл

In-memory база, две формы в `base_lesson`, справочник `vuz_group` пуст:

```
до:    2 строк (ЭК-23@vuz 'OLD-ЭК-23@vuz', ПС-23оз@vuz 'OLD-ПС-23оз@vuz')
вызов: replace_vuz_lessons(repo, [ЭК-23@vuz ...], "full")
после: 1 строк (ЭК-23@vuz 'Новая')

ПС-23оз@vuz присутствует: False
```

Строка очно-заочной формы уничтожена вызовом, который должен был
трогать только очную.

## Почему в проде не срабатывает

`sync_once` (`:356-358`) пишет справочник **до** уроков:

```python
await replace_vuz_groups(repo, parsed.groups, form)
count = await replace_vuz_lessons(repo, parsed.lessons, form)
```

После `replace_vuz_groups` в `vuz_group` лежат группы этой формы, значит
`own` не пуст. Проверил и первый запуск: `FILES` перебирается по
порядку `full`, `part`, и для каждой формы сначала идёт `groups`. Даже
на пустой базе `else` не достигается.

Проверил на живой копии: с заполненным справочником вызов `full`
сохраняет строку `part` — изоляция работает.

## Где срабатывает по-настоящему

Тесты вызывают функцию напрямую, без справочника:

```
tests/test_sync_vuz.py:78   replace_vuz_lessons(repo, lessons, "full")
tests/test_sync_vuz.py:95, 115, 118, 138, 157, 214, 236
```

В них одна форма, поэтому снос чужой формы незаметен — он маскирует
дефект. Стоит добавить тест с двумя формами и пустым справочником:
сейчас он упадёт.

## Что сделать

Убрать `else` совсем. Если справочника нет — это ошибка порядка
вызовов, а не повод сносить всё:

```python
if not own:
    raise RuntimeError(
        f"справочник групп формы {form!r} пуст — "
        f"replace_vuz_groups должна вызываться первой"
    )

await repo.session.execute(
    delete(BaseLesson).where(
        BaseLesson.source == SOURCE_VUZ,
        BaseLesson.group.in_(own),
    )
)
```

Тестам, которые зовут функцию напрямую, придётся сначала вызвать
`replace_vuz_groups` — это честнее: они проверяют реальный порядок.

Мягкий вариант без `raise`: `if not own: return 0` — ничего не удаляем
и ничего не пишем. Но тогда первый проход молча не обновит расписание,
и это хуже явной ошибки.

## Проверено и признал корректным

**Изоляция форм при заполненном справочнике работает.** Проверил:
`full` не трогает строки `part`. Именно это чинили раньше — комментарий
в докстринге («после второго файла осталась только очно-заочная»)
описывает реальный прошлый баг.

**`replace_vuz_changes` имеет ту же `else`-ветку** (`:222-226`), но там
она безопаснее: сносит `Substitution` по `source == SOURCE_VUZ` без
фильтра по группам. Это тоже снесло бы чужую форму — тот же дефект, ту
же правку стоит применить и там.

**`parse` гарантирует непустой `all_groups`.** `parse_sheet:619-620`
бросает `VuzParseError`, если групп нет, а `parse:797` — если нет пар.
Пустой справочник получается только от порядка вызовов, не от парсера.

**`result["groups"]` в `sync_once` никто не читает** — поле мёртвое
(`:324`, `:373`), единственный потребитель `poller.py` смотрит только
`failed`, `full`, `part`, `anchor_off`. Мелочь, но при правке функции
его можно убрать.

## Риски

- **`raise` уронит синхронизацию вуза**, если кто-то вызовет функцию не
  в том порядке. Но `sync_once` ловит исключение по форме (`:331-336`) и
  пишет в `failed` — колледж продолжит работать.
- **Тесты придётся править** — восемь вызовов. Это и есть польза: они
  начнут проверять реальный порядок.
