# План 096: преподаватель, пришедший через замену, не находится в списке

**Приоритет:** низкий. Три человека на проде, но дефект системный:
список вуза строится из `base_lesson`, а замены живут в
`substitution`/`college_lesson`.

**Трудоёмкость:** S (~4 строки).

## Проблема

`get_teachers_vuz` (`college_lesson.py:121`) берёт имена **только** из
базового слоя:

```python
result = await self.session.execute(
    select(BaseLesson.teacher)
    .where(BaseLesson.group.like(f"%{VUZ_SUFFIX}"))
    .distinct()
)
return _clean_teacher_names(t for (t,) in result.all() if t)
```

Комментарий объясняет выбор: «Преподаватели вуза: их пары лежат в
base_lesson, не в college_lesson».

Но это неверно: `college_lesson` для вуза — **материализованный**
результат `base_lesson` **плюс замены**. Если преподаватель ведёт пару
только по замене (заменил заболевшего), в `base_lesson` его нет вовсе,
и в списке он не появится.

## Кого это задевает на проде

```
get_teachers_vuz отдаёт:  126
реально ведут вуз:        129
```

Три преподавателя недостижимы через поиск:

| Имя | Пар вуза | Откуда |
|---|---|---|
| `Кулян Р.А` | 3 | `ЭК-25@vuz`, только замены |
| `Маргаритова Р.С.` | 2 | `ГП-25@vuz`, замена 24.10 |
| `Николаева Ю.А.` | 2 | `МЦ-22оз@vuz`, замена 24.10 |

Проверил `Маргаритову` подробно — она **ведёт и колледж, и вуз**:

```
base_lesson:   ПРф-23, ЮР-24А, ЮР-24Б     (колледж)
college_lesson ГП-25@vuz, 24.10, пары 1-2  (через replace)
substitution:  ГП-25@vuz, 24.10, action=replace
```

То есть в списке колледжа она есть, в списке вуза — нет. Студент вуза,
ищущий её по фамилии, получит пустой результат, хотя пары у неё были.

## Что сделать

Добавить `college_lesson` как второй источник:

```python
async def get_teachers_vuz(self) -> list[str]:
    names = set()
    for model in (BaseLesson, CollegeLesson):
        q = select(model.teacher)
        if model is BaseLesson:
            q = q.where(BaseLesson.group.like(f"%{VUZ_SUFFIX}"))
        else:
            q = q.where(CollegeLesson.group.like(f"%{VUZ_SUFFIX}"))
        result = await self.session.execute(q.distinct())
        names.update(t for (t,) in result.all() if t)
    return _clean_teacher_names(names)
```

`CollegeLesson` уже импортирован в модуле — проверил шапку файла.

**Проще:** заменить `BaseLesson` на `CollegeLesson` целиком. Он
материализуется из `base_lesson` за 14 дней вперёд, так что все
«обычные» преподаватели там есть. Но тогда человек, чьи пары были
только в прошлом, из списка выпадет — а сейчас он в списке. Поэтому
объединение безопаснее.

## Проверено и признано корректным

**`teacher_matches` находит «Кулян Р.А» по «Кулян Р.А.».** Проверил
все три написания:

```
teacher_base('Кулян Р.А')   -> 'Кулян Р.А'
teacher_base('Кулян Р.А.')  -> 'Кулян Р.А.'
teacher_base('Кулян Р. А.') -> 'Кулян Р.А'    <- пробел схлопнулся
```

Регулярка `(?<=\b[А-ЯЁA-Z]\.)\s+(?=[А-ЯЁA-Z]\.)` требует точки после
второй буквы; в `Р. А.` она есть, поэтому нормализация срабатывает.
Проблема не в сопоставлении — в том, что имени нет в источнике.

**`callback_data` не переполняется.** Проверил все 199 имён:
максимум **61 байт** (`'Кострицына Н.А. / Кабышева М.И.'` с префиксом
`teacher:`) при лимите Telegram 64. Запас 3 байта — впритык, но
превышений 0. Если появится имя на 2 символа длиннее, Telegram
отвергнет **всю клавиатуру**, а не одну кнопку. Стоит держать в уме.

**Клавиатура по буквам не превышает лимит 100 кнопок.** Самая
населённая буква — «К», 25 имён, 26 кнопок с «Назад».

**`get_teachers` (колледж) берёт из `college_lesson`** — проверил,
там `CollegeLesson.teacher` с фильтром `vuz=False`. У колледжа
проблемы нет: замены уже в материализованной таблице.

**Склейки через слэш.** `'Кабышева М.И. / Кострицына Н.А.'` попадает
в список отдельной записью и не находится по «Кострицына» — это
[план 078](078-merge-loses-second-teacher.md), не дублирую.

## Риски

- **Список вырастет на 3 имени.** Не проблема. Лишний `SELECT` из
  `college_lesson` (1855 строк вуза, `DISTINCT`) — но индекс есть:
  `ix_college_lesson_teacher` создан в миграции `0002_editors.py:103`.
  Проверил, дополнительный индекс не нужен.
- **Устаревшие имена.** `base_lesson` хранит и прошлые семестры; если
  преподаватель ушёл, он останется в списке. `college_lesson` тоже
  ограничен 14 днями вперёд, но хранит прошлое. Поведение не меняется —
  объединение только добавляет.
