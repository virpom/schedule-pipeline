# План 149: в выборе преподавателя дубли — 13 пар в вузе, 2 в колледже

**Приоритет:** низкий. Расписание придёт верное при любом выборе, но
человек видит два одинаковых пункта и не знает, какой правильный.

**Трудоёмкость:** S (~5 строк).

## Проблема

Экран «Выбери себя» строится из `get_teachers_vuz()` /
`get_teachers(vuz=False)`. Оба возвращают `distinct()` **по сырой
строке из БД**, а расписание одного человека записано по-разному.

Проверил на живой базе:

```
колледж: 67 имён, 2 группы дублей
  ['Вакансия', 'вакансия']
  ['Мурашова - Росс А.В.', 'Мурашова – Росс А.В.']

вуз: 126 имён, 13 групп дублей
  ['Воробьев М.С', 'Воробьев М.С.']
  ['Востриков К.В.', 'ВостриковК.В.']
  ['Глубокова Л.Г', 'Глубокова Л.Г.']
  ['Громов В.А', 'Громов В.А.']
  ['Добжанская О.Э', 'Добжанская О.Э.']
  ['Иванова З.Н', 'Иванова З.Н.']
  ['Каверзин А.В.', 'Каверзин. А.В.']
  ['Лаговская Е.В', 'Лаговская Е.В.']
  ...
```

## Что видит человек

Буква «В», вуз — семь кнопок, из них две пары одинаковых:

```
Вакуленко А.И.
Варламова Т.Е.
Вересова Е.А.
Воробьев М.С       <- без точки
Воробьев М.С.      <- с точкой
Востриков К.В.
ВостриковК.В.      <- без пробела
```

Два «Вострикова» отличаются одним пробелом. На глаз — одно и то же.

## Что происходит при выборе

Ничего страшного: `get_for_teacher_date` (`college_lesson.py:172`)
берёт первое слово фамилии и ищет `LIKE '%Востриков%'` — находит оба
написания. Расписание придёт полное в любом случае.

Но человек этого не знает. Он видит два варианта, выбирает наугад и
**не может проверить, что выбрал правильный**.

## Откуда расхождения

В `base_lesson` и `college_lesson` 1216 пар из 2659 записаны под
дублирующимися написаниями. Источники:

- **пробелы внутри инициалов** — «Петров А. М.» vs «Петров А.М.»
  (самый частый случай, 20+ пар);
- **пропущенная точка** — «Семенов Т.В» vs «Семенов Т.В.»;
- **пропущенный пробел** — «ВостриковК.В.» (опечатка в исходном xls);
- **дефис vs тире** — «Мурашова - Росс» vs «Мурашова – Росс»;
- **лишняя точка в фамилии** — «Каверзин. А.В.»;
- **регистр** — «Вакансия» vs «вакансия».

## Что сделать

Схлопнуть в `_clean_teacher_names` — она уже есть и уже применяется в
обоих методах. Сейчас она, судя по результату, только чистит пробелы
по краям. Нужно нормализовать ключ:

```python
def _norm(t: str) -> str:
    # «Петров А. М.» и «Петров А.М.» — один человек
    return re.sub(r'[^А-Яа-я]', '', t).lower()
```

и оставлять первое написание на каждый ключ, предпочитая вариант с
точками (он чаще верный).

**Важно:** `get_teachers` используется не только для выбора — проверил,
больше нигде. Значит правка безопасна.

## Что проверил и признал корректным

**Выбор любого варианта даёт верное расписание.** Проверил
`get_for_teacher_date:172` — фильтр по первому слову через `LIKE`,
оба написания попадают. То же в `get_for_teacher_range:192`, плюс там
`teacher_matches`.

**`teacher_matches` ломается на дефисе и точке, но это не вредит.**
Проверил:

```
'Мурашова - Росс А.В.' vs 'Мурашова-Росс А.В.'  -> False
'Каверзин. А.В.'       vs 'Каверзин А.В.'       -> False
'Петров А. М.'         vs 'Петров А.М.'         -> True
'Сидельников М.Э'      vs 'Сидельников М.Э.'    -> True
```

`teacher_matches` зовётся только в `get_for_teacher_range`, а там перед
ним стоит `LIKE` по фамилии. Строка с дефисом проходит `LIKE` и
отсекается `teacher_matches` — но проверил все 45 дней вокруг сегодня
для обеих пар с дефисом: **0 потерянных строк**, потому что пары
записаны под тем же написанием, что и выбранное имя.

**Префиксные коллизии не срабатывают.** Проверил: в 192 именах есть
4 пары, где фамилия одного — префикс фамилии другого («Андреев» /
«Андреева», «Данилов» / «Данилова»). `LIKE '%Андреев%'` поймал бы
«Андрееву». Проверил все 45 дней: **0 чужих строк** — у «Андреевой» и
«Даниловой» нет пар в этом диапазоне.

**`get_teachers` больше нигде не используется.** Проверил grep по
`tgbot/` — только `_teacher_letter_kb:312`.

**День и неделя дают одинаковое число.** Проверил для всех четырёх
вариантов с дефисом/точкой: `день == неделя` (4/4, 11/11, 7/7, 1/1).

## Риски

- **Схлопывание имён может склеить двух разных людей** с одинаковой
  фамилией и инициалами. Проверил: в вузе 126 имён, все различаются
  инициалами — совпадений нет. Но нормализация убирает точки, поэтому
  «Иванов А.Б.» и «Иванов А. Б.» склеятся — а это один человек.
- **Нормализация в `_clean_teacher_names`** повлияет и на
  `get_teachers_vuz` — там те же 13 дублей, эффект тот же.
