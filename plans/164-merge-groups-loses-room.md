# План 164: поток с разными аудиториями показывает всем первую

**Приоритет:** средний. Студент идёт не в ту аудиторию — это хуже,
чем не знать номер вовсе. Задевает 51 человека на четырёх слотах.

**Трудоёмкость:** S (~8 строк).

## Что происходит

`_merge_groups` (`common/schedule.py:161-188`) склеивает пары потока в
одну строку. Ключ склейки:

```python
key = (lesson.para, getattr(lesson, "para_end", None) or lesson.para,
       lesson.subject, teacher_base(lesson.teacher))
```

**`room` в ключе нет.** Две группы, один преподаватель, один предмет,
один слот — склеиваются, даже если сидят в разных кабинетах. Комната
остаётся от первой:

```python
seen.group = ", ".join(...)      # группы дописываются
# room не трогается — остаётся от seen
```

Докстринг это признаёт:

> Остальные атрибуты берутся у первой: комната у потока обычно общая,
> а если и разная, терять её всё равно нельзя — она останется от
> первой группы.

Но «останется от первой» — и есть потеря. Второй группе показывают
чужой кабинет.

## Масштаб — проверил на проде

Запрос по `college_lesson` (группы без `@vuz`, одинаковые
`date+para+para_end+subject+teacher`, **разные** `room`):

```
2026-10-02 п1  Иностранный язык      Гулиева Н.Г.
               ТЭк-26, ТЭф-24        217 / 223
2026-10-02 п4  Корпоративное право   Ворончук Л.В.
               ЮР-24А, ЮР-24Б        321 / 323
2026-10-26 п3  Физическая культура   Рамазанов Т.М.
               ЭК-25, ЮР-24Б         "" / спортзал
2026-10-26 п4  Физическая культура   Рамазанов Т.М.
               ПР-26КП, ПРф-23       спортзал / ""
```

Затронуто **51 студент**: ТЭк-26 (21), ТЭф-24 (11), ЮР-24Б (5), ЭК-25
(7), ПР-26КП (2), плюс ЮР-24А и ПРф-23, где подписчиков пока нет.

В двух случаях одна из комнат **пустая** — это ещё хуже: группа
получает пустую строку вместо «спортзал».

## Почему это не то же, что план 076

[План 076](076-week-screen-no-merge.md) проверял ровно этот вопрос, но
**только для вуза**:

> Запрос по `college_lesson` (группы `@vuz`, одинаковые
> `date+para+subject+teacher`, разные `room`) вернул **0 строк**.

Для вуза это верно — там комнат в базе вообще нет (план 021). Но
`_merge_groups` работает и для колледжа, а там кабинеты есть, и
случаев уже четыре.

[План 117](117-parallel-subgroups-merged.md) — про другую функцию,
`_merge_para_clash` (`sync_eios.py:315`), которая склеивает
параллельные подгруппы вуза через `" / "`. Здесь речь о
`_merge_groups`, и склейка идёт через `", "`.

## Что сделать

**Вариант 1 — добавить `room` в ключ.** Просто и предсказуемо: поток с
разными кабинетами перестанет склеиваться и покажется двумя строками.

```python
key = (lesson.para, getattr(lesson, "para_end", None) or lesson.para,
       lesson.subject, teacher_base(lesson.teacher),
       (lesson.room or "").strip())
```

Минус: физкультура, где у всех «спортзал», склеится как раньше — это
правильно. А вот случай `""` / `спортзал` даст две строки, хотя это
одна пара; зато обе группы увидят верное.

**Вариант 2 — показать обе комнаты в подписи.** Склейка остаётся,
но `room` собирается так же, как `group`:

```python
rooms = [r for r in (getattr(seen, "room", None),
                     getattr(lesson, "room", None)) if r]
seen.room = ", ".join(dict.fromkeys(
    part.strip() for r in rooms for part in r.split(",") if part.strip()))
```

Студент увидит «217, 223» и не поймёт, какая его.

**Что выбрать.** Вариант 1 честнее: две строки — это две группы в двух
кабинетах, ровно как в жизни. Вариант 2 сохраняет компактность, но
оставляет двусмысленность, а `format_day` печатает `room` в общий
хвост `teacher · room` (`common/schedule.py:264`), где две комнаты
через запятую неотличимы от мусора.

Рекомендую **вариант 1**.

## Проверено и признал корректным

**Склейка по потоку работает.** Одинаковый кабинет у шести групп
физкультуры — типичный случай, и он склеивается правильно.

**`dict.fromkeys` сохраняет порядок и убирает дубли.** В подписи
групп это верно.

**`seen.group` мутирует объект из списка** — безопасно, объекты
короткоживущие (проверено в плане 076).

**`teacher_base` в ключе не даёт склеить однофамильцев** — инициалы
сохраняются.

**Все 129 групп имеют ровно две цифры в имени** — проверил, поэтому
`course_from_group` (`re.search(r"(\d{2})")`) на реальных данных не
ошибается.

## Риски

- **Две строки вместо одной** для потока с разными кабинетами. Это
  изменение подачи, а не данных.
- **Пустая комната против непустой** даст две строки — формально
  верно, но выглядит странно. Можно нормализовать: считать `""` и
  `"спортзал"` разными, потому что это разные факты.
- **Тест:** нужен случай с двумя группами и разными `room` —
  ожидать две строки. Сейчас в `tests/test_schedule_layer_service.py`
  такого нет.
